# 第 9 章：把阶段 1–8 组装成单层流水线——特殊稠密投影、跨阶段线性折入与全层并发编排

**本书地图：** 第 0.0 章 → 第 0 章 → 第 0.5 章 → 第 1 章 [第 0 级] → 第 2 章 [第 1 级] → 第 3 章 [第 2 级] → 第 4 章 [第 3 级] → 第 5 章 [第 4 级] → 第 6 章 [第 5 级] → 第 7 章 [阶段 2：分页注意力] → 第 8 章 [阶段 6：路由专家] → **【第 9 章：单层 1–8 阶段总装与特殊投影】** → 第 10 章 [性能诊断法]

承接第 8 章末尾的问题（第二部分收官：单层总装）：前面八章已经把阶段 1（`qkv_gate`）、阶段 2（分页注意力 `a0 → a6`）和阶段 6（路由专家 `m0 → m5`）的主力内核逐个立住了。要把一整层模型从头到尾跑通，还剩下三个问题：其余四个稠密投影（阶段 4 `router`、阶段 3 `o`、阶段 5 `pooler` 和阶段 7 `unpooler`）各自有什么特殊算子契约？夹在投影算子之间的 4 处均方根归一化和 2 处门控残差，怎样消掉来回读写显存的开销？最后，怎样把全部八个阶段串成一条从 `T = 1` 到 `T = 16,384` 的单层流水线？本章分四步完成单层总装（`l0 → l3`）：先完成阶段 4 单精度路由与基线投影（`l0`），再补齐阶段 1、3、5、7 的切片、压缩回退与尾波切分（`l0 → l1`），接着折入跨阶段归一化与残差边界（`l1 → l2`），最后用旁路流与同流编程依赖启动（PDL）编排整层内核（`l2 → l3`）。

## 1. 阶段 4（`router` 单精度投影与 Top-8 选择）：怎样在 BF16 Tensor Core 上保持接近 FP32 的精度并缩为单波次？（`l0`）

<!-- FIG ch09-router: 图 9-1 画阶段 4（router 路由器与 Top-8 选择）从单精度权重拆分为高/低两份 BF16 残差对送入 Swap-AB Tensor Core、T=3,012 下将分块扩至 BT=192 缩为 128 个 CTA 单波次、0..3 号清零 CTA 加辅助 warp 轮询单调标志、到单 warp redux.sync 无共享内存选出 Top-8 专家的完整解剖与时间线。 -->

数据流穿过阶段 3 的第一道残差边界后，预归一化激活 `h` 分成两路，其中一路进入阶段 4 的路由器（`router`）和 Top-8 专家挑选。同是稠密矩阵乘，为什么阶段 4 不能直接照搬其它四个投影的 BF16 内核？

原因有两条：**第一，它是全层五个稠密投影里唯一使用 32 位单精度（`FP32`）权重、并要求保持单精度打分精度的阶段；第二，它的输出维度只有 256 行（对应 256 个全局专家），远窄于其它投影的几千行。** 阶段 4 的所有特殊设计，都是从这两个约束里长出来的。切换图 9-1 顶部的四种模式，可以对照它在四个词数档位下的读数变化（图上四档读数见本节末表）。

先把这一步的公式、输入输出和带宽账算清楚：
- **公式**：路由器矩阵乘先算出未归一化的单精度原始对数打分 `logits = h_router @ W_router.T`（形状 `[T, 256]`，FP32）。接着 Top-8 路由核在寄存器里乘上缩放系数求出 `scores = sigmoid(0.1767767 * logits)`，加上偏置挑出得分最高的 8 个全局专家编号 `topk_ids = argtopk_8(scores + b_router)`。最后把选中的 8 个无偏置打分 `w_raw = gather(scores, topk_ids)` 归一化为路由权重 `topk_weights = w_raw / (sum(w_raw, dim=-1) + 1e-15)`。
- **输入与输出**：输入包括阶段 3 分叉送来的激活 `h_router`、单精度路由权重 `W_router`（形状 `[256, 8192]`，FP32，占 `8,388,608 B = 8.4 MB`，位于 HBM）与偏置 `b_router`（形状 `[256]`，FP32，占 `1 KiB`，位于 HBM）。其中 `h_router` 在 `T ≤ 8` 原生 FP32 路由路径下读 `h` 的 FP32 副本 `[T, 8192]`（每词 `32 KiB`），在 `T > 8` 的 `hi / lo` BF16 拆分路径或单算子评测契约下直接读 BF16 `h`（每词 `16 KiB`，位于 HBM 或 L2）。矩阵乘输出 `logits [T, 256]`（FP32）送入路由核。路由核写出 `topk_ids`（形状 `[T, 8]`，`int32`，每词 `32 B`）与 `topk_weights`（形状 `[T, 8]`，FP32，每词 `32 B`）至 HBM 或 L2，交给阶段 6 做位图筛选或分桶重排。
- **本步下界**：每个 4 字节的 FP32 权重只做 2 次浮点运算，仅计权重时算术强度只有 `0.5 × T FLOP/B`，比同形状的 BF16 投影低一半。在单请求解码 `T = 1`（区间 I）下，光把 `8.4 MB` 权重从 HBM 读出来，带宽下界就是 `1.8 µs`（`1.75 µs`）。就算到了预填充 `T = 753`（区间 III 起点），把权重和输入输出激活全部算进去，算术强度也只有 `147 FLOP/B`，仍然是五个稠密投影里唯一低于 H200 `206 FLOP/B` 平衡点的显存受限阶段（带宽耗时 `4.48 µs` 大于算力耗时 `3.19 µs`）。

顺着这笔账，路由器矩阵乘在单请求解码（区间 I）、多词解码与投机检验（区间 II）及预填充（区间 III）三个词数区间，依次用上了 8-warp 核移植、`hi + lo` BF16 残差对与 `BT = 192` 单波次分块三项机制：

在单请求解码（`T = 1`）下，算术强度只有 `0.5 FLOP/B`，瓶颈在读权重（单精度路由向量核实测 `4.17–4.60 µs`）。我们将稠密投影族调好的 8-warp 单精度向量乘内核移植进整层流水线，使单请求滑窗层和全长层整层分别提速 **1.22% 与 1.01%**。这一增益由四个投影一起替换省下约 `2.6 µs` 推断得出；单独替换 `pooler`、`o` 或 `unpooler` 单臂未测出正收益，内核的寄存器代价未测。

当词数 `T` 进入多词区间，继续用原生 FP32 计算就用不上高吞吐的 BF16 Tensor Core；但如果直接把权重截断成 BF16，打分精度又会下降。为了同时用上 BF16 Tensor Core 并保持单精度，预处理期把 `[256, 8192]` 的 FP32 权重拆成高、低两份 BF16 残差对 `W_fp32 ≈ W_hi + W_lo`（拆法见第 5 章第 3 节）。代价是每步 `K` 要发 2 倍的 BF16 MMA 指令，或者读双倍的 BF16 权重行。在投机检验区间，内核每步 `K` 发 2 次 MMA 累加进同一个 FP32 累加器，一次启动就省掉了原先的 cuBLAS 拆分加归约核；跨版本演进中，`T = 128 / 256` 的路由器耗时从 `8.15 / 11.21 µs` 降到了 `7.32 / 9.23 µs`（未做单因子配对隔离）。到了预填充区间，则直接把高、低两份权重堆叠成 `[512, 8192]` 的 BF16 矩阵一次算完，再在片上把两半相加，并在尾声一并算完 `sigmoid`、Top-8 和本地专家编号映射（预填充单步增益、其它硬件代价与亏损边界均未测）。

当词数继续升到 `T = 3,012` 时，只有 `256` 行的窄输出又会撞上波次尾问题。为了让窄输出矩阵跑满 Tensor Core，我们先交换左右操作数（Swap-AB `wgmma.m64n192k16`，用指令的 `M = 64` 维对准 `256` 行专家维，共 `256 / 64 = 4` 块），配合 5 槽环、2-CTA 多播和 Split-K 2，把耗时从 `60.5 µs` 压到 `37.6 µs`（各子项份额未单独分离，见第 5 章第 3 节）。但此时如果按 `BT = 128` 切分词元维，`3,012` 个词元会切出 `24` 块，产生 `(4, 24, 2) = 192` 个 Split-K CTA，在 132 个 SM 上拖出半个第 2 波次。把词元分块扩到与指令 `N = 192` 对齐的 **`BT = 192`** 之后，词元分块缩减为 `16` 块，网格缩为 `(4, 16, 2) =` **128 个 CTA**，刚好一波装进 132 个 SM。在 `T = 3,012` 滑窗层上，单这一项实测省下 **15.0 µs**，整层提速 `0.79%`，全长层提速 `0.44%`。`BT = 128` 与 `BT = 192` 的 5 槽环同样占 `204,896 B` 共享内存、每 SM 限驻 1 个 CTA；改分块本身的额外代价与亏损边界未测（多播扇出退化的反例见第 3 章第 4 节）。

矩阵乘之后的 Split-K 归约尾和 Top-8 挑选，则直接复用第一部分验证过的方案。Split-K 归约尾采用第 2 章第 4 节的“清零 CTA + 单调递增标志”，消掉最后到达者 `1.05–1.15 µs` 的同步与拷贝尾，在 `T = 8 / 16 / 32` 上分别省下 `0.88 / 1.07 / 0.98 µs`（代价未测）。因为每个 TMA CTA 占 `196,640 B` 共享内存、每 SM 限驻 1 个 CTA（寄存器从 72 降至 64 个），负责清零的 4 个 CTA 必须排在最靠前的 `program_id 0..3` 防自旋死锁，在 `T = 128 / 256` 上省下 `1.22 / 1.72 µs`（见第 2 章第 2 节）。在 `T = 16 / 32` 下，再把块线程从 128 扩为 160，由第 5 个辅助 warp 在等数据期间并行取票、轮询标志并剥掉 20 条零字节死预取，又省下 `0.57 / 0.50 µs`。若让 0 号消费者线程自己轮询，反而会因为 `acquire` 读取排在自身 40 条在途加载后面而变慢 `+0.32 µs`（见第 4 章第 2 节）。

Top-8 选择按批量分成两套无共享内存方案。解码与检验用每词元 1 个 warp、每轮 2 条 `redux.sync` 指令，使 warp 指令减少 `61%`、LSU 占用从 `12.8%` 降至 `0.6%`；`T = 1` 滑窗与全长整层提速 `1.29% / 2.81%`，`T = 256` 单核从 `4.96 µs` 压到 `3.65 µs`，全范围无亏损（代价未测，见第 4 章第 4 节）。预填充则用每行 8 个线程的单 warp 归约，把 `T = 3,012 / 16,384` 的 Top-8 耗时从 `35.5 / 44.0 µs` 压到 `22.0 / 23.6 µs`（与每词元 1 程序的 `QK-norm / RoPE / KV` 内核合并测试时整层提速 `0.36%–0.56%`，代价未测，见第 4 章第 2 节）。连同预填充基线上的分块标定与库核替换，这些改动构成了单层总装起点 **`l0`**：

## 2. 阶段 1、3、5、7 稠密投影的特殊形态：$T \le 8$ 切片 `unpooler`、C12 逃逸回退梯与大批量尾波切平（`l0 → l1`）

除阶段 4 的单精度路由器外，单层里还有四个 `BF16` 稠密投影：阶段 1（`qkv_gate [2304, 8192]`，`37.7 MB`）、阶段 3（`o [8192, 1024]`，`16.8 MB`）、阶段 5（`pooler [4096, 8192]`，`67.1 MB`）和阶段 7（`unpooler [8192, 4096]`，全矩阵 `67.1 MB`）。它们的通用矩阵乘内核已经在第一部分讲完。把它们装进单层流水线时，还需要解决三个边界问题：**阶段 7 在 `T = 8 → 16` 处有一道矩阵宽度差 8 倍的切片契约；12 位无损压缩（C12）在评测器的随机权重下会超出逃逸上限；到了大批量预填充，持久网格的最后一波又会因为分块数除不尽 132 而留下几十个空闲 SM。**

先看阶段 7（`unpooler`）在 `T ≤ 8` 时的切片契约与下界跳变：
- **公式与输入输出**：阶段 7 接收阶段 6 汇总的专家激活 `m [T, 4096]`（BF16，每词 `8 KiB`，位于 HBM 或 L2），乘上 `W_unpooler` 输出升维特征 `f [T, 8192]`（BF16）交给阶段 8。在线上 8 卡部署时，当 `T ≤ 8`（单请求解码与单请求 8 词检验），每张卡只计算 `8,192` 列里的 `1,024` 列，算完再做跨卡拼接。单卡评测省去了通信，约定 `T ≤ 8` 时只算前 `1,024` 列切片 `f[:, :1024] = m @ W_unpooler[:1024, :].T`（切片权重 `[1024, 4096]` 占 `8.4 MB`），其余 `1024..8191` 列填 0。一旦 `T > 8`，则必须计算完整的 `8,192` 列 `f = m @ W_unpooler.T`（完整权重 `[8192, 4096]` 占 `67.1 MB`）。
- **下界跳变**：在 `T ≤ 8` 时阶段 7 只读 `8.4 MB`（带宽下界 `1.75 µs`）。到 `T = 16` 时读取量放大 8 倍变成 `67.1 MB`（下界 `14.0 µs`），光这一个阶段的下界就增加了 `12.2 µs`。叠加 16 个请求的专家权重和 KV 缓存读取后，整层理论下界从 `T = 8` 单请求检验到 `T = 16` 解码，在滑窗层跳增了 **14.4 µs**（`62.3 → 76.7 µs`），在全长层跳增了 **71.1 µs**（`66.4 → 137.5 µs`）。

因为 `T = 8` 时 `unpooler` 只算 `1,024` 列，原内核只发出 `64` 个 CTA，占不满 132 个 SM 的一半。整层将其换成 `128` 个 CTA 的 8 路 Split-K 12 位无损 C12 切片核，将切片权重从 `8.4 MB` 压到 `6.3 MB`，再由收尾核累加 8 份单精度部分和（额外代价未测，见第 2 章第 1 节与第 6 章第 4 节）。这一步使单请求滑窗与全长检验整层分别提速 **1.29% 与 1.42%**（`109.0 → 106.8 µs`、`119.0 → 118.0 µs`）。同理，`T = 8 / 16` 的 `qkv_gate` 采用 3 路 Split-K 的 `108`-CTA 单波次 C12 核（提速 `+0.65%..+1.58%`，代价未测，见第 2 章第 1 节）。`pooler` 和 `unpooler` 则一并组合了第一部分的三项机制：C12 带宽布局配 L2 留存提示、每 8 个权重 9 条 ALU 指令解码，以及在最后一步 `K` 循环提前拼好逃逸修正操作数使 16 条 `wgmma` 共享一次提交与等待（具体收益、亏损算例与寄存器代价见本节末表）。

把 C12 装入评测流水线后，紧接着遇到第二个问题：评测器随机权重下的逃逸超限。C12 把常见指数范围的 BF16 权重压成 12 位，超出指数范围的权重则作为逃逸项单独存放（见第 6 章第 3 节）。早期描述符将每步逃逸权重上限设为 `4`，仅适配本地前 4 个随机种子（`0..3`）。当评测器独立生成随机权重时，在 64 个随机种子中有 `6` 个 `qkv_gate`、`14` 个 `pooler` 和 `2` 个 `unpooler` 种子超出了上限 4。一旦超限，打包函数就会返回空并回退到慢速路径；例如 `qkv_gate` 在 `T = 32` 下若直接回退到稠密 BF16 核，耗时需 `37.2–39.6 µs`。

为了兜住评测器的随机权重，我们将描述符的逃逸上限从 `4` 扩到 **`8` 字/warp**。万一扩到 8 之后打包还是返回空，就让 `qkv_gate` `T = 32` 走流式回退核（耗时 **15.30–15.39 µs**，在 14 个超限种子上 14/14 优于稠密 BF16 回退），同时在预处理函数里留好稠密 BF16 兜底路径而不抛异常。这一改动的代价落在了未超限的正常种子上：扩宽逃逸上限后，`unpooler` 在 `T = 128` 和 `T = 256` 下的短记分牌等待增加了 `45%`，耗时分别变慢 **`+0.32..+0.60 µs` 与 `+0.28 µs`**。

走过解码和检验，切换图 9-2 的四档负载（`T = 1`、`753`、`3,012`、`16,384`），可以看到当词数进入预填充（`T ≥ 753`）时，全层瓶颈从显存带宽转向了矩阵算力（图 9-2 四档完整读数见本节末表）。从 `T = 753` 到 `T = 16,384`，全层五个稠密投影的总运算量从 `145 GFLOP` 升至 `3,161 GFLOP`，其中四个 BF16 投影的算术强度达到 `412–2,341 FLOP/B`，全部跨过 `206 FLOP/B` 平衡点进入算力受限区（区间 III）。在预转置权重库核基线（见第 1 节）之上，`qkv_gate`、`o`、`unpooler` 升级为每 SM 驻留 1 个持久 CTA 的线程束分工 `wgmma` 内核，单核比旧集群分块核快 `1.05–1.30 倍`（代价未测，见第 3 章第 1 节）。`T = 753` 的 `pooler` 则采用 4 级 TMA 流水，将单核耗时从 `87.25 µs` 压到 `82.12 µs`（整层提速 `+0.89%`，代价未测，见第 3 章第 4 节）。

持久网格跑起来之后，第三个问题就露出来了：尾波空闲。持久网格在全卡 132 个 SM 上各驻留 1 个 CTA，一波接一波地领走输出分块。只要总分块数不能被 132 整除，最后一波就一定会有几十个 SM 无活可干，只能空等着其余 SM 跑完整个 `K` 维循环。要消掉这截尾波空转，就得把残余分块的求和步切细、均摊给全卡 SM（推进至 **`l1`**）。

拿图 9-2 第 8 步的 `T = 3,012` 滑窗层 `qkv_gate` 来看。它读入 `x_in [3012, 8192]`（BF16）和 `W_qkv_gate [2304, 8192]`（BF16），输出 `qkv [3012, 2304]`（BF16）交给阶段 2。词元维按 `128` 行切出 `24` 块，输出列按 `256` 列切出 `9` 块，一共 `24 × 9 = 216` 个输出分块（`132 + 84`）；求和维 `8,192` 按 `64` 切为 `128` 个 `K` 步。前 132 个分块跑完第 1 波后，第 2 波只剩 `84` 个分块，留下 `132 - 84 =` **48 个 SM 空转约 `28 µs`**。我们把第 2 波改为两段式 `K` 锁步切分：`0..83` 号 CTA 只计算各自第 2 波分块的前 `82` 个 `K` 步，原本空闲的 `84..131` 号 CTA 进场协作计算这 84 个分块的后 `46` 个 `K` 步（`82 + 46 = 128` 步），最后汇合部分和写出。这把全卡 CTA 结束时间的极差与均值之差从 `29.4 µs` 压到了 **7.4 µs**，`qkv_gate` 单核缩短 **8.7 µs**，整层单独提速 **`+0.177%`**（与第 7 章单独提速 `+1.786%` 的注意力半精度累加合测时，合计提速 **`+1.930%`**）。

当然，尾波切分并不是白拿的。在 `T = 3,012` 两段 `K` 锁步中，跨 CTA 协作使 HBM 读取量增加 `6.45%`（`141.7 → 150.8 MB`），单步 `K` 耗时从 `0.61–0.66 µs` 升至 `0.78 µs`（单步变慢的具体原因未测，并非由 DRAM 带宽引起）。而且，如果另一条流本来就要用这批空闲 SM，去切尾波反而会亏本：在 **`T = 3,012` 全长层**上，旁路流上的历史键值准备核（`2,524` 个 CTA）同时在争抢 SM，开启两段 `K` 切分反而使整层**倒退 `-0.10%`**，所以这一招只在滑窗层开启。

到了首轮分块预填充 `T = 16,384`，`qkv_gate`（9 波余 96 块）和 `pooler`（16 波余 68 块）共有 `85 µs` 的尾波空闲。对这两个算子启用 **Stream-K**（把最后一波残余分块的求和维 `K` 步均摊到全卡所有 CTA），分别省下 **13 µs 与 28 µs**（与注意力投票合测时整层 `+0.35%`，9/10 种子，收益较弱）；代价是写出并汇合 FP32 部分和，使 `qkv_gate` 的 Tensor Core 活跃占比从 `98.3%` 降至 `96.9%`。对 `unpooler`（末尾 4 块切 `1/4` 宽）和 `o`（末尾 8 块切 `1/2` 宽），则用编译期常量把尾块列宽切窄，使 `unpooler` 省下 **15.8–20.3 µs**（首轮 `+0.73%–0.81%`，对比约 `0.5%` 的同版本对跑噪声余量较小）。相反，若把 4 路尾块切窄用于大 `L` 的 `qkv_gate / o` 会**倒退 `-1.3%`**，把 `unpooler` 主循环上界从编译期常量改为运行期变量会**倒退 `-0.45%`**。而在小批量解码 `T = 32` 的阶段 6 专家下投影上尝试 Stream-K 系列时，因 80 个寄存器（每 SM 限驻 6 个 CTA）、部分和板条流量以及未切分瓦片的固定开销盖过了尾波收益，最佳变体池化 `-3.98 µs` 但从未通过 5/5 门控，首版实测**变慢 `+1.84 / +7.20 µs`**（复现仍慢 `+0.91 µs`），系列关闭。

## 3. 跨阶段代数折入与层间残差边界：怎样利用矩阵乘行线性性质消掉独立的归一化 Kernel？（`l1 → l2`）

<!-- FIG ch08-p5-fuse: 图 9-3 画阶段 5（pooler）与阶段 6（专家 gemm1）之间的跨核代数融合数据流（对应 T=3,012 时将独立 pre_expert_norm 的按列乘 gain 与每行 16 个部分平方和拆入 pooler 尾声写出、再由专家 gemm1 读入部分平方和算出 r_m 在累加器尾声完成行缩放，从而省去 49.3 MB HBM 往返与 14 µs 独立 kernel 的算法步）。 -->

当阶段 1、3、4、5、7 的五个稠密投影各自成型后，夹在算子之间的四处均方根归一化（`RMSNorm`）和两道可学习门控残差就成了新的优化对象。前两处归一化都和前序算子的切分维度一致，可以直接合入同一个 kernel 内完成：阶段 1 尾声的按头归一化在 `T = 1` 下经 L2 计数由第 16 个到达的 CTA 原地完成（见第 6 章第 4 节），多词下则合入阶段 2 融合序言（见第 1 章第 1 节与第 7 章第 1 节）；阶段 2 尾声的门控输出归一化也原地合入了注意力尾声（见第 7 章第 6 节）。唯独夹在阶段 5（`pooler` 降维投影）和阶段 6（专家上投影）之间的专家前均方根归一化（`pre_expert_norm`），在基线里不得不单独启动一个 kernel。

为什么它没法直接并入 `pooler` 的尾声？**因为 `pooler` 是按列切分 `4,096` 维输出特征的，每个 CTA 手里只有一行激活的局部列切片（例如 256 列），谁也没法在核内单独算出整行 `4,096` 列的平方和均值。**

要把这个独立 kernel 消掉，依据的是矩阵乘法对行缩放的线性性质：**先把输入矩阵的某一行乘上一个标量 $r_m$、再去乘权重矩阵 `W13`，算出来的结果，与先直接做矩阵乘法、等算完之后再把那一行的输出累加器乘上同一个标量 $r_m$，在代数上等价。**

对照基线的三步公式来看这一拆法（图 9-3）：
- **基线三步公式**：阶段 5 先算 `x_pool = h @ W_pooler.T`。接着独立归一化 kernel 对每行 `m` 算出均方根倒数标量 `r_m = rsqrt(mean_k(x_pool[m, k]^2) + 1e-5)`，再乘上按列固定的增益向量 `gain[k] = 1 + w_pre_expert[k]`，写出 `p[m, k] = (x_pool[m, k] * r_m) * (1 + w_pre_expert[k])`。最后阶段 6 专家上投影计算 `[h_gate[m, :] | h_up[m, :]] = p[m, :] @ dequant_nvfp4(W13[e]).T`。
- **拆入两核尾声**：归一化里的两步乘法是可交换的。按列乘 `gain[k]` 只依赖当前列下标 `k`，`pooler` 的每个列分块 CTA 自己就能在写出尾声顺手乘完，写出 `xb_gain[m, k] = BF16(x_pool[m, k] * gain[k])`。至于整行共享的标量 `r_m`，则推迟到阶段 6 第一层矩阵乘的尾声，直接乘在算出来的整行单精度累加器上。

拆开之后，单请求解码和多词预填充各自省下了最卡自己的那笔开销：

在单请求解码（`T = 1`）下，中间张量很小，省去的是内核启动开销。`pooler` 的每个列分块 CTA 在尾声写出 `xb_gain [T, 4096]`（BF16），同时对全局单精度计数器做一次原子加，累加当前列段的部分平方和；阶段 6 专家内核读出总平方和，在内部乘上 `rsqrt` 完成行缩放。这样一来，关键路径上少了一次依赖启动，`T = 1` 整层启动次数从 `12` 次减为 **`11` 次**，单请求滑窗层和全长层整层实测分别省下 **0.82 µs**（`+1.15%`）和 **1.47 µs**（`+1.39%`；如何测量删掉某一步的耗时上限见第 10 章）。

到了多词预填充（`T = 3,012` 与 `16,384`），省去的是显存往返流量。在 `T = 3,012` 下，中间张量 `x_pool [3012, 4096]`（BF16）占 `3,012 × 4,096 × 2 B =` **24.7 MB**；到 `T = 16,384` 下更达到 `134.2 MB`，超出 60 MiB L2 缓存容量两倍多。如果不拆，独立归一化 kernel 需要从 HBM 读入 `24.7 MB`、算完再写回 `24.7 MB`，多出 **49.3 MB** 的显存往返（按 `4.8 TB/s` 算带宽下限是 `10.3 µs`，`T = 3,012` 实测该独立 kernel 耗时约 **14 µs**）。如图 9-3 所示，拆入尾声后，`pooler` 的 `4,096` 列输出按每 CTA `256` 列切为 16 个列段（`4,096 / 256 = 16`），在写出 `xb_gain [T, 4096]`（BF16）的同时各自写出本列段的部分平方和 `rs_part [T, 16]`（FP32，每词仅 `64 B`）。在 `T = 3,012` 下，这部分平方和读写各 `0.19 MB`、合计 `0.39 MB`，扣除后净省显存流量 **48.96 MB**。随后阶段 6 的专家 `gemm1` 读入 `xb_gain` 和每行的 16 个部分平方和，求和算出 `r_m`，在门控激活尾声（见第 8 章第 1 节）顺手完成行缩放，单项提速 `+0.23%`（合并测试提速 `0.60% / 1.35%`，图 9-3 两种方式的读数对比见本节末表）。

这套跨核折入的代价是 `pooler` 尾声需额外写出部分平方和（或做原子加），并由专家核读入做缩放。在 **`T = 753`**（单请求多轮预填充）下，中间张量仍能放入 L2，实测净收益约为 **0**。而在投机检验 **`T = 128 / 256`** 上，若尝试将归一化并入生产者尾声，会使核内尾部变为串行执行，反而使全部 4 个检验算例**变慢 `-0.5%..-1.0%`**，因此在检验区间不启用（原因见第 4 节）。

消掉阶段 5 到阶段 6 之间的独立归一化后，单层里还剩下两处全宽 `8,192` 维的边界归一化内核：阶段 3（`o` 输出投影后的第一道门控残差与前馈预归一化）和阶段 8（`unpooler` 后的第二道门控残差与下一层预归一化）。这两处边界不仅要计算均方根归一化，还要用逐通道（`[8192]` 向量）可学习门控 `g_1` 与 `g_2 [8192]` 更新 FP32 主干残差流 `stream_0 → stream_1 → stream_2`（每词 `32 KiB`），并算出下一阶段的 BF16 预归一化激活 `h` 和 `x_next`（每词 `16 KiB`）。以阶段 8 为例，每词需读入 `f`（`16 KiB`）与 `stream_1`（`32 KiB`），写出 `stream_2`（`32 KiB`）与 `x_next`（`16 KiB`），读写主干合计 `96 KiB`（两处边界的完整公式列于本节末表）。

这两处边界核在解码/检验与预填充下卡在不同的地方，因此分别做了两套改造（推进至 **`l2`**）：

在解码与投机检验（`T = 1..256`）下，集群边界归一化核原本用三次 `barrier.cluster.arrive.release` 同步跨块归约，会编译出 `MEMBAR.ALL.GPU + ERRBAR + CGAERRBAR` 指令序列，光 `ERRBAR` 一项就占了未发射采样周期的 `36%–46%`。改用 `st.async` 加本地 `mbarrier` 交换部分平方和之后，每次调用省下 **0.86–0.99 µs**，整层几何平均提速 **0.46%**（代价未测，见第 7 章第 6 节）。每次行归约必须分配独立的共享内存缓冲区：首版让两次归约共用同一块线程束部分和缓冲区，在内存竞态检查（方法见第 10 章）下测出了 8 处**读后写（WAR，write-after-read）**冲突（见第 3 章第 4 节）。

在预填充（`T = 753..16,384`）下，先将全部 6 个残差/归一化行内核与专家后归一化从 Triton 改写为原生 CUDA C++，在首轮 `T = 16,384` 上提速 `+0.54%–0.73%`（在 `T = 3,012` 上为 `-0.11%..-0.28%`，仅首轮有正收益，代价未测，见第 6 章第 1 节）。接着按词数分档调优这两处边界核的缓存提示、块内线程数与寄存器上限。例如在 `T > 1,024` 下将寄存器压到 `64` 个，使每 SM 驻留从 3 个升至 4 个 CTA（4 条测试通道仅 1 条通过冻结规则，收益较弱）。在 `1,024 < T ≤ 3,012` 下则扩为每行 `512` 个线程提前发出输入加载，使 `T = 3,012` 整层提速 **0.203%**（8/10 种子，收益较弱，代价未测，见第 4 章第 2 节；各分档细节汇总于下表）。

现在退回到第 0 级全层时间线（见第 0 章第 2 节与第 1 章），把阶段 1 到阶段 8 的内核组装成一条完整的单层流水线（推进至终版 **`l3`**，见图 9-4、图 9-5 与图 9-6，三张图的各档读数汇总在本节末表）。

先算一笔核间交接的账。基线单层顺着一条流跑下来大约要启动 `17` 个 kernel；即便把整层录制进 CUDA Graph，顺序单流下相邻两个节点之间仍有中位数 `1.024 µs`（约 `1.0 µs`）的启动空隙。经过第 7 章的注意力序言与归约内联、第 8 章的专家持久化，以及本章第 3 节的跨核线性折入，单层在 `T = 1` 下已经收敛到了 **11 个 kernel**。再用同流编程依赖启动（PDL，原理见第 1 章第 2 节）把相邻边界串起来，每条单 CTA 编程依赖启动串行边压到了约 `0.64 µs`，11 个核加起来量级约 `7.0 µs`，滑窗层跑完一整层共读 `191.9 MB`、最短只需 **40.0 µs**。

既然目标是消掉核间空隙，为什么不直接把这 11 个 kernel 合写成 1 个全层持久大核（Megakernel），反而要保留 11 个独立 kernel，用旁路流和同流 PDL 去编排它们？**因为不同阶段的最佳寄存器数和 SM 驻留本来就不一样。拆成独立 kernel 时，前一个核收尾腾出的 SM 可以让后一个核立刻进场预读权重，也能让旁路流去填没占满的空闲 SM。如果合写成同一个全层大核，不仅驻留会被最重的阶段锁死，原本重叠的核间交接还会退化成核内全网格串行栅栏，付出的代价远大于省下的那几微秒空隙。**

顺着这 11 个内核的分叉拓扑与串行边界，整层总装依次落下了四项决策。

**1. 旁路流调度（`router ∥ pooler`）：看主流算子还剩多少空闲 SM**

阶段 3 输出的 `h [T, 8192]`（BF16，位于 HBM 或 L2）在进入前馈半区时会分成两路：一路去阶段 4 算 `topk_ids [T, 8]` 和 `topk_weights [T, 8]`，另一路去阶段 5（`pooler`）算 `xb_gain [T, 4096]`，两条支路直到阶段 6 入口才重新汇合。因为两路之间没有数据依赖，可以开一条**旁路流（Side Stream）**，也就是与主流并行下发无依赖算子的第二条 CUDA 流，让两路并发执行。但谁放主流、谁先启动，取决于主流上的 `pooler` 占了多少个 SM，全范围一共发生三次切换：

在解码与检验基线（`T = 1..256`）里，`router`（本身耗时约 `11.7 µs`）加 `top-8` 放在旁路流上，先于主流 `pooler` 启动，省去了 `5–8 µs` 级的时间线空洞。在 `T = 128` 滑窗时间线上，`router` 位于 `38.9–47.7 µs`、`pooler` 位于 `49.1–72.5 µs`；因为两核分别占 `131 KB` 和 `198 KB` 共享内存，无法在同一个 SM 上共驻，而为了求共驻去砍浅 `pooler` 的流水环深反而会变慢（见第 3 章第 4 节）。到了 **`T = 128`（16 请求检验）**，我们将 `pooler` 和 `router` 合写进单次启动（外加旁路流上的 1-CTA 门控核），让合并核提前约 `10 µs` 启动，关掉两核之间 `8.5 µs` 的启动空隙。尽管合并核多读了 `12.5%` 的权重字节，净下来仍然省了约 **`3 µs`**，滑窗层和全长层整层分别提速 **1.30% 与 0.88%**。不过这套合核到 **`T = 256`（32 请求检验）** 就不划算了：合并核自身变长约 **`8 µs`**，抵消了关掉空隙的收益，所以 `T = 256` 保持两核分开。

进入单请求预填充 **`T = 753`（`T ≤ 1,024`）** 时，主流上的 `pooler` 只启动 `96` 个 CTA（每 SM 1 个 CTA），在 132 个 SM 上留出 **`36` 个空闲 SM**。这时把 `router`（`21.9 µs`）、`top-8`（`6.2 µs`）和路由对齐核放到旁路流上，它们就能直接使用这 36 个空闲 SM 与 `pooler` 并行跑完，使 `T = 753` 整层实测提速 **3.18%–3.33%**。

当预填充词数升到 **`T = 3,012`** 时，`pooler` 和 `router` 开始争抢 SM。此时若继续沿用“`pooler` 在主流先行”的顺序，会使 `T = 3,012` 整层**倒退 `-0.76%`**；同样，在 `T ≥ 3,012` 下把 `router` 放在边界归一化核旁边并行隐藏，也会因争抢 SM 使整层**倒退 `-1.011%`**。再到首轮 **`T = 16,384`**，`pooler` 发出 `2,048` 个 CTA 占满全部 SM，如果让 `pooler` 先跑，旁路流上的 `router` 就会被一直挤到 `pooler` 末尾才启动（早期 `pooler` 先行版曾测得 `+0.93%`）。因此终版在这里**反转流序**：先在主流上跑完 `router`，再只把轻量的 `top-8` 和路由对齐放到旁路流上与 `pooler` 重叠（反转流序的单独增益未测）。另外，在预填充全长层的阶段 1 入口，在 `qkv_gate` 启动前先记录分叉事件，让旁路流同步准备历史键值的第 0 阶段，也使全算例几何平均提速 **0.16%**（输出比特级等价）。早期版本在 `qkv_gate` 启动之后才记录等待，结果键值准备等到 `qkv_gate` 在 `54.1 µs` 跑完后，才于 `56.3 µs` 启动。

**2. 同流 PDL 全链衔接：等待前先预读权重，触发点不能放在函数入口（主循环后 / 末尾掩码 vs 入口触发慢 `14.3 µs`）**

对于无法合并成同一个 kernel 的相邻阶段（阶段 1 → 2、阶段 2 → 3，以及阶段 3–8 各边界），我们在同一条 `stream` 上全部用 PDL 串联起来。开启 PDL 之后，后继 kernel 不必等前序 kernel 的最后一个 CTA 结束，而是可以在前序收尾时提前启动，先发指令把自己的静态权重预取进 L2，再调等待指令去接前序写出的激活数据（图 9-4 模式二与图 9-5 模式 2，图中 `P2` 指阶段 2 注意力边界、`P3` 指阶段 3–8 串联链）。

把这条链逐段接通后，三处边界都省下了交接时间。在阶段 3–8 各边界开启同流 PDL（同时去掉大批量专家核的协作启动属性），在 16 请求检验（`T = 128` 滑窗与全长）上实测省下 **1.9–3.2 µs**（单测省 `2.88 / 3.25 µs`，提速 `+1.17% / +0.91%`）。在阶段 1 → 2 边界开启带等待前预取的 PDL（单项增益未测），同时在解码注意力（`T = 1 / 16 / 32`）里修复了一处漏点：原先分片主核未开 PDL，导致合并核里的等待成了空操作。将主核触发放到尾循环后面、让合并核在读部分和之前等待后，掩盖了 `+1.31 / +1.34 µs` 的空隙，单请求全长解码省下 **1.21 µs**（`+1.49%`），16/32 请求提速 `+0.44%–0.70%`（注意用剖析器单独重放单个 kernel 时看不到这种跨核重叠，见第 10 章）。在阶段 2 → 3 边界，让 `o` 投影在等待前用 `prefetch.global.L2` 预取前几阶权重分块（配合 `T = 16 / 32` 合并核入口触发），掩盖了 `+1.12..+1.25 µs` 的空隙，使单请求滑窗检验（`T = 8`）提速 **0.80%**（16 请求滑窗解码 `+0.61%`，32 请求全长解码 `+0.19%`）。

使用 PDL 有一条生死线：**触发指令放的位置不对，开 PDL 反而比不开更慢。** 如果把 PDL 触发指令直接放在前序函数的入口，前序 kernel 刚一启动就会放行后继 kernel。后继 CTA 会立刻冲进来抢占 SM 和共享内存，跟正在跑主循环的前序核挤在一起共驻，直接把前序核拖慢。在 `T = 128` 全长检验（16 请求）实测里，入口触发让整层中位耗时从 **`230.8 µs` 退化到了 `245.1 µs`（慢 `14.3 µs`）**。改成按边界掩码分别选在主循环跑完之后（`T = 128` 的 `qkv_gate`、注意力与 `o` 投影）或者函数末尾（`T = 32` 的 `o` 投影）再触发，才在 16 请求滑窗与全长检验上分别拿到 **`+1.06%` 与 `+0.34%`** 的正收益。

**3. 小批量借 `pooler` 空闲的 68 个 SM 提前启动专家核，以及图捕获下的跨流竞态**

把旁路流和 PDL 触发位置结合起来，还能在小批量解码和检验（`T = 1 / 8 / 16`）上再抠出一段重叠（图 9-4 模式四与图 9-6 方式 2、方式 3）。

在 `T = 1 / 8 / 16` 下，阶段 5 的 C12 `pooler` 只占 `64` 个 SM，全卡还留有 `132 - 64 =` **68 个空闲 SM**。整层方案把阶段 6 的小批量持久专家核设为 `pooler` 的 PDL 后继，并在 `pooler` 的函数入口触发依赖。前面刚讲过满载算子不能在入口触发 PDL，但这里 `pooler` 只占不到一半 SM，入口触发正好让专家 CTA 落在另外 68 个空闲 SM 上。专家核启动后，先不读 `pooler` 尚未算完的激活，而是利用这段时间跑完 `1.4 µs` 的路由预处理和 `1.8 µs` 的首块权重 TMA 加载（一共隐藏掉 **3.2 µs** 的起步开销），最后再执行 `griddepcontrol.wait` 等待 `pooler` 写出数据。这一步使单请求滑窗/全长解码和单请求全长检验整层提速 **1.46%–1.96%**（含单请求滑窗检验 `+1.00%` 和 16 请求全长解码 `+0.77%` 共五个算例提速 `0.77%–1.96%`）。

就在开启专家提前启动之后，我们撞上了一个只在 CUDA Graph 重放时才会复现的跨流竞态（图 9-6 方式 2 vs 方式 3）。在逐算子下发的 eager 模式下，这套提前启动全部通过；但捕获进 CUDA Graph 连续多轮重放时，输出结果出错，残差相对 L2 误差高达 **`0.7–1.09`**。

原因在于旁路流上 `top-8` 核的触发位置。在图捕获模式下，旁路流 `top-8` 核里的入口触发变成了一条可编程依赖边。当专家核被 `pooler` 的入口触发提前唤醒时，`top-8` 的入口触发也提前放行了专家核。此时 `top-8` 刚刚启动，尚未把本轮选出的 `topk_ids` 写入显存，导致提前启动的专家核读到了上一轮图重放留下的旧 `topk_ids`。将 `top-8` 改为“入口只等待不触发、出口才触发”之后，专家核才只读本轮的新编号，连续重放测试 **`0 / 240` 次失败**，速度保持中性。

**4. 为什么不再往下合核：尾声硬塞小核与全层持久大核为什么反而更慢？**

走完上面三步，就可以用实测数据回答本节开头的问题：为什么不把更多算子并入前序核的尾声，或者合写成一个全层持久大核（图 9-5 模式 3）？

第一种反例是**把已被 PDL 重叠的独立小核，硬塞进前序大核的尾声**。在同流 PDL 下，独立小核已经与前序大核的收尾重叠执行。如果你非要把它塞进生产者最后一个到达的 CTA 或者核内尾声里，原本跨 SM 的流水重叠就会退化成核内同步栅栏后面的串行等待。在解码与检验中尝试过的 **7 项此类尾部融合全部亏损被拒**。例如将尾声并入滑窗检验注意力的最后一个 CTA，使 32 请求滑窗变慢 **`+6.75 µs`**（`0.9709×`）；将归一化并入 `T = 128 / 256` 尾声，在 4 个检验算例上全输 **`-0.5%..-1.0%`**。又如把专家后归一化塞进小批量专家核尾，核内每个作业都要跑一串耗时约 `2 µs` 的串行同步洗牌链，直接盖过了省掉独立后归一化核的收益，在解码 1 / 16 / 32 与检验 1 请求上分别变慢 **`+1.18 / +4.03 / +8.34 / +2.62 µs`**。预填充中同样如此。在 `T = 3,012 / 16,384` 下把专家后归一化加权和并入 `gemm2`，使 `gemm2` 单核拉长 **`~145 µs` 与 `~340 µs`**，整层倒退 **`-1.97%`**（且 5 个种子中有 2 个精度失败）。在 `T = 16,384` 下把残差边界并入 80 寄存器的 `o` 投影尾声，整层也倒退 **`1.5%–6.8%`**（并入 `pooler` 尾声同样亏损）。

第二种反例是**跨阶段多算子合写大核与全层持久大核（Megakernel）**。尝试把多个阶段合写进单个集群或协作大核（例如把专家、升维投影 `unpooler` 和残差边界合为一核，或把 `qkv_gate` 和注意力合为一核）时，阶段交接处需要约 `1.4 µs` 的全网格栅栏。这道核内串行尾部比用 PDL 串联的两个独立核更长（双核 PDL 串联净快 `0.70–0.82 µs`，机制见第 1 章第 3 节）；其中把专家至层尾边界合写的大核方案，实测比线上流水线**慢 `1.05 ms`**。

直接测算核间空隙的耗时上限（方法见第 10 章），就能算清这笔账。在解码与检验整层上，用全局计数器调度的持久大核本身有 **`+8.3 µs`** 的结构惩罚，而整层所有核间空隙加起来的理论上限仅 **`+1.9%`**（接近 `1.4%` 的测量噪声；真正占大头的是核内负载不均衡的 `+5.5%` 与未覆盖 PDL 边的 `+2.3%`）。结构惩罚盖过了全部空隙上限，因此未构建即被否决。在预填充整层上，每个算例的核间空隙仅 `3–5 µs`（`T = 753` 全卡联合空闲仅占跨度的 `0.65%`），后两组预填充算例的理论上限仅 **`≤ 0.05% / ≤ 0.16%`**，同样由测量直接关闭。

**带走一句话：** 单层阶段 1–8 的总装之所以不用单一持久大核，是因为核内串行尾与驻留锁定付出的代价远超微秒级核间空隙；根据各阶段在当前批量下的 SM 余量与矩阵线性性质，把特殊投影、跨核行缩放折入、旁路流与主循环后触发的同流 PDL 组合起来，才能让整层紧贴硬件下界运行。
