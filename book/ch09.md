## 1. 阶段 4（`router` 单精度投影与 Top-8 选择）：怎样在 BF16 Tensor Core 上保住 FP32 精度并把单波次与尾步压到极致？（`l0`）

<!-- FIG ch09-router: 图 9-1 画阶段 4（router 路由器与 Top-8 选择）从单精度权重拆分为高/低两份 BF16 残差对送入 Swap-AB Tensor Core、T=3,012 下将分块扩至 BT=192 缩为 128 个 CTA 单波次、0..3 号清零 CTA 加辅助 warp 轮询单调标志、到单 warp redux.sync 无共享内存选出 Top-8 专家的完整解剖与时间线。 -->

数据流穿过阶段 3 的第一道残差边界后，预归一化激活 `h` 一分为二，其中一条支路进入阶段 4 的路由器（`router`）与 Top-8 专家挑选。它是全层五个稠密投影里唯一强制使用 32 位单精度（`FP32`）权重的阶段，因为微小的路由打分舍入误差就会翻转第 8 名与第 9 名专家的排序，直接改变阶段 6 激活哪几个专家。
- 公式：先在单精度下计算 256 个全局专家的打分 `scores = sigmoid(0.1767767 * (Float32(h) @ W_router.T))`，加上偏置挑出最高的 8 个全局专家编号 `topk_ids = argtopk_8(scores + b_router)`，最后将选中的 8 个无偏置打分归一化为和等于 1 的路由权重 `w_raw = gather(scores, topk_ids)`、`topk_weights = w_raw / sum(w_raw, dim=-1)`。
- 输入：阶段 3 分叉送来的激活 `h`（形状 `[T, 8192]`，BF16，每词 `16 KiB`，位于 HBM 或 L2）、单精度路由权重 `W_router`（形状 `[256, 8192]`，FP32，占 `8,388,608 B = 8.4 MB`，位于 HBM）与偏置 `b_router`（形状 `[256]`，FP32，占 `1 KiB`，位于 HBM）。
- 输出：选中的专家编号 `topk_ids`（形状 `[T, 8]`，`int32`，每词 `32 B`）与归一化权重 `topk_weights`（形状 `[T, 8]`，FP32，每词 `32 B`），写回 HBM 或 L2。
- 交给下一步：`(topk_ids, topk_weights)` 交给阶段 6（本地路由专家），用于位图筛选或分桶重排。
- 本步代价：因为每个 4 字节 FP32 权重只做 2 次浮点运算，算术强度仅为 `0.5 × T FLOP/B`（比同形状 BF16 投影低一半）。在 `T = 1` 下读 `8.4 MB` 的带宽下界为 `1.8 µs`（`1.75 µs`）；到 `T = 256` 下界为 `2.7 µs`；即便到预填充 `T = 753`（计入激活读写后强度 `147 FLOP/B`），它仍是五个稠密投影中唯一尚未跨过 `206 FLOP/B` 平衡点的显存受限阶段（带宽耗时 `4.48 µs` 大于算力耗时 `3.19 µs`）。

顺着 `T` 从区间 I（`T = 1`）跨入区间 II（`T = 8..256`）与区间 III（`T = 753..16,384`），阶段 4 在矩阵乘、Split-K 归约尾与 Top-8 选择三处选定了以下演化路径（构成单层总装起点 **`l0`**）。
- 矩阵乘路径：从 `T = 1` 的 8-warp 流式核，到 `T ≥ 8` 的 `hi + lo` BF16 残差对与 `T = 3,012` 的 `BT = 192` 单波次分块。
  1. 在区间 I（`T = 1` 单请求解码）下，算术强度只有 `0.5 FLOP/B`。我们直接把针对 `T = 1` 打磨的 8-warp 单精度向量乘内核移植进整层，替换通用基线，使单请求滑窗与全长解码整层分别提速 **1.22% 与 1.01%**（全项合入比单项测试多省约 `2.6 µs`）。
  2. 一旦进入区间 II 与区间 III（`T ≥ 8`），如果因为权重是 FP32 就留在 CUDA Core 上算，矩阵乘立刻就会掉队。第 5 章第 3 节讲过，任意 FP32 权重都能无损拆成高、低两份 BF16 残差对 `W_fp32 ≈ W_hi + W_lo`。在 `T = 8..256` 下，每步 `K` 在 BF16 Tensor Core 上发 2 次 MMA 并累加进同一个 FP32 累加器，一次启动就省掉了 cuBLAS 的拆分与归约核，把 `T = 128 / 256` 的路由器耗时从 `8.15 / 11.21 µs` 压到 `7.32 / 9.23 µs`。在预填充下，高、低两份权重直接堆叠成 `[512, 8192]` 的 BF16 矩阵一次算完，随后在片上相加并顺手完成 `sigmoid`、Top-8 与本地专家映射。
  3. 到了 `T = 3,012`（4 请求多轮预填充），输出专家维只有 `256` 行。阶段 4 先用交换左右矩阵（Swap-AB，把专家维放到 `wgmma` 的 `M = 64` 维、词元维放到 `N = 192` 维，见第 5 章第 3 节）配合 5 槽环，将耗时从 `60.5 µs` 压到 `37.6 µs`。但这时若按 `BT = 128` 切分词元维，会产生 `(4, 24, 2) = 192` 个 Split-K CTA，在 132 个 SM 上拖出半个第 2 波次。把词元分块扩到 **`BT = 192`** 后，网格缩减为 `(4, 16, 2) =` **128 个 CTA**，刚好一个波次塞进 132 个 SM，在 `T = 3,012` 滑窗层上再省 **15.0 µs**（整层提速 `0.79%`，全长层提速 `0.44%`）。代价是 5 槽 `192 × 128` 环形缓冲占了 `204,896 B`（约 `200 KiB`）共享内存，每个 SM 只能驻留 1 个 CTA。
- Split-K 归约尾与 Top-8 选择的选定路径（回指第一部分硬件机制）。
  - 在 `T = 8..256` 的路由器 Split-K 归约尾中，最后到达者的同步与拷贝尾原本要花 `1.05–1.15 µs`。我们选定第 2 章第 4 节的“清零 CTA + 单调递增标志”方案，在 `T = 8 / 16 / 32` 上分别省下 `0.88 / 1.07 / 0.98 µs`。到了 `T = 128 / 256`，每个 TMA CTA 占 `196,640 B` SMEM（每 SM 限驻 1 个 CTA），负责清零的 4 个 CTA 必须排在最靠前的 `program_id 0..3` 才不会死锁，实测省下 `1.22 / 1.72 µs`（见第 2 章第 2 节）。而在 `T = 16 / 32` 下，把块线程数从 128 扩为 160，由第 5 个辅助 warp 在等数据期间并行取票、轮询标志并剥掉 20 条零字节死预取，又能再省 `0.57 / 0.50 µs`（若让 0 号消费者线程自己轮询，反而会排在 40 条在途拷贝后面变慢 `+0.32 µs`，见第 4 章第 2 节）。
  - 紧随其后的 Top-8 选择彻底告别了共享内存与块内屏障。在解码与检验全范围（`T = 1..256`），每个词元由 1 个 warp 负责，每轮用 2 条 `redux.sync` 指令在寄存器内直接选出最大专家：warp 指令减少 `61%`，LSU 占用从 `12.8%` 降到 `0.6%`，使 `T = 1` 滑窗/全长整层提速 `1.29% / 2.81%`，并将 `T = 256` 的 Top-8 核从 `4.96 µs` 压到 `3.65 µs`（见第 4 章第 4 节）。在预填充（`T = 3,012 / 16,384`）下，则改用每行 8 个线程的单 warp 归约，将 Top-8 耗时从 `35.5 / 44.0 µs` 压到 `22.0 / 23.6 µs`（整层提速 `0.36%–0.56%`，见第 4 章第 2 节）。

## 2. 阶段 1、3、5、7 稠密投影的特殊形态：$T \le 8$ 切片 `unpooler`、C12 逃逸回退梯与大批量尾波切平（`l0 → l1`）

<!-- FIG ch08-p5-flip: 图 9-2 画同一层模型从 Decode（T=1）经多轮追加 Prefill（T=753 / 3,012）到首轮分块 Prefill（T=16,384）的各阶段算术强度、每专家平均词元数与理论下界翻转解剖图（对应稠密投影、分页注意力与 32 个本地专家在四档批量下的 GFLOPs 账本，以及 T=753 旁路流并发与 T=3,012 / 16,384 Stream-K 尾波切分的算法步）。 -->

除阶段 4 的单精度路由器外，阶段 1（`qkv_gate [2304, 8192]`，`37.7 MB`）、阶段 3（`o [8192, 1024]`，`16.8 MB`）、阶段 5（`pooler [4096, 8192]`，`67.1 MB`）与阶段 7（`unpooler [8192, 4096]`，全矩阵 `67.1 MB`）构成了单层的四个 `BF16` 稠密投影。它们的通用内核机制已在第一部分走完，但在装入单层时，阶段 7 在 `T = 8 → 16` 处有一道切片跳变契约，而全层四个投影在跨越区间 I、II、III 时则要分别解决判官随机权重的 C12 逃逸爆表与大批量持久网格的尾波空闲。
- 阶段 7（`unpooler`）的 `T ≤ 8` 切片契约与下界跳变：
  - 公式：当 `T ≤ 8`（单请求解码与单请求 8 词检验）时，只计算前 `1,024` 列切片 `f[:, :1024] = m @ W_unpooler[:1024, :].T`，其余 `1024..8191` 列填 0（线上由 8 张卡各算 `1,024` 列再做跨卡拼接，单卡评测省去通信）；一旦 `T > 8`，必须计算完整 `8,192` 列 `f = m @ W_unpooler.T`。
  - 输入与输出：输入阶段 6 汇总的专家激活 `m [T, 4096]`（BF16，每词 `8 KiB`，位于 HBM 或 L2）与权重 `W_unpooler`（`T ≤ 8` 切片 `[1024, 4096]` 占 `8.4 MB`，`T > 8` 完整 `[8192, 4096]` 占 `67.1 MB`，位于 HBM）。输出升维特征 `f [T, 8192]`（BF16），交给阶段 8。
  - 本步代价：在 `T ≤ 8` 时只读 `8.4 MB`（下界 `1.75 µs`）；到 `T = 16` 时跃升 8 倍读满 `67.1 MB`（下界 `14.0 µs`），单此一阶段的下界就跳增 `12.2 µs`（叠加 16 请求的专家与键值读取后，整层下界从 `T = 8` 单请求检验到 `T = 16` 解码在滑窗层跳增 **14.4 µs**［`62.3 → 76.7 µs`］、在全长层跳增 **71.1 µs**［`66.4 → 137.5 µs`］）。
- 区间 I 与区间 II（`T = 1..32`）的选定路径与 C12 逃逸回退梯：
  - 在 `T = 8` 下，切片后的 `unpooler` 只有 `1,024` 行输出，基线只发 `64` 个 CTA（`16 × 1 × 4`），连 132 个 SM 的一半都填不满。整层方案把它换成 `128` 个 CTA 的 8 路 Split-K 12 位无损 C12 切片核（权重从 `8.4 MB` 压到 `6.3 MB`，8 份单精度部分和由层尾边界核顺手归约，见第 2 章第 1 节与第 6 章第 4 节），使单请求滑窗与全长检验整层分别提速 **1.29% 与 1.42%**（`109.0 → 106.8 µs`、`119.0 → 118.0 µs`）。同理，`T = 8 / 16` 的 `qkv_gate` 采用 3 路 Split-K 的 `108`-CTA 单波次 C12 核（提速 `+0.65%..+1.58%`，见第 2 章第 1 节）。在 `T = 1..32` 的 `pooler / unpooler` 上，则组合了三项第一部分机制：一是 C12 带宽布局配 L2 留存提示（7 个算例提速 `+0.21%..+1.45%`，`T = 8` `pooler` 关闭提示，32 请求全长检验微退 `-0.16%`，见第 3 章第 2 节）；二是每 8 个权重 9 条 ALU 指令解码（见第 6 章第 3 节）；三是在最后一步 `K` 循环提前拼好逃逸修正操作数，让 16 条 `wgmma` 共享一次提交与等待（省下 `0.18–1.23 µs`，代价是寄存器从 `92–122` 涨到 `164–168` 并在 `unpooler` `T = 32` 上溢出 `8 B`，见第 3 章第 3 节）。
  - 判官随机权重下的 C12 逃逸爆表与回退梯反例：为什么本地自测全过的 C12 打包到了评测器上会触发慢速回退？因为早期描述符将每步逃逸权重上限设为 `4`（仅按本地种子 `0..3` 标定），而判官用独立随机种子生成权重时，在 64 个随机种子中有 `6` 个 `qkv_gate`、`14` 个 `pooler` 与 `2` 个 `unpooler` 种子超出上限 4 返回空包！若直接回退到稠密 BF16，`qkv_gate` `T = 32` 耗时将从 `15.3 µs` 暴涨至 `37.2–39.6 µs`。修复方案是先按大样本普查将描述符逃逸上限从 `4` 扩至 **`8` 字/warp**，再为超限空包建立多级回退梯（`qkv_gate` `T = 32` 回退至 `15.30–15.39 µs` 的流式核，预处理函数保留稠密 BF16 兜底路径而绝不抛异常）。这一合规修复保住了 100% 种子通过率，但付出了在正常种子上每步多扫一倍逃逸槽的真实代价，使 `unpooler` `T = 128` 与 `T = 256` 的短记分牌停顿增加 `45%`、耗时分别变慢 **`+0.32..+0.60 µs` 与 `+0.28 µs`**。

在图 9-2 中依次切换 `T = 1`、`T = 753`、`T = 3,012` 与 `T = 16,384` 四档负载，读数依次为：`T = 1：七个阶段强度 0.5–16 FLOP/B，都低于平衡点 206` / `赛题整层下界 44.2 µs（全长层）= 读 HBM 的时间`、`T = 753：每个专家平均 24 个词元（< 58）· 稠密投影强度 147–590 FLOP/B` / `赛题整层下界 496.7 µs（全长层）= 按算力算，专家阶段还没到算力区`、`T = 3,012：每个专家平均 94 个词元（> 58）· 稠密投影强度 208–1,432 FLOP/B` / `赛题整层下界 1,992.4 µs（全长层）= 按算力算`、以及 `T = 16,384：每个专家平均 512 个词元（> 58）· 稠密投影强度 234–2,341 FLOP/B` / `赛题整层下界 9,847.7 µs（全长层）= 按算力算`。到了 `T ≥ 753`，四个 BF16 稠密投影全部跨入区间 III（算术强度 `412–2,341 FLOP/B`，总运算量从 `145 GFLOP` 升至 `3,161 GFLOP`）。它们从早期的预转置库核基线（见本章第 1 节）统一升级为每 SM 驻留 1 个持久 CTA 的线程束分工 `wgmma` 内核，单核比旧集群分块核快 `1.05–1.30 倍`（见第 3 章第 1 节；其中 `T = 753` 的 `pooler` 采用 4 级 TMA 流水把耗时从 `87.25 µs` 压到 `82.12 µs`，整层提速 `+0.89%`，见第 3 章第 4 节）。不过，持久网格按固定尺寸切分大矩阵时，最后一波的分块数往往不能被 132 整除。为了不让几十个 SM 在尾波空转，我们在 `T = 3,012` 与 `T = 16,384` 下分别加入了尾波切平策略（推进至 **`l1`**）。
- `T = 3,012` 滑窗层 `qkv_gate` 的两段式 `K` 锁步尾波切分（图 9-2 第 8 步）：
  - 在 `T = 3,012` 下，`qkv_gate` 共切出 `216` 个输出分块（`132 + 84`）。前 132 个分块跑完第 1 波后，第 2 波只剩 `84` 个分块，留下 `132 - 84 =` **48 个 SM 空转约 `28 µs`**。
  - 改造后，`0..83` 号 CTA 只计算各自第 2 波分块的前 `82` 个 `K` 步（共 `8,192 ÷ 64 = 128` 步），而原本空闲的 `84..131` 号 CTA 进场协作计算这 84 个分块的后 `46` 个 `K` 步（`82 + 46 = 128`），最后由前 84 个 CTA 汇总写出。这一下把全卡 CTA 结束时间的极差-均值差从 `29.4 µs` 压到 **7.4 µs**，`qkv_gate` 单核缩短 **8.7 µs**（整层单独提速 **`+0.177%`**，与注意力半精度累加合入提速 **`+1.930%`**）。
  - 取舍与何时亏本：第二波 132 个 CTA 同时拉取数据使 HBM 读取量增加 `6.45%`（`141.7 → 150.8 MB`），单步 `K` 耗时从 `0.61–0.66 µs` 升至 `0.78 µs`；而在 **`T = 3,012` 全长层**上，由于旁路流上的历史键值准备核（`2,524` 个 CTA）同时在争抢 SM，开启该切分反而使整层**倒退 `-0.10%`**，因此严格门控在**仅滑窗层**开启。
- `T = 16,384` 下 `qkv_gate / pooler` 的 Stream-K 与 `unpooler / o` 的编译期列切窄：
  - **Stream-K** 是把最后一波残余分块的求和维 `K` 步均摊到全卡所有 CTA 的尾波切分方式。在 `T = 16,384` 下，持久核按轮转领块时，`qkv_gate`（9 个整波余 `96` 块）与 `pooler`（16 个整波余 `68` 块）在末波共有 **85 µs** 的尾波空闲。用 Stream-K 将最后 `(tiles mod grid)` 个尾波分块的 `K` 步平摊给全卡 CTA 并由起始分片汇合单精度部分和后，`qkv_gate` 与 `pooler` 分别缩短 **13 µs 与 28 µs**（整层合入提速 `+0.35%`；代价是部分和写出使 `qkv_gate` 的 Tensor Core 活跃占比从 `98.3%` 微降至 `96.9%`）。
  - 同时，将 `unpooler` 末尾 4 个分块与 `o` 末尾 8 个分块按输出列切窄为 `1/4` 与 `1/2` 宽度的子单元分摊给空闲 SM，使 `unpooler` 耗时从 `1,350.5 / 1,365.0 µs` 降至 **1,334.75 / 1,344.75 µs**（缩短 **15.8–20.3 µs**，首轮整层提速 `+0.73%–0.81%`）。但这项列切窄有两个硬边界：若把 4 路尾块切窄套用到大 `L` 的 `qkv_gate` 或 `o` 上，额外分块开销大于尾波收益，整层反而**倒退 `-1.3%`**；若把 `unpooler` 主循环上界从编译期常量（`constexpr`）改成运行期变量，多出的循环分支控制开销也会使整层**倒退 `-0.45%`**。同理，在小批量解码 `T = 32` 的阶段 6 专家下投影上尝试 Stream-K 时，由于每分块工作量小且受 80 寄存器（6 CTA/SM）与部分和板条流量拖累，实测反而**变慢 `+1.84 / +7.20 µs`**（复现仍慢 `+0.91 µs`）被彻底否决。

## 3. 跨阶段代数折入与层间残差边界：怎样利用矩阵乘行线性性质消掉独立的归一化 Kernel？（`l1 → l2`）

<!-- FIG ch08-p5-fuse: 图 9-3 画阶段 5（pooler）与阶段 6（专家 gemm1）之间的跨核代数融合数据流（对应 T=3,012 时将独立 pre_expert_norm 的按列乘 gain 与每行 16 个部分平方和拆入 pooler 尾声写出、再由专家 gemm1 读入部分平方和算出 r_m 在累加器尾声完成行缩放，从而省去 49.3 MB HBM 往返与 14 µs 独立 kernel 的算法步）。 -->

当阶段 1、3、4、5、7 的五个稠密投影各自成型后，夹在算子之间的四处均方根归一化（`RMSNorm`）与两道可学习门控残差就暴露成了新的瓶颈。其中阶段 1 尾声的按头归一化（`T = 1` 下经 L2 计数由第 16 个到达 CTA 原地完成，见第 6 章第 4 节；多词下合入阶段 2 融合序言，见第 1 章第 1 节与第 7 章第 1 节）和阶段 2 尾声的门控输出归一化（原地合入注意力尾声，见第 7 章第 6 节）都与前序算子同维度，可以直接核内融合。唯独夹在阶段 5（`pooler` 降维投影）与阶段 6（专家上投影）之间的专家前均方根归一化（`pre_expert_norm`）遇到了跨维度障碍：`pooler` 是按列切分输出特征维 `4,096` 的，每个 CTA 只握有一行激活的局部列切片（如 256 列），无法在核内单独求出整行 `4,096` 列的平方和均值。基线因此被迫在 `pooler` 之后单独启动一个归一化小 kernel，把刚写回显存的中间激活重读一遍、算完归一化再写回显存。
- 跨核线性等价式与数据流解剖（图 9-3）：
  - 基线三步公式：阶段 5 先算 `x_pool = h @ W_pooler.T`；独立归一化 kernel 对每行 `m` 算出均方根倒数标量 `r_m = rsqrt(mean_k(x_pool[m, k]^2) + 1e-5)` 并写出 `p[m, k] = (x_pool[m, k] * r_m) * (1 + w_pre_expert[k])`；随后阶段 6 专家上投影计算 `[h_gate[m, :] | h_up[m, :]] = p[m, :] @ dequant_nvfp4(W13[e]).T`。
  - 矩阵乘对行缩放的线性齐次性：均方根归一化由两步可交换的乘法组成——先按列乘固定增益 `gain[k] = 1 + w_pre_expert[k]`，再按行乘整行共享的标量 `r_m`。因为紧随其后的阶段 6 第一层矩阵乘对每行输入是严格线性的，先把输入行乘标量 `r_m` 再乘矩阵 `W13`，代数上完全等价于先用只乘过列增益的 `xb_gain[m, k] = BF16(x_pool[m, k] * gain[k])` 执行矩阵乘，最后在矩阵乘尾声把算出的整行单精度累加器乘上同一个 `r_m`。
  - 输入、输出与交接数组变化：
    1. 在区间 I 与区间 II（`T = 1..32` 解码）下，`pooler` 的每个列分块 CTA 在写出尾声直接乘上 `gain[k]` 写出 `xb_gain [T, 4096]`（BF16），并对全局单精度计数器执行一次原子加累加该行的部分平方和；阶段 6 专家内核在入口读入总平方和、算出 `r_m` 完成缩放。这在 `T = 1` 下直接砍掉了关键路径上的一次依赖启动（整层启动从 `12` 次减为 **`11` 次**），使单请求滑窗与全长解码整层实测分别省下 **0.82 µs**（`+1.15%`，兑现微扰删除实验 `1.41 µs` 上界的 `58%`）与 **1.47 µs**（`+1.39%`）。
    2. 在区间 III（`T = 3,012` 与 `16,384` 预填充）下，中间张量 `x_pool [3012, 4096]`（BF16）占 `3,012 × 4,096 × 2 B =` **24.7 MB**（在 `T = 16,384` 下更达 `134.2 MB`，超出 60 MiB L2 容量两倍多）。独立归一化 kernel 读一遍 `24.7 MB` 再写一遍 `24.7 MB`，凭空多出 **49.3 MB** 的 HBM 往返（按 `4.8 TB/s` 带宽下限为 `10.3 µs`，`T = 3,012` 实测该独立 kernel 耗时约 **14 µs**）。如图 9-3 所示，改造后 `pooler` 的 16 个列段分块在尾声各自写出 `xb_gain [T, 4096]`（BF16）与该列段的部分平方和 `rs_part [T, 16]`（FP32，每词仅 `64 B`，在 `T = 3,012` 下读写各 `0.19 MB` 共 `0.39 MB`，扣除后净省显存流量 **48.96 MB**）；阶段 6 的专家 `gemm1` 读入 `xb_gain` 与每行的 16 个部分平方和，求和算出 `r_m` 并在 SwiGLU 尾声完成行缩放。在图 9-3 中切换方式 1 与方式 2，读数分别为：`独立 kernel：多 1 个 kernel、多 49.3 MB 往返` / `T = 3,012 时约 14 µs（下限 10.3 µs）`，以及 `拆入尾声：少 1 个 kernel、少 49.3 MB 往返` / `单项提速 0.23%；合并测试 0.60% / 1.35%`。
  - 取舍与何时亏本：将行标量 `r_m` 移到 `BF16` 截断与矩阵乘之后会改变浮点舍入点（产生约 `0.3%` 的数值重结合差异，在容差内）；而在 **`T = 753`**（单请求多轮追加预填充）下，独立归一化原本仅耗时 `3.7 µs`，把部分平方和写出塞进 `pooler` 后恰好把 `pooler` 单分块尾声拉长了同等时间，导致 `T = 753` 实测净收益为 **0**；同理，在投机检验 **`T = 128 / 256`** 上尝试将归一化塞进 `pooler` 尾声时，因拉长了 PDL 交接关键路径反而使全部 4 个检验算例**变慢 `-0.5%..-1.0%`** 被否决（详见第 4 节）。

解决了阶段 5 到阶段 6 的跨核交接后，单层还剩下阶段 3（`o` 输出投影后的第一道门控残差与前馈预归一化）和阶段 8（`unpooler` 后的第二道门控残差与下一层预归一化）两处全宽 `8,192` 维的边界归一化内核（推进至 **`l2`**）。
- 阶段 3 与阶段 8 门控残差边界的解剖与选定路径（回指第一部分与第 7 章机制）：
  - 公式与数据流：阶段 3 边界核读入 `a = o_attn @ W_o.T`（`[T, 8192]`，BF16）与入口残差流 `stream_0 [T, 8192]`（FP32，每词 `32 KiB`），按可学习门控 `beta_1 = sigmoid(g_1 / 0.3)`、`alpha_1 = sqrt(max(sigmoid(-g_1 / 0.3) * (1 + beta_1), 1e-3))` 算出更新后的残差流 `stream_1 = alpha_1 * stream_0 + beta_1 * rmsnorm(a, 1e-8)`（FP32，写回 HBM 留给阶段 8）与分叉激活 `h = rmsnorm(stream_1, 1e-5) * (1 + w_pre_ffn)`（BF16，每词 `16 KiB`）。阶段 8 边界核以完全对称的公式读入阶段 7 输出 `f [T, 8192]`（BF16）与 `stream_1`，算出 `stream_2 = alpha_2 * stream_1 + beta_2 * rmsnorm(f * (1 + w_post_ffn), 1e-8)`（FP32）与下一层入口 `x_next = rmsnorm(stream_2, 1e-5) * (1 + w_next_pre_attn)`（BF16），每词合计读写 `96 KiB`。
  - 选定硬件改造路径：
    1. 在解码与投机检验（`T = 1..256`）的集群边界归一化核中，原本的三次 `barrier.cluster.arrive.release` 会编译出全卡 `MEMBAR.ALL.GPU + ERRBAR + CGAERRBAR`（占未发射周期 `36%–46%`）。改用 `st.async` 加本地 `mbarrier` 交换部分平方和后，每次调用省下 **0.86–0.99 µs**，整层几何平均提速 **0.46%**（见第 7 章第 6 节）。需要注意的是，每次行归约必须分配独立的共享内存缓冲区（在 `T = 256` 边界核上多出 `8 B` 栈溢出），因为首版共用单个 `warp_part` 缓冲区在 `compute-sanitizer racecheck` 下抓出了 8 处写后读（WAR）竞态（见第 3 章第 4 节）。
    2. 在预填充（`T = 753..16,384`）下，首先把全部 6 个残差/归一化行内核与专家后归一化从 Triton 改写为原生 CUDA C++，在首轮 `T = 16,384` 上提速 `+0.54%–0.73%`（在 `T = 3,012` 上微退 `-0.11%..-0.28%`，见第 6 章第 1 节）。接着按批量分档调优驻留与访存：在 `T ≤ 1,024` 下对流式激活行加 `evict_first`、对复用权重加 `evict_last`（见第 2 章第 3 节）；在 `T < 4,096` 用 16 个 warp、在 `T ≥ 4,096` 用 8 个 warp；在 `T > 1,024` 下把两处残差边界核压到 `64` 个寄存器，使每 SM 驻留从 3 个升至 4 个 CTA（配合路由 `CHUNK = 16,384` 提速 `+0.23% / +0.30%`，代价是在阶段 8 边界核产生 `8 B` 溢出，见第 3 章第 1 节）。而在 `1,024 < T ≤ 3,012` 区间，则把边界核扩为每行 `512` 个线程（每 SM 驻留 2 个 CTA），在第一次归约前把 `x` 与 `s_in` 的全部 16 字节 `LDG.128` 一口气并发发出，掩盖长记分牌等待使 `T = 3,012` 整层再提速 **0.20%**（见第 4 章第 2 节）。

现在退回到第 0 级（全层时间线，见第 0 章第 2 节与第 1 章），把阶段 1 到阶段 8 的全部内核组装成一条完整的单层流水线（推进至终版 **`l3`**，图 9-4、图 9-5 与图 9-6）。SGLang 基线按单流顺序依次启动约 `17` 个独立 kernel（具体哪 17 个内核对应哪几个阶段的逐一名称未测）：即使录制进 CUDA Graph，相邻两个节点之间仍有中位数 `1.024 µs`（约 `1.0 µs`）的启动空隙，16 道边界合计白白耗去约 `16.4 µs`（占单请求解码 `40.0 µs` 理论下界的四成，对应图 9-4 模式一读数： `①单流顺序：约 17 个 kernel，每个后继都等上一个完成并落盘` / `每个 kernel 边界约 1.0 µs（graph 内）· 示意总长 60.5 格（不是 µs）`）。经过第 7 章的注意力序言与归约内联、第 8 章的专家持久化以及本章第 3 节的跨核线性折入，单层在 `T = 1` 下被收敛为 **11 个 kernel**（每条单 CTA 编程依赖启动串行边约 `0.64 µs`，11 个核量级约 `7.0 µs`）。在图 9-6 中选方式 1，读数为：`11 个 kernel · 每条 PDL 串行边约 0.64 µs（基线约 17 个）` / `一层最短 40.0 µs（滑窗层，共读 191.9 MB）`。围绕这 11 个内核的分叉拓扑与串行边界，整层总装在旁路流调度、同流 PDL 链、空闲 SM 提前抢跑与融合禁区上做出了四项核心决策。

- 决策一：**旁路流（Side Stream）** 是与主流并行下发无依赖算子的第二条 CUDA 流；阶段 4 与阶段 5 分叉点（`router ∥ pooler`）及阶段 1 序言按主流剩余 SM 数动态调度旁路流。
  - 因为阶段 3 输出的 `h [T, 8192]` 同时喂给阶段 4（`router + top-8`）和阶段 5（`pooler`），两者没有数据依赖，天然可以放上两条 CUDA `stream` 并行执行。但谁先启动、谁走旁路，取决于主流内核占用了多少个 SM：
    1. 在解码与投机检验（`T = 1..256`）下，基线将 `router + top-8` 放在旁路流并先于主流 `pooler` 启动（在 `T = 128` 滑窗检验上，`router` 耗时 `38.9–47.7 µs` 与 `pooler` 的 `49.1–72.5 µs` 重叠，省去 `5–8 µs` 空洞；但在 `T = 128 / 256` 下两核分别占 `131 KiB` 与 `198 KiB` SMEM 无法同 SM 共驻，若为强行共驻而把 `pooler` 环形缓冲从 6 槽砍成 4–5 槽，单核反而变慢 `5.0–8.4 µs`，见第 3 章第 4 节）。唯独在 **`T = 128`（16 请求检验）** 这个区间 II 甜点上，把 `pooler` 与 `router` 直接合写进单次启动（外加旁路流 1-CTA 门控核通知 `top-8`）能让合并核提前约 `10 µs` 进场、彻底关掉两核之间 `8.5 µs` 的启动空隙；尽管合并核多读 `12.5%` 权重使自身变长 `2.6–7 µs`，仍净省约 **`3 µs`**（滑窗与全长整层分别提速 **1.30% 与 0.88%**）。一旦升至 **`T = 256`（32 请求检验）**，合并核自身膨胀约 **`8 µs`**，把省下的空隙全部抵消，因此在 `T = 256` 变慢被拒，恢复双流分立。
    2. 在预填充 **`T = 753`（`T ≤ 1,024`）** 下，主流 `pooler`（`128 × 256` 分块，每 SM 1 个 CTA）只启动 `96` 个 CTA，在 132 个 SM 上恰好留出 **`36` 个空闲 SM**。把 `router`（`21.9 µs`）、`top-8`（`6.2 µs`）与路由对齐核放到旁路流上，就能白捡这 36 个空闲 SM 与 `pooler` 并行跑完，使 `T = 753` 整层实测提速 **3.18%–3.33%**（对应图 9-4 模式三读数：`③旁路流：router 与 pooler 并行（T = 753，pooler 占 96 个 SM，空闲 36 个）` / `整层实测提速 3.18 %–3.33 % · 示意总长 35.2 格（不是 µs）`）。
    3. 当预填充升至 **`T = 3,012`** 时，`pooler` 网格已超过 132 个 SM；若继续套用“`pooler` 主流先行、旁路并跑 `router`”的顺序，两核争抢 SM 反而使 `T = 3,012` 整层**倒退 `-0.76%`**（同理，在 `T ≥ 3,012` 下尝试把 `router` 放在边界归一化核旁并行隐藏也因 SM 争抢**倒退 `-1.01%`**）。而到了首轮 **`T = 16,384`**，`pooler` 高达 `2,048` 个 CTA 会把全部 132 个 SM 堵死，导致旁路流上的 `router` 被迫推迟到 `pooler` 末尾才启动（早期采用 `pooler` 先行曾测得 `+0.93%`）；终版因此**反转流序**：先在主流全卡跑完短小的 `router`，再只把 `top-8` 与路由对齐放到旁路流与 `pooler` 重叠（该反转流序的单独分离增益未测）。
    4. 此外，在预填充全长层的阶段 1 入口，必须在启动 `qkv_gate` **之前**先记录主流分叉事件，让旁路流上的历史键值准备第 0 阶段与 `qkv_gate` 并行执行，使全算例几何平均提速 **0.16%**（比特级等价；早期误把分叉等待记录在 `qkv_gate` 启动之后，导致键值准备一直等到 `qkv_gate` 在 `54.1 µs` 跑完后才于 `56.3 µs` 启动，完全失去重叠）。

- 决策二：跨阶段**同流 PDL 全链衔接**与触发点位置掩码（`post / end` vs 入口触发反例，图 9-4 模式二与图 9-5 模式 2）。
  - 对于无法合核的相邻阶段（阶段 1 `qkv_gate` → 阶段 2 注意力 → 阶段 3 `o` 投影与残差边界 → 阶段 5 `pooler` → 阶段 6 专家 → 阶段 7 `unpooler` → 阶段 8 层尾边界），在同一条 `stream` 上全部用编程依赖启动（PDL，四步握手原理见第 1 章第 2 节）串联（对应图 9-4 模式二读数：`②PDL 链：后继在上一个 kernel 收尾时启动并预读权重` / `T = 128 整层实测省 1.9–3.2 µs · 示意总长 37.2 格（不是 µs）`）：
    1. 在阶段 3–8 各边界开启同流 PDL（并去掉大批量专家核的协作启动属性），在 16 请求检验（`T = 128` 滑窗与全长）上实测省下 **1.9–3.2 µs**（单测省 `2.88 / 3.25 µs`，提速 `+1.17% / +0.91%`）。
    2. 在阶段 1 → 阶段 2 边界开启带等待前预取的 PDL，並在解码注意力（`T = 1 / 16 / 32`）中修复主核原本未开启 PDL 导致合并核等待成空操作的漏点，将主核 `launch_dependents` 放在尾循环之后、合并核在读部分和前等待，掩盖 `+1.31 / +1.34 µs` 的启动空隙（单请求全长解码省 **1.21 µs** 即 `+1.49%`，16/32 请求提速 `+0.44%–0.70%`；需注意 NCU 单核重放看不到跨核 PDL 重叠）。
    3. 在阶段 2 → 阶段 3 边界，让 `o` 投影作为 PDL 后继在 `wait` 之前用 `prefetch.global.L2` 预取前几阶权重分块（配合 `T = 16 / 32` 合并核入口触发），掩盖 `+1.12..+1.25 µs` 空隙，使单请求滑窗检验（`T = 8`）提速 **0.80%**（16 请求滑窗解码 `+0.61%`，32 请求全长解码 `+0.19%`）。在图 9-5 模式 2 中切换三档选项，读数分别为：`不开 PDL：交接段不重叠` / `作为对照基线`、`开 PDL，先等待再读权重：去掉切换空隙` / `P3 实测省 1.9–3.2 µs`、以及 `开 PDL，等待前预读权重：W2 读取与收尾重叠` / `P2 重叠 5–11 µs；P3 verify 1 请求滑窗再提速 0.80%`。
    4. **触发点位置的生死线（主循环后 / 函数末尾触发掩码 vs 入口触发慢 `14.3 µs`）**：PDL 的触发指令绝不能无脑放在前序核入口！在 `T = 128` 全长检验（16 请求）实测中，若在入口过早触发，后继核的 CTA 会立刻挤进 SM 抢占槽位与共享内存、与前序主核共驻互卡，导致整层中位耗时从 **`230.8 µs` 恶化到 `245.1 µs`（慢 `14.3 µs`）**！必须按边界掩码精确选择在主循环之后（用于 `T = 128` 的 `qkv_gate`、注意力与 `o` 投影）或函数末尾（用于 `T = 32` 的 `o` 投影）才触发，在 16 请求滑窗与全长检验上分别赢得 **`+1.06%` 与 `+0.34%`**。

- 决策三：小批量 **`T = 1 / 8 / 16` 借 `pooler` 空闲 68 个 SM 提前启动专家核**，以及**图捕获下的跨流竞态修复**（图 9-4 模式四与图 9-6 方式 2、方式 3）。
  - 在 `T = 1 / 8 / 16` 下，阶段 5 的 C12 `pooler` 只启动 `64` 个 CTA（占 64 个 SM），在整张 H200 上留下了 `132 - 64 =` **68 个空闲 SM**。整层方案把阶段 6 的小批量持久专家核（`132` 个 CTA）设为 `pooler` 的 PDL 后继，并在 `pooler` **入口**就触发依赖（因为此时本就是要借用那 68 个空闲 SM！）。专家核的 CTA 提前进场落在这 68 个空闲 SM 上，先跑完 `1.4 µs` 的路由预处理与 `1.8 µs` 的首轮权重 TMA 搬运（共隐藏 **3.2 µs** 起步开销），然后才调用 `griddepcontrol.wait` 等待 `pooler` 与 `top-8` 写完数据（对应图 9-4 模式四读数：`④提前启动的专家 kernel（decode，pooler 占 64 个 SM，空闲 68 个）` / `整层实测提速 1.46 %–1.96 % · 示意总长 36.0 格（不是 µs）`）。这使单请求滑窗/全长解码与单请求全长检验提速 **1.46%–1.96%**（若计入单请求滑窗检验 `+1.00%` 与 16 请求全长解码 `+0.77%`，五格提速区间为 `0.77%–1.96%`）。
  - 图捕获下的跨流读脏值竞态与 5 行修复（图 9-6 方式 2 vs 方式 3）：开启专家提前启动后，单次 eager 模式运行全部通过，但一进入 CUDA Graph 多轮重放（且每轮输入不同）就彻底算错，残差相对 L2 误差高达 **`0.7–1.09`**！原因在于：旁路流上的 `top-8` 内核在入口调用了触发函数；当跨流汇合边被捕获进 CUDA Graph 后，它变成了一条受编程依赖控制的边，`top-8` 入口的触发直接放行了主流上的专家核，导致专家核在 `top-8` 写出本轮结果之前就提前读到了**上一轮图重放留下的旧 `topk_ids`**（若每轮喂相同输入则完全隐形）。修复只需改动 `top-8` 核的 5 行代码：入口只执行 `wait` 绝不触发，直到出口写完 `topk_ids` 才触发完成边。修复后判官式 12 格全量重放 **`0 / 240` 次失败**，速度保持中性。在图 9-6 中切换方式 2 与方式 3，读数分别为：`早期专家 + top-8 入口触发：专家读到上一轮的 topk_ids` / `图模式重复运行失败：残差相对 L2 0.7–1.09；eager 全部通过`，以及 `早期专家 + top-8 出口触发：专家读到本轮的 topk_ids` / `判官式复现 0/240 次失败；T = 1 / 8 / 16 整层提速 1.46%–1.96%`。

- 决策四（核心边界定律）：**为什么“把已被 PDL 重叠的小核强行并入前序核尾”与“全层单一持久大核（Megakernel）”必输？**（图 9-5 模式 3）
  - 既然融合能省掉启动空隙（如第 3 节在 `T = 1` 折入 `pre_expert_norm`、在 `T = 3,012` 省掉 `49.3 MB` 往返），为什么不在整层把所有收尾小核全部并入前序大核尾部，甚至把阶段 1–8 合写成一个全层持久大核？实测给出了两条铁律：
    1. **PDL 重叠下的尾部融合反转定律**：当一个小核已经通过 PDL 嵌在前序大核最后一个波次的退场阴影里并行执行时，它的启动空隙早已被隐藏；此时若强行把它塞进前序大核的最后一个 CTA 或核内尾声，反而会把并行重叠变成**核内串行长尾**（且锁死高寄存器占用、推迟向下一阶段发 PDL 触发的时刻）！在解码与检验（`T = 1..256`）中先后实测过 **7 项此类尾部融合**（把注意力尾声、合并核、专家后归一化或延迟归一化塞进生产者核尾），**7 项全部亏损被拒**：例如在 32 请求滑窗检验（`T = 256`）中把尾声并入滑窗注意力最后一个 CTA 反慢 **`+6.75 µs`**（`0.9709×`），把 `pre_expert_norm` 并入 `T = 128 / 256` 尾声在 4 个检验格上全输 **`-0.5%..-1.0%`**，把专家后归一化并入小批量专家核尾在解码 1 / 16 / 32 与检验 1 请求上分别暴跌 **`+1.18 / +4.03 / +8.34 / +2.62 µs`**（核内每作业串行同步洗牌链耗时 `~2 µs`，吃穿了 `2.2–2.9 µs` 的删除上界）。同理，在预填充（`T = 3,012 / 16,384`）中尝试把专家后归一化加权和并入 `gemm2` 尾部使单核拉长 **`~145 µs` 与 `~340 µs`**（整层倒退 **`-1.97%`** 且 5 个种子中有 2 个精度越界），尝试把残差边界并入 `T = 16,384` 的 `pooler` 或 `o` 尾声也因 80 寄存器 GEMM 驻留过低而倒退 **`1.5%–6.8%`**。
    2. **全层持久大核（Megakernel）封顶定律**：当尝试跨越多阶段合写集群/协作大核（如将本地专家、升维投影与残差边界合为一核，或将 `qkv_gate` 与注意力合为一核）时，不仅每次跨阶段同步要付约 `1.4 µs` 的全网格栅栏代价（机制见第 1 章第 3 节），整核驻留还被最耗寄存器与共享内存的阶段锁死：把专家至层尾边界合写的大核在评测机上实测比 11 核 PDL 流水线**慢了整整 `1.05 ms`**（大纲记录的协作合写变体也比拆开慢 `5–8 µs`，见图 9-5 模式 3 读数：`合写大 kernel：全网格栅栏约 1.4 µs` / `P3、P5 合写被否决；大纲记 5–8 µs（形状 UNKNOWN）`，以及 `拆成两个 kernel，PDL 串联：没有栅栏` / `批量 16 与 32 解码净快 0.70–0.82 µs`）。微扰删除实验与计数器预算直接算清了天花板：在解码/检验整层上，全层持久大核有 **`+8.3 µs`** 的结构惩罚，而砍掉剩余核间空隙的理论上限仅 **`+1.9%`**（接近 `1.4%` 噪声带，真正的大头是核内波次失衡 `+5.5%` 与未覆盖的 PDL 边 `+2.3%`）；在预填充整层上，每算例核间总空隙仅 `3–5 µs`（在 `T = 753` 上全卡联合空闲仅占跨度的 `0.65%`），合写大核的理论收益上限仅有 **`≤ 0.05% / ≤ 0.16%`**，因此在两道整层赛题中均被第一性原理与实测双双否决。

### 单层总装演化阶梯小结（`layer_pipe`：`l0 → l3`）

把本章四节走过的单层总装路径串起来，从各自独立的单阶段算子到排行榜提交的全层流水线，共经历四步跃迁：

| 演化版本 | 本步合入的核心机制 | 解决的上一版瓶颈 | 实测单层收益与关键指标 |
|---|---|---|---|
| **`l0`（阶段 4 闭环）** | `T = 1` 移植 8-warp FP32 核；`T ≥ 8` 拆 `hi + lo` BF16 残差对上 Tensor Core；`T = 3,012` Swap-AB + `BT = 192` 缩为 128-CTA 单波次；`0..3` 号清零 CTA + 单调标志 + 辅助 warp 轮询；全 $T$ 单 warp `redux.sync` / 8-lane Top-8 | 消除阶段 4 的 FP32 算力枷锁、第 2 波次尾、`1.1 µs` 归约尾与 Top-8 的共享内存屏障 | `T = 1` 整层 `+1.01%–1.22%`；`T = 128 / 256` 路由器降至 `7.32 / 9.23 µs`（归约尾省 `0.88–1.72 µs`）；`T = 3,012` 路由器 `60.5 → 37.6 µs` 再省 **15.0 µs**；Top-8 压至 `3.65 µs`（`T = 256`）与 `23.6 µs`（`T = 16,384`） |
| **`l1`（阶段 1, 3, 5, 7 补完）** | `T = 8` 切片 `unpooler` 扩 128-CTA 8 路 Split-K C12；C12 逃逸末步预拼装 + 容量 `4 → 8` 回退梯；`T = 3,012` 滑窗 `qkv_gate` 两段 `K` 锁步（`82 + 46`）；`T = 16,384` Stream-K 与编译期 `constexpr` 列切窄 | 填满小批量切片 `unpooler` 的空闲 SM，防止判官随机权重逃逸爆表，抹平大批量持久网格 `28–85 µs` 的末波空闲 | `T = 8` 整层 `+1.29%–1.42%`（`109.0 → 106.8 µs`）；`T = 32` `qkv` 回退保住 `15.3 µs`；`T = 3,012` 滑窗 `qkv` 结束差 `29.4 → 7.4 µs`（省 **8.7 µs**）；`T = 16,384` `qkv / pooler / unpooler` 分别省 **13 / 28 / 15.8–20.3 µs** |
| **`l2`（跨阶段代数折入与边界核）** | 利用矩阵乘对行缩放的线性齐次性，将 `pre_expert_norm` 拆入 `pooler` 尾声（`xb_gain + rs_part`）与专家入口/尾声（乘 `r_m`）；阶段 3/8 集群边界改 `st.async + mbarrier`（独立缓冲区）并按 $T$ 调优 64 寄存器 / 512 线程 | 砍掉阶段 5 与阶段 6 之间独立的归一化启动及 `49.3 MB` 显存往返，清零集群边界核的 `MEMBAR.ALL.GPU` | `T = 1` 启动 `12 → 11` 次、省 **0.82–1.47 µs**；`T = 3,012` 省掉约 **14 µs** 独立核与 **48.96 MB** 净流量（合入 **+0.60% / +1.35%**）；集群边界核每次省 **0.86–0.99 µs**（整层 `+0.46%`） |
| **`l3`（全层双流与 11 核 PDL 总装）** | 分叉点按 SM 余量动态选路（`T = 753` 旁路借 36 SM、`T = 128` 合核省 `3 µs`、`T = 16,384` 主流先跑 `router`）；阶段 1–8 同流 PDL 串联配主循环后/末尾触发掩码；`T = 1/8/16` 借 `pooler` 空闲 68 SM 提前跑专家 `3.2 µs` 并修复 `top-8` 出口触发；拒绝尾部强融与全层持久大核 | 消除约 17 核单流顺序的 `~16.4 µs` 边界空隙与分叉等待，同时避开入口触发共驻（慢 `14.3 µs`）、尾部强融（慢 `6.75–340 µs`）与全层大核（慢 `1.05 ms`）陷阱 | 单层收敛为 **11 个 kernel**；`T = 128` 同流 PDL 省 **1.9–3.2 µs**、合核省 **3 µs**；`T = 1/8/16` 提前专家提速 **1.46%–1.96%**（`0/240` 零竞态）；`T = 753` 旁路流提速 **3.18%–3.33%** |

---

**带走一句话：** 单层阶段 1–8 的总装绝不是把所有阶段硬塞进一个持久大核（实测反慢 `1.05 ms`，核间空隙上限仅 `0.05%–1.9%`），而是顺着各阶段在当前 $T$ 区间的 SM 余量与代数性质做拼接：阶段 4 用 `hi + lo` 残差对与 `BT = 192` 单波次保住 FP32 精度，阶段 1/5/7 用两段 `K` 锁步与 Stream-K 抹平持久尾波，阶段 5 → 6 利用矩阵乘行线性性质消掉独立归一化与 `48.96 MB` 净流量，最后用主循环后触发的 11 核同流 PDL、旁路流与空闲 SM 专家抢跑把整层焊成无缝流水线。
