# 第 8 章 [第二部分 · 阶段 6] 路由 NVFP4 混合专家：从 2.27 秒到约 6 毫秒（m0 → m5）

**本书地图：** 第 0.0 章 → 第 0 章 → 第 0.5 章 → 第 1–6 章 [第一部分：第 0–5 级机制轴] → 第 7 章 [第二部分 · 阶段 2：分页注意力] → **【第 8 章：第二部分 · 阶段 6 路由 NVFP4 混合专家】** → 第 9 章 [第二部分 · 阶段 1–8 整层总装] → 第 10 章 [性能诊断法]

注意力阶段交出 `o_attn [T, 1024]` 后，数据流经阶段 3 的输出投影与第一道门控残差，在阶段 4（路由打分与 Top-8 选择）和阶段 5（降维投影 `pooler`，从 `8,192` 维压到 `4,096` 维）处分成两路并行计算，最后汇入单层权重体积最大的阶段 6——32 个本地路由混合专家（MoE）。

同样是这 32 个本地专家，为什么整批输入词元总数 `T` 从单词解码（`T = 1`）涨到大块预填充（`T = 16,384`），内核结构非要历经五代演化（`m0 → m1 → m2 → m3 → m4 → m5`）？**原因很直接：每个本地专家都要单独做一次矩阵乘，而这个专家矩阵乘的行数 `M`——也就是分到这一个专家的词元数——决定了它被什么硬件瓶颈卡住。**

在看五代内核怎么演进之前，先交代两件事：阶段 6 的五步计算契约，以及 **`M = 58` 个词元**这条算力分界线。

在 62 层整网里，首尾的第 0 层和第 61 层专家保持 `BF16`；中间 **60 层**（第 1 至 60 层）采用 4 位浮点格式 `NVFP4`。在 8 卡专家并行（EP8）下，每张 H200 驻留 32 个本地专家，权重共占 **`906 MB`**（单专家 `28.3 MB`，见第 0 章；真实 8 卡部署还需等待最慢一张卡并做跨卡规约，单卡评测将其设为恒等映射，只测单卡耗时）。下文追踪 `m0 → m4` 的整体进展时，统一用 6 个解码与检验算例乘上 **60 层**后的几何平均总耗时（SGLang 基线为 `13,448.5 µs`）；剖析具体内核机制时，则统一用**单层**耗时（`µs`）。

在 H200 上，硬件没有原生 4 位矩阵乘指令，因此专家输入激活 `p [T, 4096]` 保持 `BF16`，4 位权重读进片上后先解码成 `BF16` 再做矩阵乘。每个权重由三层系数相乘还原：`0.5 B` 的 4 位 `E2M1` 码值、每 16 个权重共用的 `1 B` `FP8 E4M3` 块缩放（折合每权重 `0.5625 B`），以及每个专家 1 个 `FP32` 全局缩放。每个词元 `tok` 会选出 8 个专家槽位 `slot`（`0..7`）；对每一个落在本卡专家 `e` 上的 `(tok, slot, e)` 命中对，依次执行五步：
1. **门控与上投影融合矩阵乘**：`[h_gate | h_up] = p[tok] @ dequant(W13[e]).T`，维度从 `4,096` 扩到 `8,192`（前 `4,096` 列是门控 `h_gate`，后 `4,096` 列是上投影 `h_up`）。
2. **门控激活（SwiGLU）**：`inter = silu(h_gate) * h_up`，维度回到 `[4096]`。
3. **下投影矩阵乘**：`y = inter @ dequant(W2[e]).T`（`[4096] → [4096]`）。
4. **每专家独立后归一化**：`y_norm = rmsnorm(y * (1 + w_post_expert))`。
5. **按路由权重加权累加**：`m[tok] += topk_weights[tok, slot] * y_norm`（路由权重已在阶段 4 归一化为和等于 1；未命中本卡专家的词元输出全 0），写出 `m [T, 4096]` 交给阶段 7 升维投影。

这里有一个关键的代数性质：**为什么门控与上投影的两个全局缩放可以合并成一个？** 在原始模型检查点里，上投影 `W13` 的门控半边（`w1`）和上投影半边（`w3`）各有一份独立的 `FP32` 全局缩放（`w1_scale_2` 与 `w3_scale_2`，合起来形状为 `[32, 2]`），而下投影 `W2` 另有自己的全局缩放（形状 `[32]`）。H200 基线调用的 Marlin W4A16（4 位权重、16 位激活混合精度矩阵乘）内核在 `W13` 上每个专家只接收一个全局缩放标量，于是直接让门控和上投影两半共用 `w1_scale_2`（下投影 `W2` 仍保留各自的缩放）。因为 `SwiGLU(g, u) = silu(g) * u` 对上投影 `u` 是线性的，把 `u` 的缩放从 `w3_scale_2` 换成 `w1_scale_2`，会让该专家的下投影输出 `y` 整体多乘一个正常数增益 `1 / r`（`r = w3_scale_2 / w1_scale_2`）。**正因为模型第 4 步本来就在每个专家输出后紧跟一道 `RMSNorm`**，而 `RMSNorm` 会除以向量自身的均方根、把任何正数常数倍数在分子分母里同时约掉（`rmsnorm(y / r) = rmsnorm(y)`），多出来的 `1 / r` 增益刚好在跨专家加权求和之前被完全抵消。因此本章的专家内核在 `W13` 上也同样只存一个全局缩放标量 `[32]`。

再看 **`M = 58` 个词元**这条分界线。第 0 章算过，每处理一对 `(tok, e)`，每个权重做 1 次乘加（`2 FLOP`），算术强度只有 `2 ÷ 0.5625 = 3.56 FLOP/B`；要跨过 H200 的 `206 FLOP/B` 平衡点，**分到同一个本地专家的词元数（即专家 GEMM 的行数 `M`）至少要达到 `206 ÷ 3.56 ≈ 58`**。每个词元选哪 8 个专家随输入内容而变（单算子测试用多组随机种子生成不同路由分布）：词元平摊到各专家叫**均匀路由**，扎堆命中少数热门专家叫**偏斜路由**。这条 `M = 58` 的分界线把阶段 6 切成了两个区间：
- **解码（`T = 1, 16, 32`，每请求 1 词）与投机检验（`T = 8, 128, 256`，每请求 8 词）**：哪怕到了 `T = 256` 的偏斜路由，最忙卡上的 `390` 个本地命中对分散在约 `24.6` 个激活专家上，平均每个激活专家分到的行数也只有 **`M ≈ 16`**。因为 `16 < 58`，前四代内核（`m0 → m4`）始终受限于 HBM 读权重带宽、波次尾和同步延迟。
- **预填充（`T = 753, 3,012, 16,384`）**：每个词元选 8 个专家，而本卡只放全网 256 个专家里的 `1/8`（32 个），两个 `8` 相消后，均匀路由下每个本地专家平均分到的词元数是 `M = 8T ÷ 256 = T ÷ 32`——从 `T = 753` 的 **`M ≈ 24`**（过渡区），涨到 `T = 3,012` 的 **`M ≈ 94`** 和 `T = 16,384` 的 **`M = 512`**。跨过 `M = 58` 之后，把 32 个专家全部 `906 MB` 权重从 HBM 读一遍的时间下界只有 `188.7 µs`，而 `T = 16,384` 的矩阵计算时间下界高达 **`1,668 µs`**，第五代内核（`m5`）的瓶颈也随之转向 Tensor Core 与指令管线。


## 1. m0 → m1 → m2：把反量化留在片上，再让分块流水与尾块裁剪贴合专家行数

为什么第 0 代参考实现（`m0`）跑完 60 层的几何平均总耗时高达 `2,270,104.65 µs`（2.27 秒，单层约 `37.8 ms`）？因为它在 Python 循环里逐个专家串行启动内核，而且每命中一个专家，都要把 `28.3 MB` 的 4 位权重先解压成 `100.7 MB` 的 `BF16` 稠密矩阵写回 HBM，再启动矩阵乘从 HBM 读回来算。

单看显存搬运，一个专家只有 `28.3 MB` 有用权重，却因为中间写回 `100.7 MB` 再读回 `100.7 MB`，实际搬运了 `28.3 + 100.7 + 100.7 = 229.7 MB` 数据（32 个专家合 `7.35 GB`，按 `4.8 TB/s` 带宽至少要 `1.5 ms`）；再加上 Python 逐专家循环里数十次独立内核启动与主机端同步开销（占去其余约 `36 ms`，具体拆分未测），单层耗时就被拖到了几十毫秒。

第一代跃迁（`m0 → m1`）先把逐专家循环合成为**一次启动的分组专家矩阵乘（Grouped Expert GEMM），并且把 4 位反量化留在片上寄存器里完成**。程序先把命中同一个本地专家的词元分桶排好，再单次启动分组矩阵乘网格；每个专家的 4 位码字与块缩放从 HBM 读进片上后，直接在寄存器里还原成 `BF16` 送入矩阵乘管线，全程不再往 HBM 写回任何解压权重。光这一步，60 层几何平均就从 `2,270,104.65 µs` 降了 `79.5` 倍，压到 **`28,554.36 µs`**。接着把门控与上投影按 `32 + 32` 行交错排布（让同一输出行的门控和上投影落在同一个分块里），再配上无分支位运算解码与早期依赖启动（PDL，见第 1 章第 2 节与第 6 章第 3 节），60 层几何平均又快了 `1.34` 倍，降到 **`21,369.20 µs`**（相对 `m0` 累计快 `106` 倍，共省下 **`2,248.7 ms`**）。代价是矩阵乘前要维护固定形状的词元-专家分桶索引表，并固定离线权重排布；它在全部 6 个算例上都稳赢。

进入第二代跃迁（`m1 → m2`），内核先把矩阵乘主循环切到了**寄存器源 `wgmma`（register-sourced `wgmma`）分块流水架构**。第 5 章讲过，Hopper 的异步矩阵乘指令 `wgmma` 允许左操作数（A 矩阵）直接取自寄存器而不必经过共享内存；把 4 位权重放在左操作数位置，在寄存器里解码成 `BF16` 后当场送入 `wgmma`，单这一步架构切换就把 60 层几何平均从 `21,369.20 µs` 压到了 **`18,057.2 µs`**。

接着按第一部分的机制补齐小批量并行度与访存流水：
1. **下投影 `Split-K` 填满空闲 SM**：下投影 `W2` 的输出列数（`4,096`）比上投影（`8,192`）少一半，在总词数 `T ≤ 32` 时分块数填不满 132 个 SM。按第 2 章第 1 节对 `T ≤ 32` 的下投影开启 `Split-K`（`T ≤ 8` 切 4 份、`T ≤ 32` 切 2 份），把部分和平面存成 `BF16` 交给后归一化核顺带归约，60 层几何平均从 `18,057.2 µs` 降到 **`17,362.60 µs`**。
2. **共享内存权重环藏住 HBM 延迟**：换上寄存器成对无损 FP4 解码，并按第 3 章第 4 节在 `T = 16, 32` 上给权重挂上 3 槽 `cp.async` 环形缓冲（单层分别省 `5.25 µs` 与 `5.70 µs`），60 层几何平均从 `17,362.60 µs` 一举降到 **`7,944.29 µs`**。随后把 3 槽环推广到 `T = 8`（单层省 `8.45 µs`，60 层降至 **`7,830.27 µs`**），再加上环槽进位（降至 **`7,786.40 µs`**）、`T = 128, 256` 的 2 槽纯权重环（单层分别省 `4.64 µs` 与 `18.94 µs`）、解码左移分流、小批量有界持久网格与块缩放合并拷贝（见第 3 章第 2 节与第 5 章第 1 节），把 60 层几何平均进一步推到 **`7,374.90 µs`**。

在调环形缓冲深度和寄存器数时，遇到了一个 MoE 特有的**波次台阶效应**（见第 2 章第 1 节的波次量化）：为什么同一个驻留改动，换一组路由分布就会一正一负反转？在稠密矩阵乘里，矩阵形状固定，总 CTA 数不变。但在 MoE 里，**每组路由命中的本地活跃专家数 `A` 不同，全卡总块数 `A × 每专家 CTA 数 c` 跟着路由浮动**。设每个 SM 同时驻留 `k` 个 CTA，单波容量就是 `132 × k`，总耗时约为 `⌈(A × c) ÷ (132 × k)⌉ × 单波耗时(k)`。当某项改动把每 SM 驻留从 `k` 提到 `k + 1` 时，只有当某组路由的总块数刚好从 **2 个波次跨进 1 个波次**（跨过 `132 × (k + 1)` 的台阶）时，这组路由才会明显变快；而在没跨过波次台阶的路由上，更浅的缓冲或更高的同 SM 争抢反而让内核变慢。

两个实测例子就能看清这条规律。在 `T = 32` 的下投影里，每个活跃专家启动 `c = 64` 个 CTA：把每 SM 驻留从 7 提到 9 个 CTA 后，5 组路由里跨过波次台阶的 2 组分别**快了 `7.12 µs` 与 `11.87 µs`**，没跨台阶的 3 组反而**慢了 `3.41`、`5.71` 与 `6.83 µs`**。反过来，在 `T = 8` 上把 `mma.sync` 换成 `wgmma`（每专家 `c = 128` 个 CTA，见第 5 章第 3 节），会让每 SM 驻留从 `9` 掉到 `8` 个 CTA，单波容量从 `1,188` 缩到 `1,056`；结果 `A = 9`（总块数 `9 × 128 = 1,152`）的两组路由刚好从 1 波掉进 2 波，分别**慢了 `10.43 µs` 与 `11.41 µs`**。因此 MoE 的每一项驻留改动都必须在多组路由分布下同时检验：在 `T = 1` 和 `T = 16` 下开启纯权重环时，用 `__launch_bounds__` 把每 SM 驻留分别钉在 `6` 个和 `7` 个 CTA（`T = 16` 不钉住会慢 `2.13 µs`，钉住则省 `1.78 µs`；`T = 1` 开 3 槽环在 1 波内因每 CTA 环开销推测反慢 `4.18 µs`，改用钉住 6 CTA 的 2 槽环才净省 `0.56 µs`）。反过来，如果用 `__maxnreg__(56)` 硬压寄存器上限引发 8 个寄存器溢出，在 `T = 256` 上会直接**慢 `61.79 µs`**（见第 3 章第 1 节）。

钉住驻留之后，第二代（`m2`）还剩下一项明显的浪费：**轻专家尾块里的空白填充行**。分桶路由要求同一个分块里的词元属于同一个专家，因此每个专家分到的词元数 `M` 都得向上补齐到分块高度 `BM`（如 `32` 行或 `128` 行）的整数倍。在偏斜路由下，大量轻专家只分到寥寥几个词元，重专家的最后一个尾块也往往只剩几行有效数据，底下大半截全是空白填充行（padding）。如果不做处理，`wgmma` 仍会按满块高度空转矩阵周期。

`m2` 用**尾块裁剪（ragged tail trimming）**砍掉了这部分空转：在分块入口检查当前专家块的实际有效行数 `r_valid`，对不满一块的尾块按 `BM 32 → 16 → 8` 三级台阶动态下调 `wgmma` 行数；在预填充 `T = 753..16,384` 中，同样用一次标量加载检测从第 `r_valid` 行起是否全为填充，直接跳进窄行矩阵乘分支（图 8-1 中间）。
- **收益**：在单层 `T = 256` 上，上投影加上 `BM = 16` 裁剪单项就省了 **`25.68 µs`**，推广到下投影在 `T = 128 / 256` 再省 `8.08 / 7.12 µs`，在 `T = 128` 启用 `BM = 8` 第三级裁剪又省 `6.37 µs`；配合 `T = 1` 的核内路由与归约，把 60 层几何平均从 `7,374.90 µs` 压到 **`6,928.62 µs`**。到了预填充 `T = 753 / 3,012 / 16,384`，尾块裁剪把每个有效词元对平均发射的 MMA 行数从 `1.68 / 1.27 / 1.06` 压到 **`1.18 / 1.08 / 1.02`**，整层分别提速 **`4.94% / 4.32% / 0.99%`**。
- **代价与边界**：核内要生成多套窄分块分支并在入口检查有效行数。在预填充里，必须用标量加载配合统一分支，才能把环槽计数留在统一寄存器 `UR`（见第 7 章第 4 节）里；如果改用块内归约统计有效行数，环槽算术退回普通向量寄存器，每步 `K` 会多出 **34 条指令**。同时，基础分块高度 `BM` 必须跟每专家平均词元数 `M` 匹配：例如在预填充过渡区 `T = 753`（每专家平均 `M ≈ 24`）下若盲目扩到双消费者 warpgroup 的 `BM = 128`，24 个词元远填不满 128 行，填充浪费会让整层反而**慢 `1.39%`**（而选 `BM = 64` 配 TMA 权重环则能提速 `3.87%`，见第 5 节）。

最后，再加上 `T = 32` 的 `BM = 16 wgmma`（单层省 `2.02 µs`，见第 5 章第 3 节）、后归一化流水加载（省 `0.75 µs`）、`T = 1` 按活跃专家数自适应选择 `Split-K`（省 `2.05 µs`）以及每环步消费 `2 × BK = 256` 列（在 `T = 32` 上下投影分别省 `3.20 µs` 与 `5.84 µs`，在 `T = 128 / 256` 省 `2.13 µs`），第二代（`m2`）的 60 层几何平均从 `6,928.62 µs` 最终落到 **`6,718.85 µs`**，达到 SGLang 基线（`13,448.5 µs`）的 **`2.0016×`**。

为什么第二代分块流水核（`m2`）在总词数 `T = 1..32` 的单层耗时上，还是会多花 `10–20 µs`？原因在于 `T ≥ 8` 时，`m2` 把路由分桶、上投影 `W13`、下投影 `W2` 和后归一化拆成了 **4 次独立的内核启动**（`T = 1` 把路由合进矩阵乘也要 3 次启动）。每次启动都要重走一轮波次尾，中间激活还在 HBM 与 L2 之间来回读写。

要消掉多轮启动的波次尾巴，靠的是**持久核（persistent kernel）**：只启动固定数量（不超过全卡 132 个 SM）的 CTA 常驻在芯片上，每个 CTA 算完手头一块活后不退场，而是继续去队列里领下一块活，直到所有分块算完。在 `T = 1` 和 `T = 8` 下，可以先用少于 SM 数的有界持久网格省掉空 CTA 的启动与退出尾巴（单层分别省 `1.22 µs` 与 `7.60 µs`），并在 `T = 1` 下删掉独立路由核、改用最后到达者原语在核内归约（见第 1 章第 1 节）。但到了 `T = 8..32`，多核之间的折返依然省不掉。

第三代跃迁（`m2 → m3`）的做法是：**先把前 3 步——核内路由（路由阶段）、上投影加 SwiGLU（上投影阶段）和下投影（下投影阶段）——收进一个常驻 132 个 CTA 的权重驻留持久核，算完每对 `(tok, e)` 的下投影输出 `y`；随后在 `T = 8..32` 上，又把上下投影拆回两个用 PDL 首尾相接的常驻核，因为核中间那道全网格栅栏比拆核还贵。** 紧跟在后面的**后归一化核**同样通过 PDL 首尾相接（单层省 `0.31–0.93 µs`，见第 1 章第 2 节），读回 `y`（跳过非本地专家槽位）完成第 4 步每专家 `RMSNorm` 与第 5 步加权求和，写出最终输出 `m`（若强行把已被 PDL 重叠的后归一化核融进主核尾部，反而会因为破坏主核驻留与尾波而**慢 `1.18–8.34 µs`**）。围绕这套小批量常驻核，`m3` 依次解决了三个问题：

第一个问题是**怎么把多核折返压进常驻核，又不在核内全网格栅栏上空等**。
- 在 `T = 8` 上，单次启动的 132-CTA 常驻核用 TMA 环形缓冲流式搬运权重单元，在核内一气算完路由和上下投影，单层耗时直接省下 **`15.73 µs`**，把 60 层几何平均从 `m2` 末尾的 `6,718.85 µs`（`2.0016×`）压到 **`6,448.80 µs`**（相对 SGLang 基线升至 **`2.0854×`**）。
- 当词数扩到 `T = 16, 32` 时，分到超过 8 个词元的热门专家（`M > 8`）被切成每轮处理 **8 个词元的虚拟轮（8-pair virtual pass）**，配合 8-warp 尾声轮转与 8-warp `__ballot_sync + __popc` 位图并行路由（替代 256 步串行扫描，见第 4 章第 4 节）。在 `M ≤ 8` 单轮快路径先省 `13.71 µs` 的基础上，这一步在单层 `T = 16` 和 `T = 32` 上分别省下 **`20.29 µs` 与 `7.70 µs`**，把 60 层几何平均进一步从 `6,448.80 µs` 压到 **`6,123.21 µs`**（相对 SGLang 基线达 **`2.1963×`**）。它的代价是热门专家每多跑一轮虚拟轮都要重读一次权重：如果在 `T = 16, 32` 上把单轮粒度无条件扩成 16 个词元（双倍虚拟轮），单步指令数会涨 `16%` 并在活跃专家多的路由下拖出长尾，单层反而**慢 `1.71 µs` 与 `2.54 µs`**；而到了 `T ≥ 128`，热门专家重读权重过多，就必须换用第 3 节的大分块内核。
- 合进单核之后，上投影阶段和下投影阶段之间原本立着一道耗时 `1.42 µs`（`1,419 ns`）的全网格同步栅栏（`grid.sync()`）。按第 1 章第 3 节的做法，在 `T = 8, 16, 32` 下把上下投影拆回两个 PDL 串联核：下投影核在等待上投影核收尾的空档里提前把权重环预载进共享内存，单层又净省 **`0.37 / 0.70 / 0.82 µs`**（`T = 1` 没有尾波失衡，拆核无益，保持单核即可）。同时给权重流标上 `evict_first` 提示以防冲刷 L2 里的激活（在 `T = 1` 下去掉该提示会**慢 `2.44 µs`**，见第 2 章第 3 节）。此外，在 `T = 1` 且活跃专家数不超过 3 时，按 `blockIdx.x + 132 j` 轮转派发上投影单元让 132 个并发 TMA 请求在显存地址上紧挨着，单层再省 **`0.66 µs`**（若把权重环加深到 4–6 槽则会**慢 `0.59–1.30 µs`**）；在 `T = 16, 32` 拆核后，硬件按 `blockIdx.x` 顺序派发下投影块，最后进场的 `131` 号块比前序块晚启动约 `2 µs`，对 `100..131` 号块按二次曲线少分一点下投影单元又省下 **`0.27 / 0.31 µs`**（见第 2 章第 2 节；若在不含双倍虚拟轮的路由上无门控开启，则会因前序块过载而**慢 `0.42 / 0.49 µs`**）。

第二个问题是**内核刚启动时，为什么读取几千字节的激活 `x` 会堵在队列里干等 `0.96 µs`？**
在路由阶段，各线程先把上下投影的 64 个全局缩放系数（占 `256 B`）预载进共享内存，使每个子任务尾声的缩放查询从 `328` 周期的 L2 命中压到 `23` 周期的共享内存读取 `LDS`（在 `T = 128 / 256` 单层省 `0.47 / 0.55 µs`）；同时按第 3 章第 5 节的做法，把共享内存路由计数表的行宽从 32 或 64 字填充成 **33 字**奇数行宽（图 8-2，表体积只多占 `128 B`）错开 32 路 bank 冲突，并只读一次 `topk_ids`。

但查看 `T = 1` 下的入口时间戳发现，普通全局加载（`LDG`）和硬件 TMA 走的是同一个 DRAM/L2 请求队列。如果在序言里先一口气连发 3 槽权重 TMA，全卡 132 个 SM 瞬间往显存队列里塞进约 `14 MB` 的权重请求；紧跟着发出的激活 `x` 读取，就会排在这批权重请求后面干等 **`0.96 µs`**（因多通道并发交错，实测排队为 `0.96 µs`）。看清队列拥堵之后，解法就是把启动顺序反过来：**先发出激活 `x` 的 `LDG` 和第 0 槽权重 TMA，再用 GPU 硬件纳秒计时器把第 1、2 槽权重 TMA 推迟 `500–600 ns`（约一趟激活加载往返的时间）错峰发出**，最后用 `__maxnreg__(144)` 卡住 `T = 1` 主核的寄存器上限，腾出空间让占 110 个寄存器的后归一化 CTA 同 SM 共驻、提前进场。在 `T = 1` 上，这套启动解耦单层实测省下 **`1.06 µs`**（逐项叠加依次为：全局缩放表预载省 `0.41 µs`，加 `x` 先发累计省 `0.71 µs`，加 `500 ns` 错峰累计省 `1.05 µs`，共驻再省 `0.08 µs`）；在 `T = 8` 拆分核上省 **`0.76–0.82 µs`**，在 `T = 16 / 32` 省 `0.40 / 0.48 µs`。当然，开环错峰延迟不能拉得太长：在 `T = 8` 上推迟 `600–800 ns` 能省 `0.76–0.84 µs`，一旦拉长到 **`1,200 ns`**，就会因人为推迟权重供应而退回到只省 `0.43 µs`；到了 `T = 32`，错峰收益已落入测量波动范围，直接设为 `0 ns`。

第三个问题是**后归一化核里的两处 `ptxas` 编译器退化（图 8-3，原理见第 6 章第 1 节）**。后归一化核对输入做 2 组 × 4 路流水加载（省 `0.75 µs`；若改成宽幅无分支加载使每线程寄存器从 `64` 涨到 `128+` 掉驻留，反而会**慢 `0.43–0.90 µs`**），拆开它的 SASS 反汇编后修复了两处退化：
- 第一处是**预取加载被下沉到等待之后**。序言里原本写在 `ACQBULK`（即 `griddepcontrol.wait`，等待前序网格写操作全部完成并可见）之前的 6 条 16 字节只读缓存预取加载——读取 `w_post_expert`（2 条）、`topk_weights`（2 条）与 `topk_ids`（2 条）——被 `ptxas` 移到了 `ACQBULK` 后面（编译器将加载下沉到获取等待之后并不违背内存模型，但会让 PDL 预读失效）。**把这 6 条加载放在 `griddepcontrol.wait` 之前之所以安全，前提是在单算子测试里这三份输入都不是前序专家核写出的**（而在第 9 章的整层流水线里，`topk_ids` 与 `topk_weights` 由前序路由核写出，在等待前读取就会读到上一轮的旧值，那里只能预读静态权重 `w_post_expert`）。改用 `asm volatile` 普通全局加载后，在当前编译器（NVRTC 13.0 / `sm_90a`）下实测观察到能把这 6 条 `LDG.E.128` 留在 `ACQBULK` 之前（规范并不保证编译器不重排，换编译器版本后必须重新核对 SASS），在 `T = 1 / 16 / 32 / 8` 上分别省下 **`0.45 / 0.67 / 0.41 / 0.27 µs`**。它的代价是放弃了只读缓存提示，且只适用于 `T ≤ 32`；到了 **`T > 32`**（如 `T = 128`），前序常驻专家核占满全部 132 个 SM，后归一化核在等待前没有重叠窗口，开启 `volatile` 预取反而会**慢 `0.45 µs`**。
- 第二处是**循环外常量被重新计算（rematerialization：编译器为省寄存器把算好的值丢掉、用时再算）**。循环外预先算好的 16 个 `nw[i] = 1.0f + w_post_expert[i]`，被 `ptxas` 拆回内层循环里反复重算，多出 `321` 条 `FADD`。加一行空内联汇编 `asm volatile("" : "+f"(nw[i]));` 逼编译器把这 16 个值留在寄存器里（占 16 个 FP32 寄存器即 `64 B`），静态 SASS 指令数从 `1,603` 条降到 **`1,120` 条**，在 `T = 1 / 16 / 32` 上再省 **`0.21–0.30 µs`**。

这套组合拳下来，第三代（`m3`）把 `T = 1 / 8 / 16 / 32` 的单层耗时分别压到了 **`28.6 / 58.8 / 76.6 / 109.9 µs`**，6 个算例的 60 层几何平均总耗时从 `6,718.85 µs` 降至 **`6,123.21 µs`**（相对 SGLang 基线达 **`2.1963×`**）。

## 3. m3 → m4（上）：大批量检验（T = 128..256）下，让 132 个常驻 CTA 同时收尾

<!-- FIG ch08-m4a-wgs: 图 8-4 画阶段 6 第四代常驻 wgmma 作业队列与全卡尾波均衡数据流：上方展示 4 个消费者 warpgroup（512 线程，每线程 96 寄存器）与 2 个生产者 warp 从全局作业队列拉取 64 × 256 × 256 子任务（取代 4 核分块方案省 22.54 µs）；中间对比按填充后词元数降序的 LPT 排列（省 1.40–2.32 µs）与 T=128 生产者原子动态领活（消除 108 个 CTA 跑 6 活、24 个 CTA 跑 5 活的静态失衡，提速 1.67%）；下方画按上投影负载秩逆序分配下投影（最轻上投影配最重下投影，削平 9–52 µs 长尾，将全卡最晚退出时间从 189.4 / 215.0 µs 压至 176.3 / 195.0 µs）。 -->

为什么第三代小批量常驻核（`m3`）在 `T ≤ 32` 下表现很好，到了大批量投机检验（`T = 128, 256`）却跑不过分块大核？**因为词元数涨上来以后，热门专家分到的词元数 `M` 达到几十个，继续按 8 个词元一轮切分会让同一个热门专家的 `28.3 MB` 权重被反复重读。** 可要是退回第二代（`m2`）的 4 核分块方案，4 次独立启动之间的 L2 折返和波次尾又会多花二十多微秒；而且当热门专家的 `M` 涨到几十行时，单 warp 的 `mma.sync` 已经喂不饱矩阵管线，必须换回 4 个 warp 协同的寄存器源 `wgmma`。

第四代（`m4`）的做法是：**在 `T = 128..256` 下合成为单次启动的常驻寄存器源 `wgmma` 核，让 132 个常驻 CTA 围绕同一条全局子任务队列，在同一次启动里连续跑完核内 33 字直方图路由、上投影加 SwiGLU（`64 × 256 × 256` 分块）和下投影，再用四项跨 SM 均衡手段把轻重专家混杂拖出来的长尾削平。**

先看常驻 `wgmma` 核的内部编制。每个常驻 CTA 初版配 18 个 warp（`576` 个线程）：4 个消费者 warpgroup（共 512 个线程）并发跑 `BM = 64, BN = 256` 的寄存器源 `wgmma`，外加 2 个专职生产者 warp（第 16 号权重生产 warp 负责 TMA 权重环，第 17 号激活收集 warp 负责 `cp.async` 激活收集）。第 3 章的 2 消费者 warpgroup 配法可以给每个消费者线程分 232 个寄存器，但这里有 4 个消费者 warpgroup，如果还按 232 个配，光消费者就要 `4 × 128 × 232 = 118,784` 个寄存器，远超单 SM `65,536` 个寄存器的硬件上限；按 `65,536 ÷ 576 ≈ 113` 留出余量，每线程寄存器上限统一卡在 **`96` 个**（`576 × 96 = 55,296 ≤ 65,536`，见第 3 章第 1 节）。热门专家的最多 64 个词元一次装进同一个 `64 × 256` 分块，权重只从 HBM 读 1 遍，中间激活 `h` 留在 L2 与全局平面里直接交给下投影阶段消费。在单层 `T = 256` 上，单次启动的常驻 `wgmma` 核比 4 核分块方案配对实测省下 **`22.54 µs`**。不过这套 256 列宽块不能直接照搬到 `T = 128`：在 `T = 128` 下，22 个子任务乘 16 个分块一共 `352` 个块，在 132 个 SM 上折合 **`2.66` 个波次**，多出来的约 `18 µs` 分数波次尾会把单块收益抵消掉；如果在下投影每阶段再加轮询栅栏，更会**慢 `5.8–9.0 µs`**。

把所有工作装进 132 个常驻 CTA 之后，整核的耗时完全取决于 **132 个 CTA 里最晚退出的那 1 个 CTA**。开启第 1 节的尾块裁剪后，一个满载 `64` 行的重子任务和一个只有 `8` 行的轻尾块（单活耗时约 `17.15 µs`）执行时间差出一大截。怎么防止某个 SM 在最后时刻撞上大活、拖慢全卡？`m4` 从四个方向把 132 个 SM 的退出时间拉齐：

第一项是 **LPT（最长处理时间优先）降序排列**。把全局队列里的所有子任务按填充后词元数从大到小排好，让满块重活先上，把 `8` 行的短尾块留在最后去填补各 SM 的末尾空隙（排序后全卡最早和最晚收尾的 CTA 只差 `15.84 µs`）。在单层 `T = 128 / 256` 上，这比不按大小排序省下 **`1.40 µs` 与 `2.32 µs`**；在预填充 `T = 753` 上把满块排在前面、短尾块排在后面，整层同样提速 **`1.33%`**。代价是维护一张全局排序映射表；到了 32 个专家几乎全是满块的 `T = 3,012 / 16,384`，没有短尾块可填，收益也就归零。

第二项是 **`T = 128` 生产者原子动态领活**。在 `T = 128` 下，如果按固定步长静态分活，会有 `108` 个 CTA 分到 `6` 个子任务，剩下 `24` 个 CTA 只分到 `5` 个子任务，导致这 24 个 SM 在最后约 `17 µs` 里空转干等。改由每个 CTA 的权重生产 warp 在跑当前子任务时，用一次原子加（`atomicAdd`）按 LPT 顺序去全局队列里动态领下一个活，使 `T = 128` 滑窗与全长整层分别提速 **`1.67%` 与 `0.65%`**。这和第 7 章第 2 节注意力的结论正好相反：注意力单个分块只有约 `1–2 µs`，且每次领活都要在 CTA 内同步广播，动态认领反而亏本（见第 7 章第 2 节）；而这里单个专家子任务长达约 `17 µs`，生产者领到活后直接顺着原有的环形缓冲往下传、不加新屏障，一次原子加的成本几乎看不见。

第三项是**按上投影负载秩逆序派发下投影**。早期版本里，上投影阶段和下投影阶段共用同一套来回交替（蛇形）的顺序领活，结果**最重的下投影子任务，又落在了刚刚跑完最重上投影子任务的那批 CTA 头上**，两段重活叠在一起拖出了 `9–52 µs` 的长尾。解法是记下每个 CTA 在上投影阶段的实际负载排名（秩），到了下投影阶段反过来派活，让上投影最轻的 CTA 优先去领最重的下投影子任务。这一倒序把 `T = 256` 滑窗与全长最慢 CTA 的退出时间从 `189.4 / 215.0 µs` 压到了 **`176.3 / 195.0 µs`**（核尾提前 `13.1 / 20.0 µs`，`T = 128` 滑窗也提前 `2.6 µs`），使 `T = 256` 滑窗与全长整层分别提速 **`5.2%` 与 `1.47%`**。

第四项是**尾部 66 活沿 `K` 维对半切分（K-halves，见第 2 章第 1 节）**。当下投影最后一轮剩余子任务数不超过 `66`（不超 132 个 SM 的一半）且末尾都是 `8` 行短尾块时，把剩余的下投影子任务沿 `K` 维对半劈成两份半程活（前半程写出 FP32 部分和并立下就绪标志，后半程等标志到了再累加），让原本要空转的另一半 SM 也分到活干。这一切分在单层 `T = 128 / 256` 上平均省下 **`0.54 µs` 与 `1.95 µs`**，在只剩 `12` 个子任务的路由上省下 **`4.53–5.07 µs`**。不过在不触发切分的满波路由上，多出的分支与标志检查会**慢 `0.52–0.75 µs`**，因此必须只在剩余子任务数 `≤ 66` 时开启。

拉齐 132 个常驻 CTA 的收尾时间之后，大批量专家核里剩下的停顿就集中在消费者线程束的同步与尾声指令上了。

## 4. m3 → m4（下）：把同步从消费者关键路径上拿走，并在尾声折叠缩放

<!-- FIG ch08-m4b-sync: 图 8-5 画阶段 6 第四代消除消费者同步停顿与尾声指令瓶颈的四步改造：上方对比 512 线程并发 red.release 引发 93.3 µs L2 原子串行化、延迟上投影完成标志至下一子任务 wait_group<0> 之后刷新（省 29.92 µs）与将 GPU 级释放移交独占的第 18 号释放 warp（576 → 608 线程，消除消费者 400–700 周期 MEMBAR.ALL.GPU 停顿并避免阻塞第 16 号生产者 warp 的 TMA 发射，合计省 2.59 µs）；下方画奇偶双账本 doneA[0..1023] / [1024..2047] 免除核尾清零链（省 0.29–0.33 µs）与 SwiGLU 线性缩放折叠（每元素 9 → 7 条指令，省 0.54–0.60 µs）。 -->

把所有工作装进常驻 `wgmma` 核之后，为什么消费者线程束还是会频繁停下来等同步？**因为 `wgmma` 要求整个 128 线程的 warpgroup 锁步齐发（`sync.aligned`），只要消费者路径上留着一条设备级内存栅栏（`MEMBAR.ALL.GPU`），或者在 L2 原子单元上排起长队，整条矩阵管线就会跟着一起停摆。**

在改同步协议之前，剖析器先抓出了四处流水线阻塞：
1. **流水区间混入非矩阵写**：在 `wgmma` 流水区间里混入了非矩阵写操作，触发了 `ptxas` 寄存器读写串行化告警（见第 6 章第 1 节），每条 `HGMMA` 后面都被编译器插进寄存器依赖等待屏障（`DEPBAR`），单层慢了 **`8.10 µs`**；把非矩阵写移出流水区间即可消除。
2. **激活收集未合并**：离散激活收集起初按标量写出耗去了 `22.5 µs`；改成 16 字节宽幅合并写出（`STG.E.128`，一次写 128 位，见第 3 章第 2 节）后，直接省下 **`13.10 µs`**。
3. **512 个线程同时发原子释放**：第 2 章第 4 节讲过，如果让 4 个消费者 warpgroup 的 **512 个线程同时往 L2 计数器发 `red.release.gpu`**，全卡成千上万个原子请求会在中央 L2 原子单元上排队，单层 `T = 256` 慢 **`93.3 µs`**。按 PTX 内存模型，release 具备跨线程的因果累积性（cumulativity）：一个线程先通过屏障看到同组其他线程的写入，再做一次 release，就能把那些写入一并发布到全卡可见。因此改成每个 warp 先经 `__syncwarp` 对齐、再只由 `lane 0` 发 1 次释放（512 次请求缩成 16 次），这 `93.3 µs` 的排队开销随之消失。
4. **设备级栅栏卡在两个子任务之间**：就算改成了每 warp 释放，消费者在每个上投影子任务末尾发布完成标志时，依然要执行一次设备级栅栏 `MEMBAR.ALL.GPU`。因为每个 SM 的 L1 缓存之间并不自动保持一致，设备级栅栏必须等此前发出的全局写请求一路排空到全卡共享的 L2 缓存，每次停顿达 **`400–700` 个周期**（负载下约 `0.6–1.3 µs`），直接卡在两个子任务的 `wgmma` 之间。

围绕这第 4 个阻塞点，`m4` 一路做减法，把 GPU 级同步从消费者关键路径上剥离出去：

第一步是**晚一步再立上投影完成标志，并用跨代理栅栏 `fence.proxy.async` 替换重型栅栏**。下投影阶段的 CTA 要读取某一块中间激活 `h`，必须先看到这块的上投影完成标志。可消费者刚算完当前上投影子任务、发出写出 `h` 的指令时，数据还在飞往 L2 的路上，而且消费者马上就要发下一个子任务的第一轮 `wgmma`；这时候插一道全局栅栏，等于逼着矩阵管线停下来等显存写排空。

`m4` 的做法是：当前子任务写完 `h` 先不立标志，直接去发下一个子任务的第一轮 `wgmma`；**等下一个子任务完成了 `wait_group<0>`（第 5 章讲过的等待异步 `wgmma` 组完成指令）之后，再回过头刷新上一个子任务的上投影完成标志**。按 PTX 规范，推迟后的 release 依然排在写出 `h` 的指令之后，内存可见性顺序完全成立；而在硬件执行上，上一个子任务写出的 `h` 在这一组 `wgmma` 运行期间已经排空到 L2，刷新标志几乎不再卡停矩阵管线。在单层 `T = 256` 上，延迟刷新上投影完成标志这一项改动就省下 **`29.92 µs`**，代价只是让下投影阶段晚 1 个 `wgmma` 组看到标志。反过来，如果在小批量 `T = 1..32` 上也想用细粒度计数器或数据内嵌标志去替掉 `1.42 µs` 的全网格栅栏，因为经由 L2 交接 `h` 至少要付约 `1 µs` 的写排空延迟，结果反而会**慢 `0.10–1.06 µs`**，所以小批量继续用第 2 节的双核 PDL 串联。

与此同时，在激活收集与就绪释放里，普通线程写出的数据（通用代理通路）和硬件 TMA / `wgmma` 异步读取的数据（异步代理通路）走两条不同的硬件通路。每个存储线程先执行一条跨代理栅栏 `fence.proxy.async.global` 让普通写对异步通路可见，再经 CTA 屏障 `bar.sync` 对齐后由线程 0 发单次 `red.release.gpu`（同样利用跨线程累积可见性），就能替掉每个存储线程 5 条指令的 `fence.acq_rel.gpu`（见第 2 章第 4 节），在单层 `T = 128 / 256` 上再省 **`0.52 µs` 与 `0.70 µs`**。此外，在激活环上改由每个消费者 warp 的 `lane 0` 独立向空信号报到，在权重环上把空信号报到推迟到激活满信号等待之后，消除了待决 `LDS` 的读后写（WAR）竞态（付出 `0.4–1.6 µs` 的速度代价，见第 3 章第 4 节）。

第二步是**把残留的 `MEMBAR.ALL.GPU` 移出消费者，交给新增的第 18 号专职释放 warp（`576 → 608` 线程，共 19 个 warp）**。为了让 4 个消费者 warpgroup 连子任务末尾那一次 `red.release.gpu` 都不用发，消费者改为只对共享内存计数器做片上释放 `red.release.cta`（只需几十个周期）；另派一个专职释放线程用 `ld.acquire.cta` 轮询片上计数器达标后，代发一次 GPU 级的 `red.release.gpu`（按跨作用域的因果传递性，消费者的全局写入随之对全卡可见，编译出的静态 `MEMBAR` 从 `25` 处降到 `9` 处）。这一步在单层 `T = 128 / 256` 上省下 **`1.49 µs` 与 `1.74 µs`**。

起初为了省线程，这个专职释放线程被塞在第 16 号权重生产 warp 的 `lane 1`。但第 4 章第 3 节讲过，**同一个 warp 的 32 个线程共用唯一一条指令流**：当 `lane 1` 轮询计数器或卡在 `MEMBAR.ALL.GPU` 上时，同一个 warp 里的 `lane 0` 就没法及时发出下一轮权重 TMA。于是 `m4` 给每个 CTA 多开 1 个 warp（从 18 个 warp `576` 线程扩到 **19 个 warp `608` 线程**），把释放线程迁到**独占的第 18 号释放 warp（`lane 0`）**，单层 `T = 128 / 256` 又省下 **`0.77 µs` 与 `0.85 µs`**。如果在原位置直接把 `MEMBAR` 删掉再测（见第 10 章），只能省下 `0.44 / 0.15 µs`——由此可以推断，迁往独立释放 warp 的收益（尤其在 `T = 256` 上）有一大半来自不再挡住第 16 号生产者 warp 的 `lane 0` 发射 TMA。反过来，不要让这个释放线程顺带去按阶段发信令提前唤醒后归一化核：把等待删掉再测，隐藏后归一化核尾部的收益上界只有 `1.06–2.21 µs`，而在主核里加信令本身就要花掉 `2.2–3.2 µs`，实测反而**慢 `0.9–21 µs`**。

第三步是**用奇偶双账本省掉核尾的清零链**。在 CUDA Graph 反复重放时，全局的上投影完成标志计数器每一趟跑完都得归零。如果在核尾让最后一个退出的 CTA 去清零，就得多跑一串栅栏和同步。`m4` 直接把计数器显存翻倍（`4 KiB → 8 KiB`），开辟偶账本（下标 `0..1023`）和奇账本（下标 `1024..2047`）：每次启动按全局递增序号的奇偶挑其中一本用，同时让空闲的生产者线程在 `griddepcontrol.wait`（等待前序网格全部完成）之后，在后台顺手把另一本清零（因为前序使用那套账本的内核一定已经跑完，后台清零不会与前序读写发生冲突）。删掉核尾的重置链后，单层 `T = 128 / 256` 又省下 **`0.29 µs` 与 `0.33 µs`**。

第四步是**在发射槽受限的 SwiGLU 尾声里折叠缩放系数**。主循环里的反量化直接复用了第 5 章第 1 节与第 6 章第 3 节的寄存器解码（`IMAD.SHL` 左移分流、成对块缩放解码与每字 8 条整数指令的异或重排解码，见第 6 章第 3 节）。接着排查子任务之间的切换间隙：单个上投影或下投影切换间隙分别耗时 `1.26 µs` 与 `1.75 µs`，每个 CTA 在全部子任务上的切换间隙累计达 `12.7 µs`（占全核耗时的 `6.1%`）。起初尝试加第 3 套 A 寄存器缓冲（`wait_group<2>`）去盖住它，结果完全没有收益。把特殊函数指令删掉再测（保持总指令数不变，见第 10 章），才揪出真正的瓶颈：**卡住上投影尾声的是指令发射槽（`932` 个发射周期 > `768` 个特殊函数周期），而不是数据等待或特殊函数单元吞吐。**

既然瓶颈在指令条数，而章首说过每个专家的门控与上投影共用同一个全局缩放 `s`，设寄存器里还没乘全局缩放 `s` 的门控与上投影值分别为 `dg` 和 `du`（即 `g = s * dg`，`u = s * du`），代入 `SwiGLU` 公式就能把两次乘 `s` 折进指数参数和分母里：
`silu(g) * u = (s * dg) / (1 + exp(-s * dg)) * (s * du) = (dg * du) / (k + k * 2^(dg * (-s * log2e)))`，其中 `k = 1 / s^2`。
因为 `(-s * log2e)` 和 `k = 1 / s^2` 都是每个专家固定的常数，内层尾声算指数参数 `arg = dg * (-s * log2e)` 和分母乘加 `FFMA(e, k, k)` 时顺手就把全局缩放消化掉了；再配合 `ld.shared.v4` 向量化读取作业描述符，把每个元素的尾声指令从 `9` 条砍到 **`7` 条**，在单层 `T = 128 / 256` 上省下 **`0.54 µs` 与 `0.60 µs`**（用 `ex2.approx.ftz` 去掉低于 `-126` 的次正规数补救分支每线程少 `48` 条指令，再省 `0.28 / 0.48 µs`）。当然，这套尾声折叠只有在内核受发射槽限制时才管用：在 `T ≤ 32` 解码下它的收益为 `0.00 µs`；移植到不受发射槽限制的整层检验变体上时，尽管砍掉了 `22%–41%` 的尾声指令，实测仍是中性（`0.99938×`）。

第四代（`m4`）把 `T = 128..256` 大批量检验下的跨 SM 尾波失衡与消费者同步停顿逐一剥离；把单层 `T = 256` 常驻 `wgmma` 核（配对省 `22.54 µs`）叠加到 `m3` 的 `6,123.21 µs` 实测结果上，6 个算例的 60 层几何平均耗时预计降至约 **`6,033 µs`**（估计值，相对 SGLang 基线约 **`2.23×`**；整套 `m4` 全部细粒度改动叠加后的 60 层耗时未单独测）。

## 5. m4 → m5：预填充（T = 753..16,384）下，32 个专家全忙时怎样喂饱矩阵管线

<!-- FIG ch08-p5-moe: 图 8-6 画阶段 6 预填充路由专家（Grouped NVFP4 GEMM）的四步硬件流水线（对应将乱序词元按 32 个本地专家分桶重排并裁剪末尾填充行尾块与空退出网格分块数上限、4-warp 收集线程束配 TMA 权重环与 4 组旋转寄存器保持 wait_group<2> 跨管线重叠、gemm1 SwiGLU 尾声用打包 cvt.rn.bf16x2.f32［F2FP］将 F2F 从 224 条压至 96 条使 SFU 管线占用从 5.74% 降至 3.08%、以及单通道释放完成标志消除消费者 MEMBAR.ALL.GPU 的算法步）。 -->

章首算过，当输入从逐词解码和投机检验跨进长序列预填充（`T = 753, 3,012, 16,384`）时，本卡 32 个本地专家全部被激活；一旦 `T ≥ 3,012`，每个专家平均分到的词元数 `M` 就跨过了 58 个词元的平衡点，瓶颈从读权重带宽转向了矩阵算力与指令管线。面对几千到上万个本地 `(tok, slot, e)` 命中对，第五代（`m4 → m5`）切到了由独立路由对齐核驱动的分组矩阵乘（Grouped NVFP4 GEMM）流水线（图 8-6）。

`m5` 的改造顺着数据流分成三步：先在入口砍掉非本地槽位和空转 CTA，再按词数 `T` 分成过渡区（`T ≤ 1,024`）和算力区（`T > 1,024`）两条主循环，最后把尾声里的类型转换从特殊函数管线上挪开。

第一步是**只生成本卡 32 个专家的紧凑分桶表，并用分块数上限砍掉空转 CTA**。在预填充下，专用路由对齐核直接输出**只包含本卡 32 个本地专家（`0..31`）分块的重排词元表与每块对应的专家表**，从源头剔除非本地空块（代价是预先分配固定大小的缓冲显存以供静态图反复重放复用），并启用第 1 节的尾块裁剪与第 3 节的 LPT 大块先排。

即便剔除了非本地专家，主网格的大小还有一个隐患。因为 CUDA Graph 静态图捕捉要求录制时网格形状固定（见第 1 章第 1 节），不能在运行期按实际命中数动态改网格大小，`gemm1` 和 `gemm2` 的网格原本按最坏情况（假设所有词元的 8 个路由槽位全落在本卡，即 `8T` 对，外加 32 个专家各自的填充块）开到了 `1,056` 个 `BM = 128` 分块 CTA。但在 `T = 16,384` 下统计发现，这 `1,056` 个 CTA 里有 **`77%`** 一进场发现没有有效分块、转头就空退出。

为什么会空出这么多？因为均匀路由下本卡平均只命中 `T` 对（`8T ÷ 8` 张卡）。于是 `m5` 按平均命中数的 **2 倍偏斜余量（`2T` 对）** 加上每个专家最多补齐的 127 行填充，把 `T > 3,012` 的 `gemm1` 和 `gemm2` 主网格截断在 `分块数上限 = ⌈(2T + 32 × 127) / 128⌉`（`T = 16,384` 时从 `1,056` 块截断到 **`288`** 个分块，直接省掉约 `73%` 的启动块）；再另外启动一个每 SM 1 个 CTA（共 132 个）的常驻溢出兜底核，去处理万一超出 `288` 块的分块（测试分布下无溢出分块，空跑的兜底核耗时约 `1.25 µs`）。砍掉空退出块后，`T = 16,384` 的 `gemm1` 从 `2,905 µs` 压到 **`2,831 µs`**，`gemm2` 从 `1,406 µs` 压到 **`1,376 µs`**（两者合计 `4,207 µs`，达到 `1,668 µs` 理想算力下界的约 **`40%`**，剩余差距诊断见第 10 章），整层直接提速 **`1.07%`**（仅在 `T > 3,012` 开启）。

第二步是**按词元数 `T` 分成两条主循环，并在 `T = 16,384` 的 `gemm2` 上退回 `9,216`-CTA 非持久网格**：
- **在 `T = 753`（过渡区，每专家平均 `M ≈ 24` 个词元）**：每个专家只有约 24 个词元，填不满 128 行，因此走 `BM = 64` 分块路径，改由消费者线程束发 TMA 搬运权重（替代线程发 `cp.async`，每线程寄存器从 `180` 压到 `151 / 150` 个，使每 SM 驻留从 `2` 个升到 `3` 个 CTA）。这样 64 个词元对共享一次权重解码配 TMA 权重环，让 Tensor Core 管线占用从 `40%` 升到 `57%`、`gemm1` 从 `240.0` 降到 `222.3 µs`，`T = 753` 整层提速 **`3.87%`**（若把这套消费者发 TMA 环搬到 `T = 3,012` 的 `BM = 128`，整层反而**慢 `1.6%`**）。接着用第 1 章第 1 节的单核票据排序把 `gemm1 + SwiGLU + gemm2` 融进同一个网格省掉核间启动空隙，配合 4 套旋转 A 寄存器缓冲（`wait_group<2>`，见第 5 章第 4 节），在 `T = 753 / 3,012 / 16,384` 上整层分别提速 **`2.04% / 1.82% / 4.98%`**。同时，每步开头用 8 字节寄存器 `LDG` 提前读入 1 字节 `FP8 E4M3` 块缩放码并在步末展开（消掉缩放码的 `cp.async` 等待组和 `LDS` 往返，净提速 **`0.38%`**；若改用 `cp.async + LDS` 搬运展开反而变慢），并加上第 4 节的后置 `fence.proxy.async` 配 4 槽环（提速 **`1.37%`**）以及第 5、6 章的每 32 位权重字发 1 组 `wgmma`、左移分流、异或重排解码与循环携带槽计数器（见第 5 章第 1、4 节与第 6 章第 1、3 节）。
- **在 `T = 3,012 / 16,384`（算力区，每专家平均 `M ≈ 94` 与 `512` 个词元）**：分块扩到 `BM = 128`。因为 Hopper 的硬件 TMA 没法按重排词元表（`pair // 8`）去离散收集激活行（见第 3 章第 3 节），`gemm1` 专门划出 **4 个收集 warp（共 128 个线程）用 `cp.async` 收集离散激活行 `x`，同时用 TMA 搬运连续权重装填 3 套环形缓冲**。把 `cp.async` 和代理栅栏移出消费者主循环后（代价是收集 warp 占去 128 个线程），在 `T = 3,012 / 16,384` 上整层提速 **`1.21% / 2.03%`**；配合每步 `K` 把 2 个 CTA 屏障合为 1 个再提速 **`1.48% / 1.70%`**；在此基础上把 `gemm1` 改成常驻网格，并加上一道**分块完成 `mbarrier`**，让收集 warp 在消费者跑当前分块尾声时跨分块提前预取下一块激活（`T = 3,012` 再提速 `0.71%–0.93%`）。下投影 `gemm2` 的满块也采用同样的 **1 个 TMA 生产者 warp + 4 个消费者 warp 的 2 槽环分工**（`maxnreg 128`），在 `T = 3,012 / 16,384` 上提速 **`1.70% / 1.95%`**。至于能不能在 `T ≤ 3,012` 下把 `gemm1` 改成更宽的词元分块、在核内由生产者 warp 做激活收集？实测核内宽块收集破坏了寄存器配额与环流水，在 `T = 753` 上零收益，在 `T = 3,012` 上反而**慢 `1.4%–13.4%`**。
- **为什么到了 `T = 16,384` 的 `gemm2`，反而要从 `264`-CTA 常驻核退回 `9,216`-CTA 非持久网格？** 此前曾把 `gemm2` 写成 `264` 个 CTA（`2 × 132`）的常驻核，让每个 CTA 按固定步长（`idx += gridDim.x`）静态领分块。但在 `T = 16,384` 下，各个专家分块的完成时间和尾块裁剪长度参差不齐，固定步长根本没法把活从慢 SM 挪给快 SM（核内动态原子领活在此核上未测）。剖析器一测，`gemm2` 核内的 **SM 空闲时间高达 `60.3 µs`**，SM 之间的有效周期极差拉开到 `94.0 µs`，连带着挂在后面的归一化核也在 PDL 等待里干等了约 **`118–119 µs`**。`m5` 退回非持久的 **`9,216` 个普通 CTA（`288` 个行分块 × `32` 个 `128` 列分块，合 `4,096` 输出列）**，直接交给硬件块调度器把下一个分块派给最先腾出空的 SM。这一退，把 `gemm2` 核内的 SM 空闲时间从 `60.3 µs` 压到了 **`18.6 µs`**（极差压到 `45.5 µs`），单核耗时从 `1,468.96` 缩到 `1,443.17 µs`，直接省下 **`25.8 µs`**。

第三步是**在 `gemm1` 尾声用 `F2FP` 成对打包舍入替代单数转换 `F2F`，给特殊函数管线（`SFU`）减负（图 8-6 下方）**。在 `T > 1,024` 的 `gemm1` 尾声里，把单个单精度浮点数转成 `BF16` 的标量转换指令 `F2F`（float-to-float），和算指数的 `MUFU.EX2` 指令走的都是第 5 章讲过的同一条特殊函数管线（`SFU`），两条指令流排在同一个队列里互相等待，拉长了尾声关键路径的延迟。`m5` 把标量转换改成了两个浮点数一起打包舍入的指令 `cvt.rn.bf16x2.f32`（编译为走普通 `ALU` 管线的 **`F2FP`**，float-to-float packed，静态条数从 `56` 升到 `120`）。这样一来，静态 `F2F` 指令从 `224` 条砍到了 **`96` 条**，剖析器实测 `SFU` 管线占用率从 `5.74%` 降到 **`3.08%`**，单改这一项就让整层预填充提速 **`0.33%`**。它的代价是需要用移位和按位与把打包半字拆开；如果把它移植到第 4 节的解码与检验专家核里，因为那边的尾声不在延迟关键路径上，实测为中性。

**带走一句话：** 路由混合专家的五代内核演化（`m0 → m5`）始终跟着一个数走——分到同一个本地专家的词元数（即专家矩阵乘的行数 `M`）：当 `M < 58` 时，靠片上反量化、权重环、尾块裁剪、常驻核与异步释放省掉显存往返和同步停顿；当 `M ≥ 58` 时，靠分块数上限、专门收集线程束、硬件块调度与成对打包舍入喂饱 Tensor Core 与指令管线。
