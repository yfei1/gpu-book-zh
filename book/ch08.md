## 1. 从 Decode 到 Prefill 的单层账本翻转：`T = 753` 过渡区与 `T = 16,384` 纯算力区（阶段 1、3、4、5、7 稠密投影与尾波切分）

<!-- FIG ch08-p5-flip: 图 8-1 画同一层模型从 Decode（T=1）经多轮追加 Prefill（T=753 / 3,012）到首轮分块 Prefill（T=16,384）的各阶段算术强度、每专家平均词元数与理论下界翻转解剖图（对应稠密投影、分页注意力与 32 个本地专家在四档批量下的 GFLOPs 账本，以及 T=753 旁路流并发与 T=3,012 / 16,384 Stream-K 尾波切分的算法步）。 -->

赛题 P5 的单层数学参考实现与第 7 章的 P3 字节级完全一致。它同样从 HBM 读入本层入口激活 `attn_input [T, 8192]`（BF16）与残差流 `stream [T, 8192]`（FP32），依次流过阶段 1 至阶段 8，原地追加写入分页 `FP8 E4M3` 键值缓存（块内 `L` 个新词元带下三角因果掩码），最后输出 `(out BF16 [T, 8192], stream FP32 [T, 8192], experts int32 [T, 8])` 交给下一层。唯一改变的是每趟并排流过单层的词元总数 `T = B × L`，涵盖三档真实预填充负载：
- 单请求多轮追加（`B = 1, L = 753, T = 753`，接在 `80,000` 个已缓存历史词之后）：滑窗层下界为 `257.0 µs`，全长层下界为 `496.7 µs`。
- 四请求多轮追加（`B = 4, L = 753, T = 3,012`，各接 `80,000` 个历史词）：滑窗层下界为 `1,036.3 µs`，全长层下界为 `1,992.4 µs`。
- 首轮长提示词分块（`B = 1, L = 16,384, T = 16,384`，按 SGLang 分块预填充粒度切块）：历史 `ctx = 0` 全长层下界为 `5,518.4 µs`，`ctx = 32,768` 滑窗层下界为 `5,663.4 µs`（评测权重 `138 = 3 × 46`，代表全部三个 `16,384` 滑窗分块），`ctx = 32,768` 全长层下界为 `7,710.0 µs`，`ctx = 65,536` 全长层下界为 **9,847.7 µs**（约 `9.85 ms`）。

在图 8-1 中依次切换 `T = 1`、`T = 753`、`T = 3,012` 与 `T = 16,384` 四档负载，就能看清为什么 `T = 753` 与 `T = 16,384` 构成了从带宽过渡区到纯算力区的两级翻转。
- 阶段 1、3、4、5、7（五个稠密投影）。因为 `T > 8`，阶段 7 的 `unpooler` 不再只算前 `1,024` 列切片，而是算满全部 `8,192` 列（读 `67.1 MB`）。五个稠密投影权重总计固定为 `197.1 MB`（按 `4.8 TB/s` 算出的权重读取时间仅 `41.1 µs`）。当 `T` 从 `1` 升到 `753`、`3,012` 与 `16,384` 时，稠密投影总运算量从 `0.134 GFLOP` 跃升至 **145 GFLOP**（按 `989 TFLOP/s` 算力下界 `147 µs`）、**581 GFLOP**（`587 µs`）与 **3,161 GFLOP**（`3.20 ms`）。按第 0 章计入权重与输入输出激活的同一口径计算，五个稠密投影的算术强度从 `T = 753` 的 **147–590 FLOP/B**（仅 4 字节权重的 `router` 为 `147`，其余四个 BF16 投影均已超 `412`），升至 `T = 3,012` 的 **208–1,432 FLOP/B** 与 `T = 16,384` 的 **234–2,341 FLOP/B**，全面跨过 `206 FLOP/B` 平衡点，由 Tensor Core 算力主导。
- 阶段 6（32 个本地专家）在 **`T = 753` 与 `T = 16,384` 之间的临界翻转**。单个 NVFP4 专家权重占 `28.3 MB`（32 个本地专家全读一遍的上限为 `905.97 MB`，按 `4.8 TB/s` 耗时 **188.7 µs**；在偏斜路由下 `T = 753 / 3,012` 实际命中的不同本地专家个数未在记录中单列，属未知，图 8-1 按 32 个专家全读上限绘出）。每个词元在单个专家上执行 `100.7 MFLOP`（算术强度 `3.6 FLOP/B`），必须有 `206 ÷ 3.56 ≈` **58 个词元**命中同一个专家，该专家才跨过 `206 FLOP/B` 平衡点（见第 0 章第 2 节）。按均匀路由（每词元在 32 个本地专家上平均产生 1 条本地路由）计算，每个本地专家分到的平均词元数为 `T ÷ 32`：
  1. 在 **`T = 753`** 时，每个本地专家平均只分到 `753 ÷ 32 ≈` **24 个词元**（`< 58`）。专家阶段总运算为 `76 GFLOP`（算力耗时仅 `77 µs < 188.7 µs`），尚未跨过平衡点，仍处在**显存带宽与指令延迟过渡区**。
  2. 到 **`T = 3,012`** 时，每个本地专家平均分到 `3,012 ÷ 32 ≈` **94 个词元**（`> 58`）。专家运算量升至 **303 GFLOP**（算力耗时 `306 µs > 188.7 µs`），跨过平衡点。
  3. 到 **`T = 16,384`** 时，本卡 32 个本地专家全部被激活，平均每个专家分到 `16,384 ÷ 32 =` **512 个词元**（跨过平衡点近 9 倍）。专家总运算高达 **1,649 GFLOP**（算力下界约 `1.67 ms`，远超读完 32 个专家权重的 `188.7 µs`），彻底翻转为大型分组矩阵乘（Grouped NVFP4 GEMM）的 **Tensor Core 算力战**。
- 阶段 2（分页注意力）。滑窗层因窗口固定为 `2,048`，在 `T = 753 / 3,012 / 16,384` 下运算量仅为 `6 / 25 / 137 GFLOP`。而在全长层上，每个新词元既要回顾 `65,536` 或 `80,000` 个历史词，又要按块内因果掩码回顾块内前序词。其运算量在 `T = 753 / 3,012` 下达 **248 / 992 GFLOP**，在 `T = 16,384, ctx = 65,536` 下更暴增至 **4,948 GFLOP**（算力下界约 `5.00 ms`，独占整层 `9.85 ms` 下界的一半以上）。图 8-1 在四档负载下的读数依次为：`T = 1：七个阶段强度 0.5–16 FLOP/B，都低于平衡点 206` / `赛题整层下界 44.2 µs（全长层）= 读 HBM 的时间`、`T = 753：每个专家平均 24 个词元（< 58）· 稠密投影强度 147–590 FLOP/B` / `赛题整层下界 496.7 µs（全长层）= 按算力算，专家阶段还没到算力区`、`T = 3,012：每个专家平均 94 个词元（> 58）· 稠密投影强度 208–1,432 FLOP/B` / `赛题整层下界 1,992.4 µs（全长层）= 按算力算`、以及 `T = 16,384：每个专家平均 512 个词元（> 58）· 稠密投影强度 234–2,341 FLOP/B` / `赛题整层下界 9,847.7 µs（全长层）= 按算力算`。

针对已经进入算力受限区的阶段 1、3、4、5、7（五个稠密投影），P5 在第 2 级、第 0–1 级与第 1 级上做了三项重塑。
- 第 2 级（持久线程束分工 `wgmma` 与 `router` 左右矩阵交换）。全部 BF16 稠密投影（`qkv_gate`、`o`、`pooler`、`unpooler`）切换为每 SM 驻留 1 个持久 CTA 的线程束分工内核（`BM = 128, BK = 64`，1 个 TMA 生产者 warp 配 2 个消费者 warpgroup，按第 7 章图 7-1 的 `setmaxnreg 40 / 232` 分配 `64,512` 个寄存器）。两个消费者 warpgroup 各自向环形槽的 `empty[s]` 报到（计数为 2），省去每步 `K` 的块内屏障并消除逐分块启动开销，单核比旧集群分块内核快 **1.05–1.30 倍**（整层提速 `1.14%–2.72%`）。在 `T = 3,012` 的阶段 4 `router`（词元数 `M = 3,012` 大而专家数 `N = 256` 小，FP32 权重拆为高/低两份 BF16 残差对并在 FP32 累加器中相加）中，采用交换左右矩阵（swap-AB，见第 5 章第 2 节）的 `wgmma.m64n192k16`。它把窄的专家维放在 `M = 64` 侧、把词元维放在 `N = 192` 侧，配合 5 槽环、2-CTA 集群多播与 2 路 Split-K，将 `router` 内核耗时从 `60.5 µs` 压到 **37.6 µs**（`T = 3,012` 整层提速 `1.03%–1.15%`）。随后再把词元分块从 128 扩至 192，使网格从 `192` 个 CTA（`1.45` 个波次）缩为 `128` 个 CTA 单波次装入 132 个 SM，实测在 `T = 3,012` 滑窗层再省 **15.0 µs**。
- 第 0–1 级（`T = 753` 利用空闲 SM 的旁路 `stream` 并发）。在 `T = 753` 下，阶段 5 的 `pooler`（`128 × 256` 分块，每 SM 驻留 1 个 CTA）只启动 `96` 个 CTA，在 132 个 SM 上留下了 `36` 个空闲 SM。由于阶段 4 的 `router`（`21.9 µs`）、`top-8`（`6.2 µs`）与路由对齐核只依赖阶段 3 输出的 `h`、不依赖 `pooler`，P5 把它们移到旁路 `stream` 上，直接利用这 36 个空闲 SM 与主流上的 `pooler` 并行执行，使 `T = 753` 整层实测提速 **3.18%–3.33%**（在 `T = 16,384` 下，因 `pooler` 网格达 `2,048` 个 CTA 会占满 SM 使旁路流等到 `pooler` 末尾才启动，改为先在主流全卡跑完 `router`，再把 `top-8` 与路由对齐放到旁路流与 `pooler` 重叠，首轮提速 `0.93%`）。
- 第 1 级（`T = 16,384` 与 `T = 3,012` 的稠密尾波切平）。在 `T = 16,384` 下，持久稠密内核按轮转顺序领分块，`qkv_gate`（9 个整波余 `96` 块）与 `pooler`（16 个整波余 `68` 块）在最后一波共有 **85 µs** 的尾波空闲。P5 用 **Stream-K** 将最后 `(tiles mod grid)` 个尾波分块的 `K` 步均摊到全卡所有 CTA，由起始分片汇合单精度部分和，使 `qkv_gate` 与 `pooler` 分别缩短 **13 µs 与 28 µs**（同时将 `unpooler` 与 `o` 的末尾 4 块与 8 块按列切窄为 `1/4` 与 `1/2` 宽度的子单元分摊，使 `unpooler` 耗时从 `1,350.5 / 1,365.0 µs` 降至 `1,334.8 / 1,344.8 µs`，再缩短 `15.8–20.3 µs`）。在 `T = 3,012` 滑窗层下，`qkv_gate` 共 `216` 个分块（`132 + 84`，第 2 波有 48 个 SM 空闲约 `28 µs`）。P5 让 `0..83` 号 CTA 算各自尾波分块的前 82 个 `K` 步并汇总，让空闲的 `84..131` 号 CTA 协作算后 46 个 `K` 步，把全卡 CTA 结束时间的极差-均值差从 `29.4 µs` 压到 **7.4 µs**（`qkv_gate` 缩短 **8.7 µs**）。

## 2. 阶段 2（Prefill 分页注意力）：从 1,366-CTA 尾波切分、统一寄存器 `UR` 降压，到 ALU 直接生成 FP8 指数与 F16 累加（含 `f16x2` 伪打包反例）

在 `T = 16,384, ctx = 65,536` 的全长层上，阶段 2 的分页注意力单层运算量高达 `4,948 GFLOP`（耗时超 `5 ms`，占整层一半以上），成为决定 P5 性能上限的头号战场。
- 公式与入站/出站交接：
  1. 旁路键值准备与入库：在阶段 1 的 `qkv_gate` 启动前先在主流记录事件分叉点（`fork`），让旁路 `stream` 上的历史键值准备第 0 阶段与 `qkv_gate` 并行执行（在 `T = 3,012` 全长层省 `27.7 µs`、在 `T = 753` 全长层省 `5.1 µs`）。随后由每词元 1 个线程组的融合内核在寄存器内完成 `q = rmsnorm(q_in) * 5.473`、`k = rmsnorm(k_in)`、滑窗层 `RoPE` 及新键值 `FP8 E4M3` 入库（`T = 16,384` 从 `52.75 µs` 压至 **31.0 µs**）。
  2. 分块预填充因果注意力与门控输出融合：全算例统一运行 512 线程（1 个生产者 + 3 个消费者 warpgroup）的分页预填充注意力内核，按 `128` 个键一分块流式计算 `P = softmax((q_fp8 @ K_visible.T) / 8)` 与 `o_raw = P @ V_visible`（块内 `L` 个新词元带下三角因果掩码）。在内核尾声直接融合 `o_attn = rmsnorm(o_raw, 1e-5) * sigmoid(gate)`，省去外部 FlashAttention-3 调用与独立输出归一化启动及其中间激活往返，单此一项将全算例总耗时从 `233.07 ms` 压至 **231.36 ms**（配合第 4 节恢复非持久 `gemm2` 网格后合为 **230.23 ms** 的统一基线）。
- 输入与输出：输入 `qkv [T, 2304]`（BF16，位于 HBM 或 L2）、`page_table [B, max_pages]`（`int32`）与 `K_cache, V_cache`（FP8 `E4M3`，位于 HBM）。输出 `o_attn [T, 1024]`（BF16，写回 HBM 或 L2），交给阶段 3（`o` 投影）。

进入注意力主内核后，顺着第 1 级（整卡波次）、第 3 级（SMSP 统一寄存器与发射槽）到第 4–5 级（SFU 管线、ALU 打包与 Tensor Core 累加器精度），P5 连续解开了四道硬件束缚。
- 第一步（第 1 级：拆细最轻的 40 个查询分块削平 `1,366` 个 CTA 的尾波）。在 `T = 16,384` 全长层上，注意力网格共 `1,366` 个 CTA。它在 132 个 SM 上跑完 `10` 个整波次（`1,320` 个 CTA）后，第 11 波只剩 `46` 个 CTA。尽管各分块已按工作量从重到轻排序，这最后 46 个轻 CTA 跑完时仍有 86 个 SM 空转等待（实测尾波耗时 `304 / 589 µs`，与贪心列表调度模型的 `302 / 587 µs` 吻合，证明尾波来自波次量化而非排序失误）。P5 将最轻的 40 个查询分块各沿键值维拆成 4 个 Split-KV 子块（网格从 `1,366` 扩为 `1,606` 个 CTA），让短小的尾块铺满最后一波的全部 SM，在 `ctx = 32,768` 与 `65,536` 全长算例上单核直接省下 **210 µs 与 345 µs**（配合 `T = 3,012` 路由器单波次改造，整层提速 **0.35%**）。

- 第二步（第 3 级：将全 warp 相同的环槽、相位与描述符移入统一寄存器 `UR`，并改按 warp 释放槽位，图 8-2 模式 2）。在全长注意力的消费者主循环中，剖析器显示 SMSP 发射槽成了瓶颈。未掩码循环每处理一个 128-key 分块要发 `354` 条静态 SASS 指令（非上抬路径 `304` 条，其中当全 warp 最大值未抬升时通过 `__any_sync` 投票直接跳过重缩放）。检查反汇编发现，循环计数器、环形槽号、相位位与矩阵描述符被放在了线程私有的向量寄存器 `R` 里。每次更新这些变量都要耗费 `37` 条 `UR/R2UR` 与 `14` 条整数指令重复拼装（实际只需约 `4 + 2` 条）。P5 将这些全 warp 一致的变量移入每个 warp 共用的 **uniform register**（统一寄存器 `UR`），把 `Q` 与全 `1` 矩阵描述符外提到循环外，同时把每分块一次的 128 线程 `bar.sync` 改为 12 个消费者 warp 各自独立向 `EMPTY` 的 `mbarrier` 报到（省去跨 warp 排队）。实测编译出的非上抬路径每分块指令从 `304` 条降到 **284** 条（分析预估目标约 `269` 条）。当它与第 3 节的 `pre_expert_norm` 跨核融合同轮合并测试时，比上一步提速 **0.60%**，比更早的统一注意力版本（`230.23 ms`）提速 **1.35%**。在图 8-2 中选模式 2（模式 1 读数 `串行 256 步 → 8 个 warp 并行：每个 warp 1 次读 + 1 次 ballot + 1 次 popc` / `ballot+popc+bfind 约 40 周期；单 token 与 8-token 算例合计省 0.62 µs 与 2.46 µs` 见第 7 章第 3 节），读数为：`UR：不上抬路径每分块指令 304 → 284 条（预估目标约 269）` / `与归一化融合同轮合并：比上一步提速 0.60%，比更早的统一注意力版本提速 1.35%`。

- 第三步（第 4–5 级反例与突破：为什么半精度打包指数 `ex2.approx.f16x2` 不能减半 SFU 开销，而用 ALU/FMA 直接生成 `E4M3` 字节能提速 **2.33%**，图 8-3）。在每个 128-key 分块中，每个消费者 warp 原本要发 `64` 条 `MUFU.EX2` 求指数，使 4 通道 SFU（XU 管线）占用率高达 **77.3%**。单是 SFU 一项就锁死了每分块 `1,548` 个周期的下界（初期通过 256 线程命名屏障让 3 个消费者 warpgroup 错开约 22 条 `MUFU` 启动指数阶段，只能缓解争用提速 `0.28%`）。既然半精度二元打包能让算术与转换指令减半，把单精度 `ex2.approx.ftz.f32` 换成半精度打包指数 `ex2.approx.f16x2`，能不能让 SFU 周期减半？
  直接用 `cuobjdump --dump-sass` 检查 `sm_90a` 编译出的机器指令（图 8-3 模式 1），就能看到第 5 级的硬件真相。Hopper 的 4 通道 SFU 只支持标量输入，没有一次算两个半精度指数的打包硬件通道。编译器遇到一行 `ex2.approx.f16x2` 时，会在底层把它拆成 **2 条串行的 `MUFU.EX2.F16` 指令**，后面再跟 **1 条走 ALU 的 `PRMT` 字节重排指令**（不带 `.ftz` 的 `ex2.approx.f32` 还会被额外包上比较与乘法修正指令，具体附加条数未记录，只有 `ex2.approx.ftz.f32` 才编译成裸的 1 条 `MUFU.EX2`）。
  真正卸下 SFU 负担的做法，除了第 7 章图 7-5 的惰性重缩放（图 8-3 模式 2）外，是在 P5 中直接跨管线生成 `FP8 E4M3` 编码（图 8-3 模式 3）。因为注意力权重 `P = 2^y` 紧接着就要量化成 1 字节 `E4M3` 送进 `QGMMA` 算 `P · V`，而 `2^y` 的 `E4M3` 无符号字节值近似等于线性映射 `8(y + 7)`（3 位尾数自然实现 Mitchell 分段线性近似 `2^f ≈ 1 + f`），P5 直接在空闲的 FMA 与 ALU 管线上用饱和乘加（`FFMA.SAT` 将 `y` 映射到 `u = (y + 7) / 15`）、打包半精度乘加（`n = 120u`）与 `PRMT` 字节提取一步算出 `E4M3` 权重字节。行求和 `l` 仍用同一批 `P` 字节乘全 `1` 矩阵算出，以保持分子分母自洽。这把每个分块的 `MUFU.EX2` 从 `66` 条骤降到 **2** 条（仅留行最大值重缩放）。NCU 实测全长注意力的 XU 管线占用率从 `77.3%` 暴跌至 **0.58%**，单分块周期从 `2,003` 降至 `1,645.6`（`ctx = 65,536` 全长注意力核耗时从 `6,651.9 µs` 降至 **5,471.4 µs**），在全长与滑窗注意力上分别使 P5 整层实测提速 **2.33% 与 0.55%**。图 8-3 的三条读数分别为：`f16x2：2 × MUFU.EX2.F16 + 1 × PRMT，SFU 每个值的时间与 f32 相同` / `SFU 周期按 8/条估算（半精度版未单独实测）；PRMT 多占 ALU 2 周期`、`惰性重缩放：减少 exp2f 的调用次数，而不是改指令` / `P1 32 请求全长 verify：T = 4 省 8.77 µs；T = 6 再省 1.42 µs`、以及 `ALU/FMA 直接生成 E4M3 字节：SFU 32 周期 → 0，发射槽 4 → 约 10（每 4 个值）` / `每个分块 MUFU.EX2 66 → 2 条；整层实测提速 2.33%`。
- 第四步（第 4–5 级：微扰删除实验锁定字节打包链、`f16x2` 行最大值树与 `Q · K^T` 半精度 `F16` 累加）。卸下 SFU 后，第 9 章的微扰删除实验显示，字节打包链与每行 62 条 `FMNMX` 最大值树分别占去全长注意力耗时的 **24.5% 与 9.7%**。P5 紧接着连做三刀手术：
  1. 非规格化数直接舍入打包。把 `FFMA.SAT` 系数乘上 `2^-21`，使 `t = n × 2^-24` 落入半精度非规格化数区间（最小步长恰好等于 `2^-24`）。这样 `cvt.rn.f16x2.f32` 在硬件转换时就能直接把 `n` 舍入为整数，每 4 个值删掉 2 条 `HFMA2` 与 2 条 `MOV`（全长核省 64 条、滑窗核省 96 条 `HFMA2`），使 `ctx = 65,536` 注意力核再省 **78.3 µs**，整层提速 **0.96%**。
  2. 打包 `f16x2` 最大值树与编码合并。把单精度分数先转为 `f16x2`，用打包半精度比较（被 `ptxas` 融合为三输入 `VHMNMX`）求行最大值，再用 1 条带 `1024` 偏置的 `f16x2` 乘加配 `PRMT` 直接抽出 `E4M3` 字节。这使全函数 `FMNMX` 从 `138` 条降至 **14** 条、每分块再省 **28** 条指令，单步使整层提速 **0.60%**（至此 P5 整层相对 SGLang 基线的累积几何平均加速比在排行榜评测中达到最高的 **1.7963 倍**）。
  3. 无掩码分块 `Q · K^T` 直接用 `F16` 累加器。既然 `Q · K^T` 算出的分数马上要转成 `f16x2`，且查询 `q` 已做均方根归一化使内积绝对值 `|S| ≤ 30,464 < 65,504`（绝不超出半精度上限），P5 在无掩码分块上直接调用 `wgmma.mma_async.sync.aligned.m64n128k32.f16.e4m3.e4m3`，让 Tensor Core 直接把结果写成打包 `F16`。这一下删掉了每分块 **34 条 `f32 → f16x2` 转换指令**并释放了 **32 个累加器寄存器**，使全长注意力核耗时再降 **14.5%–16.8%**，单此一项使整层提速 **1.79%**（配合第 1 节的两段式 `K` 锁步尾波切分合计提速 **1.93%**）。

## 3. 阶段 5 到阶段 6 的跨核交接：用矩阵乘行线性性质消掉独立的 `pre_expert_norm` Kernel 与 49.3 MB 显存往返

<!-- FIG ch08-p5-fuse: 图 8-4 画阶段 5（pooler）与阶段 6（专家 gemm1）之间的跨核代数融合数据流（对应 T=3,012 时将独立 pre_expert_norm 的按列乘 gain 与每行 16 个部分平方和拆入 pooler 尾声写出、再由专家 gemm1 读入部分平方和算出 r_m 在累加器尾声完成行缩放，从而省去 49.3 MB HBM 往返与 14 µs 独立 kernel 的算法步）。 -->

注意力输出穿过阶段 3 的 `o` 投影、第一道残差边界与阶段 4 的 `router` 后，在阶段 5（`pooler` 降维投影）与阶段 6（本地专家上投影 `gemm1`）的交界处撞上了一笔巨大的中间激活搬运账。在 P5 基线中，`pooler` 与专家第一层矩阵乘之间夹着一个独立的均方根归一化小 kernel（见第 1 章第 1 节）。它本身不读任何大矩阵权重，却要把整批中间激活从显存读进来、算完归一化再写回显存。
- 公式与代数恒等式拆解：
  - 基线三步：`pooler` 先算出 `x_pool = h @ W_pooler.T`。独立归一化 kernel 对每行 `m` 算出均方根倒数标量 `r_m = rsqrt(mean_k(x_pool[m, k]^2) + 1e-5)`，并写出 `p[m, k] = (x_pool[m, k] * r_m) * (1 + w_pre_expert[k])`。随后专家第一层矩阵乘算 `[h_gate[m, :] | h_up[m, :]] = p[m, :] @ dequant_nvfp4(W13[e]).T`。
  - 跨核线性等价式：均方根归一化包含两步可交换的乘法——先按列乘归一化权重 `gain[k] = 1 + w_pre_expert[k]`，再按行乘该词元的均方根倒数标量 `r_m`。因为紧随其后的专家第一层矩阵乘对每行输入满足严格线性关系，将整行输入 `x_pool[m, :] * gain` 乘上标量 `r_m`，完全等价于先用未乘 `r_m` 的 `xb_gain[m, k] = BF16(x_pool[m, k] * gain[k])` 执行矩阵乘，再在矩阵乘尾声把算出的整行单精度累加器乘上 `r_m`。
- 输入、输出与交接数组变化：
  - 基线中间张量：在 `T = 3,012`（4 请求 × 753 词）算例下，`x_pool [3012, 4096]`（BF16）占 `3,012 × 4,096 × 2 B =` **24.7 MB**（在 `T = 16,384` 下更达 `134.2 MB`，超出 60 MiB L2 容量两倍多）。独立归一化 kernel 读一遍 `24.7 MB` 再写一遍 `24.7 MB`，凭空多出 **49.3 MB** 的 HBM 读写往返（按 `4.8 TB/s` 理论下限为 `10.3 µs`，`T = 3,012` 时实测该独立 kernel 耗时约 **14 µs**）。
  - 改造后交接（图 8-4）：在阶段 5 `pooler` 的写出尾声里，每个沿列分块的 CTA 顺带在单精度下乘上 `1 + w_pre_expert` 写出 `xb_gain [T, 4096]`（BF16），同时写出每行在该列段上的部分平方和 `rs_part [T, 16]`（FP32，每词仅 `64 B`）。阶段 6 的专家 `gemm1` 直接读入 `xb_gain` 与每行的 16 个部分平方和，求和算出 `r_m` 并在 SwiGLU 激活尾声里完成行缩放。
- 实测收益：这一跨核手术彻底删掉了独立的 `pre_expert_norm` kernel 及其 `49.3 MB` 显存往返（扣除 `rs_part` 写出与读入各 `0.19 MB` 共 `0.39 MB` 后，净省显存流量 **48.96 MB**，在 `T = 3,012` 下省去约 `14 µs`），单此一项在 P5 全算例几何平均上提速 **0.23%**。当它与第 2 节的注意力 `UR` 指令瘦身同轮合并测试时，比上一步提速 **0.60%**（比更早的统一注意力版本提速 **1.35%**）。在图 8-4 中切换方式 1 与方式 2，读数分别为：`独立 kernel：多 1 个 kernel、多 49.3 MB 往返` / `T = 3,012 时约 14 µs（下限 10.3 µs）`，以及 `拆入尾声：少 1 个 kernel、少 49.3 MB 往返` / `单项提速 0.23%；合并测试 0.60% / 1.35%`（与第 7 章图 7-10 模式 1 的读数 `独立归一化 kernel：多 1 个 kernel + 49.3 MB HBM 往返` / `T = 3,012 时该 kernel 约 14 µs` 与 `拆入尾声：少 1 个 kernel、少 49.3 MB 往返` / `单项几何平均提速 0.23%；合并测试 0.60% / 1.35%` 完全对应）。

## 4. 阶段 6 与层尾（Prefill 路由专家与收官）：从 Token 分桶重排、RAG 尾块裁剪、Grouped NVFP4 流水线，到 `F2FP` 打包舍入与单通道释放

<!-- FIG ch08-p5-moe: 图 8-5 画阶段 6 Prefill 路由专家（Grouped NVFP4 GEMM）的四步硬件流水线（对应将乱序词元按 32 个本地专家分桶重排并裁剪末尾填充行 RAG 尾块与 77% 空退出网格 a_cap、4-warp 收集线程束配 TMA 权重环与 4 组旋转寄存器保持 wait_group<2> 跨管线重叠、gemm1 SwiGLU 尾声用打包 cvt.rn.bf16x2.f32［F2FP］将 F2F 从 224 条压至 96 条使 XU 管线占用从 5.74% 降至 3.08%、以及单通道释放 done1/done2 消除消费者 MEMBAR.ALL.GPU 的算法步）。 -->

拿到阶段 4 的 `topk_ids [T, 8]`、`topk_weights [T, 8]`（P5 将 `top-8` 改为每行 8 个线程在单 warp 内无共享内存归约，使 `T = 16,384` 的 `top-8` 耗时从 `44 µs` 压到 **23.6 µs**、`T = 3,012` 从 `35.5 µs` 压到 `22.0 µs`）与阶段 5 的 `xb_gain [T, 4096]`、`rs_part [T, 16]` 后，数据流进入阶段 6 的 32 个本地 NVFP4 专家。在预填充下，本卡命中的 `(tok, slot, e)` 对多达数千至上万个（`T = 16,384` 时平均每本地专家 `512` 个词元）。为了让 64 行宽的 `wgmma` 每次都能乘满属于同一个专家 `e` 的词元，必须先在路由对齐核（`route / align`）中把命中同一本地专家的词元索引**分桶重排（permute）**为连续的 `BM`（`64` 或 `128`）行分块。它输出重排索引表 `sorted` 与每分块专家编号 `block_experts`，再送入大型分组矩阵乘（Grouped NVFP4 GEMM，图 8-5）。
- 第一步（第 1 级与第 4 级：RAG 尾块裁剪省掉无效填充行，以及网格上限 `a_cap` 砍掉 **77%** 空退出 CTA）。
  - 分桶对齐会把每个专家的词元数向上补齐到分块高度 `BM` 的整数倍，导致每个专家的最后一个分块混入大量无效填充行（padding），白白消耗 Tensor Core 周期。P5 引入 **RAG 尾块分支**：用一次标量加载检测分块第 `RAG` 行起是否全为填充（保持环槽运算留在统一寄存器 `UR` 内），若是则直接切入更窄的 `RAG / RAG2` 行矩阵乘分支。这把 `T = 753` 下每有效词元对发射的 MMA 行数从 `1.68` 压到 **1.18**（`T = 3,012` 从 `1.27` 压到 `1.08`，`T = 16,384` 从 `1.06` 压到 `1.02`）。在 `T = 753` 下，`gemm1` 耗时从 `211.0 µs` 降至 `189.3 µs`、`gemm2` 从 `119.3 µs` 降至 `105.6 µs`，使 `T = 753` 与 `T = 3,012` 整层直接提速 **4.94% 与 4.32%**（首轮 `T = 16,384` 提速 `0.99%`；配合把满成本分块排在前面、RAG 短尾块排在最后填平尾波的 LPT 映射，在 `T = 753` 上再提速 `1.33%`）。
  - 在 `T = 16,384` 下，若按最坏情况（所有词元的 8 条路由全落本卡，加 32 个专家的填充块）启动 `1,056` 个分块 CTA，统计显示多达 **77%** 的 CTA 一进场发现无有效分块就空转退出，白占派发与启动开销。P5 将 `gemm1` 与 `gemm2` 的主网格截断在 `a_cap = ⌈(2T + 32 × 127) / 128⌉`（`T = 16,384` 时为 `288`）个分块，另派每 SM 1 个持久溢出 CTA 兜底（评测负载中溢出块为 0，仅耗 `1.25 µs`）。这使 `T = 16,384` 的 `gemm1` 从 `2,905 µs` 降至 `2,831 µs`、`gemm2` 从 `1,406 µs` 降至 `1,376 µs`，首轮整层提速 **1.07%**。
- 第二步（第 2–5 级：`T ≤ 1,024` 单核票据融合流水线 vs `T > 1,024` 收集线程束 + 4 组旋转寄存器 `wait_group<2>` 流水线）。
  - 在 **`T = 753`**（`T ≤ 1,024` 过渡区，每专家平均 24 个词元）下，采用 `BM = 64` 的单核票据融合内核（`128` 寄存器，每 SM 驻留 `4` 个 CTA）。把分块高度从 `32` 扩至 `64` 使每 64 个词元对共享一次 4 位权重解码（解码开销减半，Tensor Core 占用从 `40%` 升至 `57%`），并在同一个按票据排序的网格内连续跑完 `gemm1 + SwiGLU + done1 同步 + gemm2`，省去两步之间的启动空隙。主循环内每个 32 位权重字发 1 组 `wgmma` 并保持 `wait_group<1>` 让下一字解码与当前矩阵乘重叠（MMA 等待采样占比从 `36.8%` 降至 `17.8%`）。同时把 2 条左移指令改用走 FMA 管线的 `shl.b32`（`IMAD.SHL`），将 ALU 管线占用从 `55.6%` 压到 `48.9%`；配合预处理异或重排（每 8 个权重解码从 `13` 条减为 `12` 条指令，提速 `0.20%`）以及在每步开头用 8 字节 `LDG` 提前把下一步的 1 字节 `UE4M3` 块缩放码读入寄存器（省去 `cp.async` 等待组与共享内存往返，整层提速 **0.38%**）。
  - 在 **`T = 3,012 / 16,384`**（`T > 1,024` 纯算力区，每专家平均 94 至 512 个词元）下，`gemm1` 采用持久化的 `BM = 128` 线程束分工内核（图 8-5 中间）。因为激活行需按重排索引表 `sorted`（`pair // 8`）离散收集（Hopper 的 TMA 不支持按索引列表收集离散行，见第 3 章第 3 节），专门划出 4 个收集 warp（40 寄存器）用 `cp.async` 按行号收集 `x` 并用 TMA 搬运权重装填 3 套环形缓冲（超前 2 步预取，并通过块完成 `mbarrier` 在消费者跑当前分块尾声时提前预取下一分块）。消费者 warpgroup 则用 **4 套旋转寄存器缓冲**配合 `wait_group<2>` 保持 **2 组寄存器源 `wgmma`（每步 8 条 `m64n128k16`）同时在途**（使首轮分块提速 **4.98%–5.02%**，`T = 3,012` 提速 `1.76%–1.82%`）。紧随其后的下投影 `gemm2` 通过 PDL 在 `gemm1` 收尾期提前进场，并恢复非持久化的 `9,216` 个 CTA 网格（`288 × 32`），靠硬件块调度器把下一个分块动态派给最先空闲的 SM，将核内 SM 空闲时间从静态步长持久核的 `60.3 µs` 压到 **18.6 µs**。
- 第三步（第 4 级：`gemm1` SwiGLU 尾声用 `F2FP` 成对打包舍入卸下 XU 管线，图 8-5 下方）。在预填充专家第一层矩阵乘（`gemm1`）的激活尾声中，每个线程算完 `xb_gain` 行缩放系数 `r_m` 与 `SwiGLU` 后，要把单精度门控与上投影结果舍入为 `BF16`（紧挨着 `128` 条走 4 通道特殊函数与转换管线即 XU 管线的 `MUFU.EX2` 指数指令）。基线逐个调用单值转换，编译出 `224` 条同样走 XU 管线的 `F2F` 指令，使该管线在尾声期间接近 100% 满载。改用成对打包舍入指令（`cvt.rn.bf16x2.f32`，编译为 **`F2FP`**，静态条数从 `56` 增至 `120`，NCU 将其计入 16 通道 ALU 管线）后，`F2F` 指令从 `224` 条降到 **96** 条。NCU 实测该内核的 XU 管线占用率从 `5.74%` 降到 **3.08%**（SM 周期减少 `0.6%`），单改这一项使 P5 整层实测提速 **0.33%**。在图 8-5 中切换 `T = 3,012` 与 `T = 16,384` 两档模式，读数分别为：`T = 3,012：每个专家平均 94 个词元 · 每个有效对 MMA 行数 1.27 → 1.08` / `F2F 224 → 96 条 · XU 管线占用 5.74% → 3.08%`，以及 `T = 16,384：每个专家平均 512 个词元 · 每个有效对 MMA 行数 1.06 → 1.02` / `F2F 224 → 96 条 · 77% 空退出 CTA 被 a_cap 砍掉`。
- 第四步（第 1–5 级：单通道释放 `done1 / done2` 消除消费者 `MEMBAR.ALL.GPU`，并在阶段 7、8 完成层尾收官）。
  - 在 `gemm1` 与 `gemm2` 的分块结尾，原本由消费者 warp 0 执行 `atom.acq_rel.gpu` 发布完成标志，每次都会编译出 `MEMBAR.ALL.GPU + ERRBAR + ATOMG + CCTL`（在 `gemm1` 耗时约 `687` 周期、在 `gemm2` 耗时约 `1,409` 周期），导致整个消费者 warpgroup 在下一分块 `wgmma` 前停顿等待。P5 将 `gemm1` 的 `done1` 释放移交收集 warp 的空闲通道（消费者只做片上 `mbarrier.arrive`），将 `gemm2` 的 `done2` 原子加移交 TMA 生产者通道在发完最后一次加载后执行（单独 `gemm1` 侧移交为噪声，实测收益来自 `done2` 移交及两项合用）。同时在 `gemm2` 尾声无条件执行 `pack_bf16x2` 以消费完所有挂起的 `LDS` 记分牌（将未完成 `LDS` 的释放点从 `24` 处清零为 `0` 处），使整层再提速 **0.16%**。
  - 最后，专家加权汇总输出 `m [T, 4096]` 流经阶段 7（`unpooler` 完整 `8,192` 列）进入阶段 8（层尾门控残差 2 与下一层预归一化）。在 `T > 1,024` 下，边界归一化内核将每线程寄存器上限压至 `64` 个以在每个 SM 驻留 `4` 个 CTA；在 `1,024 < T ≤ 3,012` 时改用 `512` 线程并在第一次归约前把 `x` 与 `s_in` 的全部 16 字节 `LDG.128` 提前并发发出，掩盖 `32.9%–38.9%` 的长记分牌等待（提速 **0.20%**），最终向 HBM 写出更新后的 `(out BF16 [T, 8192], stream FP32 [T, 8192])` 交给第 `l + 1` 层。

---

**带走一句话：** 当单层进入 Prefill（`T = 753` 过渡区至 `T = 16,384` 纯算力区），瓶颈从 HBM 读权重彻底翻转到首轮分块 **4,947–9,758 GFLOP**（按 `989 TFLOP/s` 折合算力耗时 `5,003–9,867 µs`，多轮追加 `T = 753 / 3,012` 下为 `227–1,876 GFLOP`）的 Tensor Core 与执行管线：通过持久线程束分工加 Stream-K 切尾波、注意力统一寄存器 `UR` 降压加 ALU 直接生成 `E4M3` 指数与 `F16` 累加、跨核线性折入消掉 `49.3 MB`（净省 `48.96 MB`）独立 `pre_expert_norm`、以及专家分桶 RAG 裁剪配 4 缓冲 `wait_group<2>` 与 `F2FP` 打包舍入（同时避开 `ex2.approx.f16x2` 伪打包反例），才能在算力受限区跑满整张 H200。
