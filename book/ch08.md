# 第 8 章 [Part II · 阶段 6]：路由 NVFP4 混合专家——从 2.27 秒到 6 毫秒及 Prefill 大分块的五代演化（m0 → m5）

**本书地图：** 第 0.0 章 → 第 0 章 → 第 0.5 章 → 第 1 章 [第 0 级] → 第 2 章 [第 1 级] → 第 3 章 [第 2 级] → 第 4 章 [第 3 级] → 第 5 章 [第 4 级] → 第 6 章 [第 5 级] → 第 7 章 [阶段 2：分页注意力] → **【第 8 章：阶段 6 路由 NVFP4 混合专家】** → 第 9 章 [整层总装] → 第 10 章 [性能诊断法]

承接第 7 章末尾的问题：阶段 2 的分页注意力交出 `o_attn [T, 1024]` 后，数据流经阶段 3 的输出投影与第一道门控残差，在阶段 4（`router` 路由打分与 Top-8 选择）与阶段 5（`pooler` 降维投影）处并联分叉，最终汇入单层权重体积最大的阶段 6——32 个本地 NVFP4 路由混合专家（MoE，总权重 `906 MB`）。为什么参考实现跑完 6 个解码与检验算例的几何平均耗时高达 `2,270,104.65 µs`（2.27 秒），我们又如何顺着词元数从 `M = 1` 到 `T = 16,384` 的物理区间迁移，用五代内核架构跃迁（`m0 → m1 → m2 → m3 → m4a/m4b → m5`）把它一步步推向 `~6,033 µs` 与预填充算力极限？

在进入第一代跃迁前，先锁定阶段 6 的完整算法解剖与物理区间边界：
- **公式**：在 8 卡专家并行（EP8）下，本卡驻留 32 个本地专家 `[local_start, local_start + 32)`。对每个命中的本地 `(tok, slot, e)` 词元-专家对依次执行五步：
  1. 门控与上投影融合矩阵乘：`[h_gate | h_up] = p[tok] @ dequant_nvfp4(W13[e], sf13[e], gs13[e]).T`（`[4096] → [8192]`，前 `4,096` 列为门控 `h_gate`，后 `4,096` 列为上投影 `h_up`）。
  2. 门控激活（SwiGLU）：`inter = silu(h_gate) * h_up`（`[4096]`）。
  3. 下投影矩阵乘：`y = inter @ dequant_nvfp4(W2[e], sf2[e], gs2[e]).T`（`[4096] → [4096]`）。
  4. 每专家独立后归一化（在加权求和之前逐对执行）：`y_norm = rmsnorm(y * (1 + w_post_expert), 1e-8)`。
  5. 按路由槽位权重加权累加：`m[tok] += topk_weights[tok, slot] * y_norm`（未命中本卡任何专家的词元输出全 0）。
- **输入**：降维并归一化后的激活 `p [T, 4096]`（BF16，每词 `8 KiB`，位于 HBM 或 L2）、全局选中专家编号 `topk_ids [T, 8]`（`int32`）、归一化路由权重 `topk_weights [T, 8]`（FP32），以及本卡 32 个专家的 NVFP4 权重：`W13 [32, 8192, 2048] uint8` + 块缩放 `sf13 [32, 8192, 256] FP8 E4M3` + 全局缩放 `gs13 [32] FP32`，与 `W2 [32, 4096, 2048] uint8` + 块缩放 `sf2 [32, 4096, 256] FP8 E4M3` + 全局缩放 `gs2 [32] FP32`（每权重 `0.5 B` 码字 + `0.0625 B` 缩放 = `0.5625 B`，单专家 `50.33M × 0.5625 B = 28.3 MB`，32 个本地专家共 `906 MB`，常驻 HBM）及后归一化权重 `w_post_expert [4096]`（BF16）。
- **输出与交给下一步**：加权汇总后的专家激活 `m [T, 4096]`（BF16，每词 `8 KiB`，写回 HBM 或 L2），交给阶段 7 的 `unpooler` 升维投影（第 9 章第 2 节）。
- **单步代价与 58 词元平衡点**：每对 `(tok, e)` 执行 `2 × 3 × 4096 × 4096 = 100.7 MFLOP`，权重复用为 1 时算术强度仅 `2 ÷ 0.5625 = 3.56 FLOP/B`。要跨过 H200 的 `206 FLOP/B` 平衡点（第 0 章第 3 节），**同一个本地专家至少要在一个批次内分到 `206 ÷ 3.56 ≈ 58` 个词元**：
  - 在 Decode（`M = 1, 16, 32`）与 Verify（`M = 8, 128, 256`）全部 6 个负载下，即便到最大的 `M = 256`（最忙卡 390 个本地命中对落在约 `24.6` 个专家上），每个激活专家平均也只分到约 `16` 个词元（`< 58`），因此前四代演进（`m0 → m4b`）全程受 HBM 权重读取、波次尾与同步延迟限制（6 档负载物理下界分别为 `11.4 / 52.5 / 70.8 µs` 与 `37.3 / 101.3 / 108.9 µs`）。
  - 进入 Prefill（`T = 753, 3,012, 16,384`）后，均匀路由下每专家平均词元数 `T ÷ 32` 从 `T = 753` 的 `24` 个（过渡区）跃升至 `T = 3,012` 的 `94` 个与 `T = 16,384` 的 `512` 个（`> 58`），第五代内核（`m5`）全面转入区间 III 的 Tensor Core 算力与管线战（32 专家全读上限 `188.7 µs`，而 `T = 16,384` 算力下界达 `1,668 µs`）。

为什么参考实现（`m0`）跑完 6 个算例的几何平均高达 `2,270,104.65 µs`？因为它在 Python 循环里逐个遍历专家：对每个命中的专家，先启动独立内核把 `28.3 MB` 的 NVFP4 权重反量化成 `100.7 MB` 的稠密 BF16 大矩阵写回 HBM，再调用矩阵乘读回来计算。这不仅制造了数百次内核启动空隙（第 1 章第 1 节），还让 HBM 反复读写膨胀了 `3.56` 倍的反量化权重。

第一代跃迁（`m0 → m1`）做出第一个核心架构决策：**用单次启动的分组专家矩阵乘（Grouped Expert GEMM）取代逐专家循环，并将 4 位反量化锁在片上寄存器内完成**。主机端先把命中同一本地专家的 `(tok, slot)` 对分桶排好，随后单次启动分组矩阵乘内核：所有命中专家的分块在同一网格内并行派发，`0.5625 B/权重` 的压缩码字与块缩放从 HBM 读进片上后当场还原为 `BF16` 送入矩阵管线，全程不再向 HBM 写出任何反量化权重。仅这一步，6 个算例的几何平均耗时就从 `2,270,104.65 µs` 暴降 `79.5` 倍至 **`28,554.36 µs`**；紧接着将门控与上投影按 `32 + 32` 行交错排布（使同一输出行的门控与上投影落在同一个分块内）、改用无分支位运算解码并加上早期编程依赖启动（PDL，机制见第 1 章第 2 节与第 6 章第 3 节），几何平均进一步降至 **`21,369.20 µs`**。
- **取舍（得到 vs 付出 vs 何时亏本）**：分组矩阵乘消除了逐专家启动空隙与 `3.56×` 的 HBM 权重膨胀（6 格几何平均省 `2,241.5 ms`）；付出的代价是必须在矩阵乘前维护固定形状的词元-专家分桶索引表，且交错排布约束了离线权重布局（单独寄存器与 SMEM 变化未测）；在全部 6 个评测算例上无条件稳赢。

进入第二代跃迁（`m1 → m2`），切入基于寄存器源 `wgmma` 的分块流水内核（Gluon）后，小批量下首先暴露出第 1 级与第 2 级的两道硬件瓶颈：一是下投影 `GEMM2` 的输出列数（`4,096`）比上投影（`8,192`）少一半，在 `M ≤ 32` 时分块数填不满 132 个 SM；二是片上环形缓冲深度与每 SM 驻留 CTA 数之间存在尖锐的波次冲突。
- 先按第 2 章第 1 节与第 3 章第 4 节的通用机制补齐在途并行度：对 `M ≤ 32` 的下投影启用 `Split-K`（`M ≤ 8` 切 4 份、`M ≤ 32` 切 2 份）并将部分和平面存为 `BF16` 交由后归一化核顺带归约，使 6 算例几何平均从 `18,057.2 µs` 降至 **`17,362.60 µs`**（在 `decode 16` 上 `GEMM2 Split-K = 2` 省 `1.38 µs`，而切成 4 份因归约流量翻倍反慢 `+3.26 µs`）；同时为权重挂上 3 槽 `cp.async` 环形缓冲（`decode 16 / 32` 敲除实验省 `5.25 / 5.70 µs`，`verify 1` 省 `8.45 µs`）或 2 槽纯权重环（`verify 32 / 16` 省 `18.94 / 4.64 µs`）、每步消费 `2 × BK = 256`（`decode 32` 省 `3.20–5.84 µs`）与块缩放双射合并拷贝（`verify 16 / 32` 省 `3.38 / 1.50 µs`，机制均见第 3 章第 1–4 节）。
- **波次边界定律（为什么同一个驻留/环深改动在不同路由种子上正负反转？）**：在稠密矩阵乘里，矩阵形状是固定的；但在 MoE 中，**每个随机路由种子命中的本地活跃专家数 $A$ 不同，全卡总块数 `A × 每专家 CTA 数` 随之浮动**。当某项改动（如减少寄存器或调整环深）使每 SM 驻留从 $k$ 升至 $k+1$ 个 CTA 时，唯有当该种子的 `A × 64` 个 CTA 恰好因此从 **2 个波次跨入 1 个波次**（跨过 `132 × (k+1)` 台阶）时才会大赢；在未跨过波次边界的种子上，更浅的缓冲或更高的每 SM 争抢反而使耗时变慢！例如在 `decode 32` 的 5 个路由种子上，同一项驻留调整分别测出 `+3.41 / +5.71 / +6.83 / -7.12 / -11.87 µs` 的两极分化；在 `verify 1`（`M = 8`）上把 `mma.sync` 换成 `wgmma`（机制见第 5 章第 3 节）因每 SM 驻留从 `9` 掉到 `8` 个 CTA，使 $A = 9$ 的两个种子从 1 波掉进 2 波，单种子暴跌 **`+10.43 µs` 与 `+11.41 µs`**。这直接确立了 MoE 优化的**全种子铁律**：任何改动必须在全部 5/5 路由种子上同时不退化才能合入；在 `M = 1 / 16` 下开启权重环必须用编译器指令把驻留死死钉在 `6` 或 `7` 个 CTA/SM（不钉住驻留时 `decode 1` 慢 `+4.18 µs`、`decode 16` 慢 `+2.13 µs`；反之若用 `__maxnreg__(56..80)` 强压寄存器，触发 2–18 个寄存器溢出到局部内存，在 `verify 32` 上暴跌 **`+26.43..+61.79 µs`**，见第 3 章第 1 节）。

在钉死驻留与波次之后，第二代内核（`m2`）迎来了 MoE 独有的第二个核心机制突破：**RAG 不规则专家尾块动态裁剪（Ragged Tail-Tile Trimming）**。分桶路由要求每个分块内的词元属于同一个专家，因此每个专家的词元数必须向上补齐到分块高度 `BM`（如 `32` 或 `128` 行）的整数倍。在偏斜路由下，大量轻专家只分到几个词元，或者重专家的最后一个尾块只剩寥寥几行有效数据，其余全是空白填充行（padding）——但 `wgmma` 却照样为这些填充行空转矩阵周期并重复读取整块专家权重！
- **机制与解剖**：`m2` 在分块入口检查当前专家块的实际有效词元行数，对不足满块的尾块动态下调分块高度 `BM`（`BM 32 → 16 → 8` 三级台阶，在 `M = 128` 上启用三级裁剪；在第五代预填充 `T = 753..16,384` 中同样用一次标量加载检测第 `RAG` 行起是否全为填充，直接跳入窄行矩阵乘分支，见图 8-1 中间）。
- **取舍（得到 vs 付出 vs 什么时候变成亏本）**：
  - **得到什么**：彻底省去轻专家尾块的无效填充行计算与权重重读。在 `verify 32`（`M = 256`）上，引入 `RAG 16` 单项实测缩短 **`25.68 µs`**（置信区间 `[-26.08, -24.42] µs`，5/5 种子全胜且比特级恒等），叠加下投影与 `M = 128` 三级裁剪后在 `verify 16 / 32` 上再省 **`8.08 / 7.12 µs` 与 `6.37 µs`**；在预填充 `T = 753 / 3,012 / 16,384` 上，它将每个有效词元对发射的 MMA 行数从 `1.68 / 1.27 / 1.06` 压到 **`1.18 / 1.08 / 1.02`**，使 `T = 753 / 3,012 / 16,384` 整层直接提速 **`4.94% / 4.32% / 0.99%`**。
  - **付出什么**：核内需生成多套窄分块模板分支，并在分块入口增加一次有效行数判定；在预填充中必须使用标量加载配合统一分支，才能让环槽计数留在统一寄存器 `UR`（第 7 章第 4 节）中（若改用块内归约统计有效行数，会导致环槽算术退回私有向量寄存器，每步 `K` 凭空多出 **34 条指令**）。
  - **什么时候变成亏本（反例：盲目扩大分块高度 `BM` 或虚拟轮单位 `TT`）**：分块高度 `BM` 的选择严格取决于每专家平均词元数。当把预填充 `T = 753`（每专家平均 24 个词元）的分块从 `BM = 32` 扩至 `BM = 64`（配消费者发 TMA 权重环）时，每 64 个词元对共享一次解码使 Tensor Core 占用率从 `40%` 升至 `57%`、整层提速 **`3.87%`**；但若在同一个 `T = 753` 上盲目继续扩到双消费者 warpgroup 的 **`BM = 128`**，由于 24 个词元远填不满 128 行，填充浪费反噬使滑窗与全长分别跌至 `0.9495×` 与 `0.9782×`（总分**倒退 `-1.39%`** 被否决）。同理，在小批量 `decode 16 / 32` 的第三代内核上，若无条件把虚拟轮处理粒度从 8 对（`TT = 1`）扩成 **16 对（`TT = 2`）**，单步指令数暴涨 **`+16%`** 且在活跃专家数 $A$ 较大的种子上拖出长尾，实测反慢 **`+1.71 µs`（`decode 16`）与 `+2.54 µs`（`decode 32` 重 $A$ 种子）** 被否决。

为什么第二代分块流水核（`m2`）在 `M = 1..32`（`decode 1/16/32` 与 `verify 1`）下还会留下十多微秒的差距？因为在 `m2` 中，路由分桶、上投影 `W13` 与下投影 `W2` 分属不同内核启动：每次启动都要经历波次量化，且中间激活在 HBM/L2 之间折返读写（即便在 `M = 1/8` 改用少于 SM 数的有界持久网格消去空 CTA 启动尾，省下 `1.22 / 7.60 µs`，並在 `M = 1` 删掉独立路由核、用最后到达者原语内联归约省下 `1.12 / 1.42 / 0.86 µs`［见第 1 章第 1 节］及按活跃专家数 $A$ 自适应选择 `Split-K = 2/3` 省下 `2.05 µs`［见第 2 章第 1 节］，在 `M = 8..32` 上多核折返依然存在）。

第三代跃迁（`m2 → m3`）做出核心架构决策：**切换为 132-CTA 全卡持久权重驻留内核（`M20`），把核内路由（Phase 0）、上投影与 SwiGLU（Phase A）、下投影（Phase B）装进同一套按 8 对词元为单位（8-pair virtual pass）的 TMA 权重流引擎，并在 `M = 8..32` 下进一步将 Phase A 与 Phase B 从全网格栅栏拆成两个 PDL 串联持久核**。
- **机制与解剖**：
  1. **从多核分块到 `M20` 8 对虚拟轮持久核，再到双核 PDL 串联**：在 `verify 1`（`M = 8`）上，单次启动的 `M20` 持久协作核用 TMA 环形缓冲流式搬运权重驻留单元、在核内直接完成路由与上下投影，彻底消除了多核波次量化，单步实测直降 **`15.73 µs`**（官方总分从 `2.0160×` 跃升至 `2.0854×`）。当扩至 `decode 16 / 32`（`M = 16 / 32`）时，命中超过 8 对的热门专家被切成每轮 **8 对词元的虚拟轮（8-pair virtual pass）** 配合 8-warp 尾声轮转与 8-warp `__ballot_sync + __popc` 位图并行路由（约 `40` 周期代替 256 步串行扫描，在 `M = 1 / 8` 省 `0.62 / 2.46 µs`，机制见第 4 章第 4 节），在 `decode 16 / 32` 上再砍 **`20.29 µs` 与 `7.70 µs`**（总分升至 `2.1963×`）。随后按第 1 章第 3 节机制，在 `M = 8 / 16 / 32` 下把 Phase A 与 Phase B 中间耗时 `1,419 ns`（`1.42 µs`）的全网格栅栏（`grid.sync()`）拆成两个 PDL 串联核，让 Phase B 在等待前预载权重环（在 `decode 16 / 32` 重叠 `5–11 µs`），净省 **`0.37 / 0.70 / 0.82 µs`**（而在 `M = 1` 下因无尾波失衡保持单核协作，并为权重流标上 `evict_first` 防止冲刷 L2 中的激活，省去 `+2.44 µs` 退化，见第 2 章第 3 节；同时在 `M = 1` 命中专家 `≤ 3` 时按 `blockIdx.x + 132 j` 轮转派发省 `0.66 µs`，在 `M = 16 / 32` 对晚启动的 `100..131` 号 CTA 按二次曲线少分 Phase-B 单元省 `0.27–0.31 µs`，详见第 3 节）。
  2. **冷启动显存队列解耦（`gs` 预载 + 激活 `x` 先于权重 TMA 发出 + `500–600 ns` 错峰）**：剖析 `M20` 入口时间戳发现，普通全局加载（`LDG`）与硬件 TMA 共享同一个 DRAM/L2 请求队列。若在序言里先连发 3 槽权重 TMA（全卡瞬间涌入约 `14 MB` 权重请求），紧随其后发出的激活 `x` 读取就会排在 `14 MB` 权重洪峰后面苦等 **`0.96 µs`**（在大批量核冷启动第 0 段上，排队使激活收集耗时从热态的 `0.7–1.4 µs` 暴涨到 **`5.3 µs`**）！`m3` 立即倒转启动顺序：在 Phase 0 把 64 个浮点全局缩放系数（`gsA / gsB`，`256 B`）预载入共享内存（将每次尾声查询从 `328` 周期的 L2 命中压到 `23` 周期的 `LDS`，SASS `LDG` 从 `36` 条降至 `21` 条，在 `verify 16 / 32` 省 `0.47 / 0.55 µs`；同时将共享内存路由直方图行宽从 32/64 字填充为 **33 字**奇数行宽消除 32 路 bank 冲突并单次读 `topk_ids`，在四个 verify 形状上省 **`1.28–7.49 µs`**，见图 8-2 读数：`32 字行宽：32 路 bank 冲突，读 1 列 = 32 轮` / `读 32 列 = 1,024 轮 · 表占 4,096 B`、`64 字行宽：32 路 bank 冲突，读 1 列 = 32 轮` / `读 32 列 = 1,024 轮 · 表占 8,192 B`、以及 `33 字行宽：读 1 列 = 1 轮，读 32 列 = 32 轮` / `实测 P3 省 1.28–7.49 µs（0.6%–2.1%）`），接着**先发出激活 `x` 的 `LDG` 与第 0 槽权重 TMA，再用 `%globaltimer` 将第 1、2 槽权重 TMA 延迟 `500–600 ns` 错峰发出**，最后用 `__maxnreg__(144)` 限制 `M = 1` 主核寄存器使 110 寄存器的后归一化 CTA 能同 SM 共驻提前进场。在 `decode 1` 上，这套启动解耦在 **360/360 个种子上全胜**，实测省下 **`1.055 µs`**（分项：`gs` 预载 `-0.41 µs`、`x` 提前 `-0.71 µs`、错峰 `-1.05 µs`，共驻再省 `0.080 µs`），在 `verify 1` 拆分核上省 **`0.755–0.82 µs`**。
  3. **后归一化（`pn`）内核的 `ptxas` 防下沉与防重物化（图 8-3）**：后归一化通过 PDL 挂在专家主核之后（省 `0.31–0.93 µs`，见第 1 章第 2 节），并对输入做 2 组 × 4 路流水加载（省 `0.75 µs`）。但检查 SASS 反汇编抓出两处编译器暗箱退化：一是序言里写在 `ACQBULK`（`griddepcontrol.wait`，第 5 条 SASS）之前的只读加载 `ld.global.nc` 被 `ptxas` 全部下沉到了 `ACQBULK` 之后，改用 `volatile` 普通全局加载内联汇编将 6 条 16 字节预取（`LDG.E.128`）锁回 `ACQBULK` 之前后，在 `decode 1 / 16 / 32` 与 `verify 1` 上实测省下 **`0.45 / 0.67 / 0.41 / 0.27 µs`**；二是循环外预计算的 16 个 `nw[i] = 1.0f + norm_w[i]` 被 `ptxas` 为省寄存器拆回 2 相 × 8 槽内层循环重复计算（多出 `321` 条 `FADD`），加上一行零运行时开销的空内联汇编 `asm volatile("" : "+f"(nw[i]));` 后，静态 SASS 指令从 `1,603` 条骤降至 **`1,120` 条**（净省 **483** 条），在 `decode 1 / 16 / 32` 上实测省下 **`0.21–0.30 µs`**（图 8-3 读数分别为：`volatile 加载：6 条 16 B 预取排在 ACQBULK 之前，恢复预读重叠` / `普通 .nc 加载被 ptxas 下沉到 ACQBULK 之后，PDL 预读失效`、`空 asm：PN 的静态 SASS 1603 → 1120 条（少 483 条）` / `H200 实测省 0.21–0.30 µs（decode 1/16/32）；运行期不生成指令`、以及 `8 条整数指令（2 SHF + 2 IMAD.SHL + 4 LOP3）+ 4 条 HMUL2，无分支` / `ALU、FMA 管线各 12 周期；P3 异或解码几何平均提速 0.58%，最高 1.01%（解码 32 请求滑窗）`）。

- **取舍与什么时候变成亏本（反例）**：
  - **8 对虚拟轮与错峰窗口的 U 型边界**：8 对虚拟轮让超过 8 对的热门专家每轮重读一次权重；而错峰延迟若在 `M = 8` 上从 `600–800 ns`（省 `0.755–0.840 µs`）拉长到 **`1,200 ns`**，会因人为推迟权重供应而回退到 `-0.425 µs`（在 `M = 32` 上错峰仅 `-0.247 µs`，落入副本噪声带故设为 `0 ns`）。
  - **后归一化预取在 `M > 32` 反输与无分支加载膨胀**：在 `M > 32`（`verify 16 / 32`）下，前序持久专家核占满全部 132 个 SM，后归一化核在 `ACQBULK` 前根本没有共驻重叠窗口，开启 `volatile` 预取反而**变慢 `+0.45 µs`**（故严格门控在 `M ≤ 32`）；而在后归一化中若把 2 组流水加载改成宽幅无分支加载（`pnp`），每线程寄存器从 `64` 暴涨至 `128+` 掉驻留，在全部 6 个负载上反慢 **`+0.43..+0.90 µs`** 被否决。
  - **预填充 `T = 753` 尾声提前读 `sorted` 与块写出被拒**：在 `T = 753` 的单核融合专家中，尝试将尾声的 `sorted` 索引读取和块写出提前（Hoist），但因 `sorted` 原本就命中 L1 缓存，且提前块写出迫使环槽释放等待块写出排空，实测在滑窗与全长算例上**反而变慢**被否决。

## 3. 第四代跃迁上篇（m3 → m4a，Verify 大批量 M = 128..256）：M20-WGS 18-Warp 持久 wgmma 引擎、LPT 动态领活、按秩逆序分配与尾部 K-halves

为什么第三代 `M20` 内核（`m3`）在 `M ≤ 32` 下大获全胜，到了 `verify 16 / 32`（`M = 128 / 256`，全卡 191 至 390 个本地词元-专家对）却跑不过分块大核？因为在 `M = 256` 下，平均每个命中的本地专家分到约 16 个词元（热门专家高达几十个词元）：若仍按 `M20` 的 8 对虚拟轮切分，同一个热门专家的 `28.3 MB` 权重会被反复重读 3 到 6 遍，且单 warp 的 `mma.sync` 远不如 4-warp 协同的 `wgmma` 高效；而若退回第二代的 4 核分块方案（路由核 + 上投影核 + 下投影核 + 后归一化核），4 次独立启动之间的 L2 折返与波次尾又会白白烧掉二十多微秒。

第四代跃迁上篇（`m3 → m4a`）做出核心架构决策：**在 `M = 128..256` 下合体为单次启动的 18-Warp 持久寄存器源 `wgmma` 内核（`M20-WGS`），让 132 个持久 CTA 围绕同一条全局子任务队列，连续跑完核内 33 字直方图路由（Phase 0，见第 2 节）、`64 × 256 × 256` 上投影加 SwiGLU（Phase A）与下投影（Phase B），并用四项跨 SM 均衡技术抹平轻重专家混杂造成的长尾**。
- **机制与解剖**：
  1. **18-Warp 持久 `wgmma` 引擎（`M20-WGS`）取代 4 核分块**：每个持久 CTA 配置 `576` 个线程（4 个消费者 warpgroup 共 512 线程并发执行 `BM = 64, BN = 256` 的寄存器源 `wgmma`，配 2 个专职生产者 warp 分别负责 TMA 权重环与 `cp.async` 激活收集；由于 `4 × 128 × 232 = 118,784 > 65,536` 超出单 SM 寄存器总池，无法照搬 3-warpgroup 的 232 寄存器分账，故采用每线程 `96` 寄存器的统一上限，机制见第 3 章第 1 节）。热门专家的最多 64 个词元一次性装进同一个 `64 × 256` 瓦片，权重只从 HBM 读 1 遍，中间激活 `h` 留在 L2/全局平面内由 Phase B 直接消费。在 `verify 32`（`M = 256`）上，单次启动的 `M20-WGS` 比 4 核分块方案直接缩短 **`22.54 µs`**（从 `261.15 µs` 压至 **`241.58 µs`**，置信区间 `[-23.23, -21.57] µs`）。
  2. **从双指令蛇形（Snake）到 LPT 降序排列，再到 `T = 128` 原子动态领活**：持久核的总耗时由 132 个 CTA 中**最晚退出的那 1 个 CTA** 决定。由于开启了第 1 节的 RAG 尾块裁剪，一个 `npad = 64` 的重子任务与一个 `npad = 8` 的轻尾块（单活耗时 `17.15 µs`）执行时间相差悬殊：
     - **LPT（最长处理时间优先）降序排列**：把所有子任务按填充后词元数 `npad` 从大到小排序（满块排最前，`npad = 8` 的短尾块排最后用来填齐最末波空隙，实测全卡 CTA 结束时间极差为 `15.84 µs`），在 `verify 16 / 32` 上比未按大小排序实测省下 **`1.40 µs` 与 `2.32 µs`**（在第五代预填充 `T = 753` 上用 LPT 将满成本块排前、RAG 短尾块排后，同样使整层再提速 **`+1.33%`**）。
     - **`T = 128` 生产者原子动态领活**：在 `T = 128`（`verify 16`）下，静态步长分配会让 `108` 个 CTA 分到 `6` 个子任务、其余 `24` 个 CTA 只分到 `5` 个子任务，导致这 24 个 SM 在最后约 `17 µs` 里空转。改为让每个 CTA 的权重生产者 warp 在当前子任务内通过原子递增（`atomicAdd`）按 LPT 顺序动态认领下一个子任务后，132 个 SM 的退出时间被动态拉齐，使 `verify 16` 滑窗与全长整层分别提速 **`+1.67%` 与 `+0.65%`**（为什么第 7 章第 2 节注意力动态偷取反慢 `+22.6 µs` 而这里稳赢？因为注意力单瓦片仅 `< 1 µs`，原子同步与排空环占去 `10%`；而 MoE 单个子任务长达 `~17 µs`，远大于一次原子领活开销！）。
  3. **按 Phase-A 负载秩逆序分配 Phase-B（消除同 CTA 重叠长尾）与尾部 66 活 K-halves 切半**：
     - **按秩逆序分配（Reverse-Rank Deal）**：早期 Phase A 与 Phase B 共用同一条蛇形序列领活，结果**最重的 Phase-B 下投影恰好落在了刚刚跑完最重 Phase-A 上投影的那批 CTA 上**，造成 `9–52 µs` 的木桶长尾！改为统计各 CTA 在 Phase A 的实际负载秩（Rank），让 Phase A 最轻的 CTA 优先认领最重的 Phase B 子任务（正逆配对），一举将 `verify 32` 滑窗与全长最慢 CTA 的退出时间从 `189.4 / 215.0 µs` 压到 **`176.3 / 195.0 µs`**，核尾提前 **`2.6 / 13.1 / 20.0 µs`**（对应 `verify 16` 滑窗 / `verify 32` 滑窗 / `verify 32` 全长），使 `verify 32` 滑窗与全长整层实测飙升 **`+5.2%`（20/20 全胜）与 `+1.47%`**！
     - **尾部 66 活 K-halves 对半切分与小批量派发微调**：当最后一轮剩余子任务数 `r ≤ 66`（不到 132 个 SM 的一半）且倒数第 5 个子任务为 `npad = 8` 时，将最后 66 个 Phase-B 子任务沿 `K` 维对半切成 `2 × 66 = 132` 个半程活（前半 `stages 0..7` 写 FP32 部分和并立标志，后半 `stages 8..15` 等标志累加，机制见第 2 章第 1 节），在 `verify 16 / 32` 上平均省 **`0.54 / 1.95 µs`**（在 `r = 12` 的种子上狂省 **`4.53–5.07 µs`**）。而在小批量 `M20` 侧，如第 2 节预告：当 `M = 1` 活跃专家 `nact ≤ 3` 时按 `blockIdx.x + 132 j` 轮转派发 Phase-A 单元使 132 个并发 TMA 在显存上紧邻，分块节拍从 `1.21 µs` 缩至 `1.10–1.15 µs`（`decode 1` 省 **`0.664 µs`**）；在 `decode 16 / 32` 拆核后，针对按 `blockIdx.x` 顺序最后进场、比前序晚 `~2 µs` 启动（在 `62% / 81%` 种子中沦为最慢块）的 `100..131` 号高编号 CTA，按二次曲线少分 Phase-B 单元（省 **`0.27 / 0.31 µs`**，机制见第 2 章第 2 节）。

- **取舍与什么时候变成亏本（反例）**：
  - **`M = 128` 下 256 列宽块的 `2.66` 波次尾与轮询栅栏代价**：在 `verify 16`（`M = 128`）上直接套用 256 列宽的 `M20-WGS` 时，22 个子任务 × 16 个分块 = `352` 个块，在 132 个 SM 上折合 **`2.66` 个波次**，多出的 `+18 µs` 分数波次尾吃掉了单块收益（实测 `[-0.26, +4.35] µs` 打平）；若在 Phase B 每阶段加轮询栅栏（`PB_POLL = 1`），更会直接倒退 **`+5.8..+9.0 µs`**。
  - **无门控开启尾部切半或块索引倾斜反输**：尾部 K-halves 在尾波已满（不触发切分）的种子上会因分支与标志检查慢 **`+0.52..+0.75 µs`**，故必须严格门控在 `r ≤ 66`；同様に，Phase-B 的 `blockIdx ≥ 100` 二次倾斜若在**不含重型双倍分块（`TT = 2`）**的种子上无条件开启，会把过多工作推给前序 CTA，实测反慢 **`+0.42 / +0.49 µs`**；而在预填充 `T = 16,384`（32 个专家全满块）上开启 LPT 映射则因无短尾块可填而微退至 `0.9987×`。

**演化收尾（`m3 → m4a`）：** 第四代上篇 `m4a` 在 `M = 128..256` 下切入 18-Warp 持久 `wgmma` 引擎 `M20-WGS`（`verify 32` 省 `22.54 µs`），叠加 LPT 降序（省 `1.40–2.32 µs`）、`T = 128` 原子动态领活（`+1.67%`）、按 Phase-A 秩逆序分配 Phase-B（核末提前 `20.0 µs`，`+5.2%`）与尾部 66 活 K-halves（省 `1.95 µs`），将大批量专家的跨 SM 波次尾与负载失衡彻底削平。
