# 第 2 章 [第 1 级]：整张 H200 芯片——132 个 SM 怎样铺平波次、喂饱 HBM 并在中央 L2 归约？

**本书地图：** 前言 → 第 0.0 章 → 第 0 章 → 第 0.5 章 → 第 1 章 [第 0 级] → **【第 2 章 [第 1 级]：整张 H200 芯片】** → 第 3 章 [第 2 级] → 第 4 章 [第 3 级] → 第 5 章 [第 4 级] → 第 6 章 [第 5 级] → 第 7–10 章

承接第 1 章末尾的问题（第 1 级：整张芯片）：第 1 章把单层启动从约 17 次压到 11 次，但 `qkv_gemm g1a` 去掉第二次启动后在 `T = 256` 反而比 cuBLAS 慢了 `10.50 µs`。把时间线上代表单个 kernel 的条块横向剖开，如何让全卡 132 个 **SM**（Streaming Multiprocessor，流式多处理器——执行指令的计算单元）同时干完活、挂起足够的在途字节喂饱 4.8 TB/s **HBM**（高带宽显存），并在中央 **L2 cache**（二级缓存，60 MiB）上安全高效地合并跨 SM 的部分和？

在一句话流过单层八个阶段（第 0 章）时，第 1 章时间线上的每个阶段 kernel 都要派发到全卡 132 个 SM 上并行执行。这包括阶段 1/3/4/5/7 的稠密投影（如 `qkv_gate` 2,304 行、`pooler` 4,096 行）、阶段 2（分页注意力拆分块）和阶段 6（本地专家 CTA）。因为 132 个 SM 共享中央 60 MiB 的 L2 缓存从 HBM 读权重，且跨 SM 切开的半行或分片必须在 L2 汇合后才能把输出交给下一阶段，本章第 1 级决定了整卡波次排布、派发顺序、单 SM 在途字节门槛，并且是全书唯一讲解跨 SM 经中央 L2 归约四种原语的章节。

## 1. 132 个 SM 上的 Wave（波次）、Tail（尾波）与非整除 Split-K 切分

**本节要回答的问题：** 为什么 2,304 行 `gemv` 的最后 192 个 CTA 或 `qkv_gate` `T = 128` 的 72 个 CTA 会让大半张芯片空等？

<!-- FIG ch02-a: 图 2-1 上方画 H200 芯片封装（两侧 HBM 堆叠［按 6144 位总线除以每堆叠 1024 位推得 6 个］、中间 GPU 裸片与中央 L2 缓存带，移动块对应 qkv_gate 的 W 行块依次流向各 SM），裸片上每个小方块代表 1 个 SM。下方画 2,304 个 CTA（按每 SM 1 个 CTA 的简化模型为 17 × 132 + 60）在 132 个 SM 上按波次推进的时间线。 -->

图 2-1 上方画出了 H200 芯片表面。中间裸片上的每个小方块是 1 个 SM（全卡共 132 个）。两侧是 141 GB 的 HBM3e 显存（按 6,144 位总线除以每堆叠 1,024 位推得 6 个堆叠，美光 H200 规格为每堆叠 24 GB、8 层 DRAM）。先按每 SM 一次只跑 1 个 CTA 的简化模型演示波次。第 3 章会算出 `v1 / v2` 实际每 SM 驻留 16 个 CTA，全卡单轮容量为 `132 × 16 = 2,112` 个，`2,304 = 2,112 + 192` 实际分两轮跑完。全卡齐步跑完的一轮 CTA 称为一个 **wave**（波次）。在图 2-1 的单 CTA 模型中，启动 2,304 个 CTA（每块读 `W` 的 1 行 16 KiB）与启动 2,376 个 CTA 都要跑 `⌈2304 ÷ 132⌉ = 18` 个 wave。第 18 个 wave 无论有 60 个还是 132 个 SM 在算，整个 kernel 都要等这一波跑完才结束。

只要总 CTA 数不是单轮容量的整数倍，最后一个 wave 就只有余数 `r` 个块在算（图 2-1 中 `r = 60`）。其余 **`132 − r`**（72）个 SM 空等到终点线，这段空等就是 **tail**（尾波）。当最后一波的余数 `r` 不超过单轮容量的一半（单 CTA 模型下 `2r ≤ 132`，即 `r ≤ 66`）时，可把队尾每一行的 `K = 8,192` 列对半切开：前半块读前 4,096 列（8 KiB），后半块读后 4,096 列（8 KiB）。这一做法称为 **K-halves**（尾波对半切分，勾选图 2-1 的切半开关可见）。切开后的 `2r` 个半块刚好放进最后一轮的空闲 SM 里，两半经跨 SM 合并（见第 4 节）即可在该模型下把尾波缩短约半个 wave。

更一般地，当输出矩阵的行分块数 `M_tiles` 乘列分块数 `N_tiles` 填不满全卡 132 个 SM 的单波次容量时，就要沿内积求和维 `K` 切分成 `SPLIT` 段——称为 **Split-K**（沿内积维切分；阶段 2 注意力沿历史键值维切分称为 Split-KV，见第 7 章第 2 节）。

<!-- FIG ch02-splitk-wave: 图 2-6 Split-K 切分数与 132-SM 波次权衡解剖图：上方对比阶段 6 下投影（M = 16）在 Split-K = 1（不满波）、Split-K = 2（铺满单波省 1.38 µs）与 Split-K = 4（跨波次加归约流量反慢 3.26 µs）下的 SM 占用，下方展示阶段 1 qkv_gate（T = 128/256）用非整除 Split-K = 3 将 36/42 个输出瓦片扩为 108/126 个 CTA 填满 132 个 SM 的过程。 -->

以阶段 6 路由专家的下投影（`gemm2`）在 `decode 16`（`M = 16`）下的 `Split-K = 2` 切分为主例，解剖 Split-K 如何在“填满 132 个 SM”与“避免跨波次及部分和膨胀”之间取得平衡：
- **公式**：将下投影 `y = inter · W2^T`（内积维 `K = 4,096`）沿 `K` 切成 `S = 2` 段（每段 `K_s = 2,048`），各分片 CTA 算出部分和平面 `y_part[s, tok, :] = inter[tok, s·2048:(s+1)·2048] · W2[:, s·2048:(s+1)·2048]^T`，再累加 `y = y_part[0] + y_part[1]`。
- **输入**：上投影产出的中间激活 `inter`（BF16 `[A_tok, 4096]`，位于 L2/HBM）与命中专家的下投影 4 位权重 `W2`（每专家 `9.4 MB`，位于 HBM）。
- **输出**：`S = 2` 份部分和平面 `y_part`（存为 BF16 `[2, A_tok, 4096]` 以减半中间平面流量，位于 L2/HBM）。
- **交给下一步**：由后归一化核以单精度读取并求和 `y_part`，乘上每专家归一化与路由权重后写出 `m [16, 4096]`。
- **本步代价与三元权衡**：
  - **得到什么（实测收益）**：当 `M = 16` 时，每个命中专家按列切出 64 个输出块，不切 `K` 时总块数 `A × 64` 填不满单轮波次容量；切成 `Split-K = 2` 后 CTA 总数翻倍，恰好铺满波次，在 `decode 16` 上 5 个种子全部获胜，实测省下 **1.38 µs**（区间 `[-1.71, -1.18] µs`）。
  - **付出什么（代价）**：多写出 1 份部分和平面并由下游多读 1 次（最大绝对误差 `0.0078`，在容差内）。
  - **参数翻转（切分过多跨过波次边界反输）**：在同一 `decode 16` 上若把切分数继续翻倍到 **`Split-K = 4`**，总 CTA 数越过单波次上限掉进下一波，叠加 4 份部分和的读写开销，实测反而**变慢 +3.26 / +1.50 µs**；而在 `decode 32`（`M = 32`）上尝试 `Split-K = 2` 时，虽池化均值快 `2.69 µs`，但因命中专家数较多的 1 个种子跨过波次边界**慢了 +1.33 µs** 而被门控拦截。

同样地，在第 1 章末尾留下的 `qkv_gemm g1a`（`T = 128 / 256`）悬案中，`W [2304, 8192]` 按 `BN = 64` 只有 `2,304 ÷ 64 = 36` 个输出列块。`g1a` 用 `Split-K = 2` 只派出 `36 × 2 = 72` 个 CTA（每 SM 驻留 1 个 CTA），导致 `132 − 72 = 60` 个 SM 全程闲置！但 `K / BK = 8,192 ÷ 64 = 128` 步又不能被 `3` 整除。解决方案是引入**非整除 Split-K（uneven K parts）**：允许 `SPLIT = 3` 把 128 个 K 步拆成 `43 + 43 + 42` 步，在 `T = 128`（`BM = 128`，1 个行块）派出 `1 × 36 × 3 =` **108 个 CTA**，在 `T = 256`（若配 `SPLIT = 3` 与 42 个输出分块）派出 **126 个 CTA**，一举填满 132 个 SM，配合第 4 节的票据并行切片归约在 `verify 16 / 32` 上立省 **2.78–2.86 µs** 与 **7.50–7.89 µs**！

- **什么时候变成亏本（反例与失效边界）**：

## 2. PDL 提前进场时发生了什么：观察到的 CTA 派发顺序

<!-- FIG ch02-e: 图 2-5 PDL 提前进场时，后继 kernel 的 CTA 按 blockIdx.x 顺序填进空出来的 SM；时间线显示最后一个 CTA 晚 2–3 µs 开始。 -->

按第 1 章第 3 节的 PDL 规则，阶段 6（P2 专家）拆成阶段 A（算 `w13` 与 `SwiGLU`，每专家权重 18.9 MB，写出 `inter [M, 4096]`）与阶段 B（算 `w2`，每专家权重 9.4 MB，写出 `y [M, 4096]`）。在小批量内核中，阶段 B 在全卡每个 SM 上启动 1 个常驻 CTA（即 `b = 0..131`，循环处理分给它的工作单元；大批量内核的持久队列见第 7 章）。本来每个 CTA 分到的工作单元数相同，应该同时结束。但阶段 A 的 132 个 SM 是一批批退场的（结束跨度约 4–7 µs）。硬件派发器在交接处按 `blockIdx.x` 从小到大的顺序，把阶段 B 的 `0..131` 号 CTA 依次派给刚空出的 SM。结果编号最大的 131 号 CTA 总是最后进场，比前 100 个 CTA 晚约 **2–3 µs** 到达第一个工作单元（每单元周期约 1.05 µs）。

如图 2-5 所示，选“decode 16”时读数为：`decode 16：编号小于 100 的块 2.3 µs 到第一个 B 单元，131 号块 4.3 µs，晚 2.0 µs`（62% 的种子中 131 号块最慢）。选“decode 32”时读数为：`decode 32：编号小于 100 的块 1.9 µs 到第一个 B 单元，131 号块 5.1 µs，晚 3.2 µs`（81% 的种子中 131 号块最慢）。选“verify 1（M = 8）”时读数为：`verify 1（M = 8）：编号小于 100 的块 2.0 µs 到第一个 B 单元，131 号块 2.9 µs，晚 0.9 µs`（22% 的种子中 131 号块最慢）。因此在代码里从 100 号块起按启动延迟代价项给编号大的 CTA 少分阶段 B 工作单元，在 decode 16 与 32 上实测平均省下 **0.27 µs** 与 **0.31 µs**（verify 1 上为 `−0.02 µs`，无差别）。

## 3. 全卡内存层次与利特尔法则：为什么每个 SM 要挂起约 `64 KiB` 在途读取？

<!-- FIG ch02-mem: 图 2-0 H200 的存储层次：寄存器 → SMEM/L1 → L2 → HBM，每层的容量、延迟、带宽，以及 qkv_gate 的一个 W 元素和 x 走过哪些层。 -->

如图 2-0 所示，从计算单元向外看，H200 的存储分为四层。最内层是每个 SM 私有的寄存器文件（65,536 个 32 位寄存器，依赖乘加延迟约 4.10 个周期，第 3、4 章展开）。往外是每个 SM 的 256 KB 片上池，切分为最多 228 KiB 的 SMEM（无冲突读延迟 23.06 个周期，每 SM 峰值 128 B/周期，按 1.7964 GHz 持续张量时钟折合约 229.9 GB/s）与私有的 L1 缓存（命中 54.4 个周期，见第 3 章）。再往外是全卡 132 个 SM 共享的中央 **L2 cache**（L2 缓存，容量 60 MiB，近端命中 327.8 个周期、远端 414.1 个周期，全卡命中带宽约 **7.33 TB/s**）。最外层则是两侧的 **HBM**（容量 141 GB，空载往返 600.2 个周期，按该测试的 1.7964 GHz 时钟折合约 0.334 µs，标称带宽 4.8 TB/s，各层延迟独立测量、不直接相加）。在 `qkv_gate`（`y = W · x`）中，权重 `W`（37.7 MB）每步只用 1 次，必须从最外层 HBM 经 L2 流入寄存器。而输入向量 `x`（16 KiB）被全部 2,304 个 CTA 重复读取，首次读入后即可留在 L2 中就近返回（近端 327.8 个周期，按 1.7964 GHz 约 0.182 µs）。在图 2-0 中选 v1（2 字节标量读），读数为：`每条 warp 指令读 64 B（2 个扇区）· 每个 SM 在途 4.0 KiB`；`整卡实测 642 GB/s（58.88 µs）`。改选第 3 章的 v5（16 字节向量读），读数为：`每条 warp 指令读 512 B（16 个扇区）· 每个 SM 在途 32.0 KiB`；`整卡实测 2,127 GB/s（17.76 µs）`。再选第三档 TMA 模型（本 `gemv` 未实现 TMA 版本，该档按第 3 章 TMA 搬进 SMEM 建模），读数为：`2 条 TMA 搬 32 KiB 进 SMEM · 0 个寄存器等数据`；`单 SM 的 TMA 流实测 182.7 GB/s · 本 gemv 没有整卡实测`。

如图 2-2 所示，全卡 132 个 SM 读写全局指针 `W, x, y` 时，全部连向芯片中央共享的 L2 cache，未命中时再去两侧的 HBM 读取。第 0 章算下界用的 4.8 TB/s 是手册标称峰值，而全卡用普通 16 字节向量读取持续流式读 HBM 的实测稳态上限约为 **4.54 TB/s**。平摊到每个 SM，目标带宽约为 `4.54 TB/s ÷ 132 ≈ 34 GB/s`。一条读取发出后、数据返回前，它请求的字节叫 **bytes in flight**（在途数据量）。图 2-2 把 `W` 的 1 整行（`16 KiB = 32` 条每次 512 字节的线程束读取，见第 3 章）画作 1 个在途单元。图 2-2 横轴用“▲”标出了 `v1–v10` 按 SASS 数据流估算的在途位置，其中 `v1–v4` 每线程只发 2 字节读取，每 SM 在途估算仅 4.0 KiB。根据 **Little's Law**（利特尔法则），要跑满单 SM 的目标带宽，SM 上同时保持的在途字节数必须覆盖往返延迟。

```text
bytes in flight（所需在途数据量） = 单 SM 目标带宽 × 包含排队在内的往返延迟
```

先按空载延迟估算。全卡只有 1 个请求在路上时（空载），读 HBM 往返约 0.33 µs（600.2 个周期），算出每 SM 只需挂起 `34 GB/s × 0.33 µs ≈ 11 KiB`。切换图 2-2 的档位。选“每个 SM 在途 16 KiB（同时读 1 行 W）”时，读数为：`全卡 2.29 TB/s，是标称的 48%；一行往返约 0.94 µs`。再切到“每个 SM 在途 **64 KiB**（同时读 4 行 W）”。此时读数到达拐点：`全卡 4.49 TB/s，是标称的 94%；一行往返约 1.92 µs`。满载往返约为空载延迟的 6 倍，因为全卡请求在 L2 与显存控制器前拉长了排队时间。超过约 64 KiB 后，带宽停在约 4.54 TB/s。

把图 2-2 的时间轴拖到最后一步，即可看清为什么单次 37.7 MB 启动的实测点（○，写 512 MiB 清缓存下 `v7` 为 15.68 µs 即 2,409 GB/s，读 512 MiB 干净清缓存下为 14.27 µs 即 2,645 GB/s）落在稳态曲线下方。此时读数为：`H200 实测：v7 稳态 4.54–4.61 TB/s，在曲线上`；`一次 37.7 MB = 8.2 µs 稳态 + 6.4 µs 固定开销 ≈ 14.6 µs（实测 14.27）`。当在干净清缓存下把读取行数从 2,304 行扩到 4,608 行（75.5 MB）及以上时，H200 实测 `v7` 每多读 37.7 MB 的稳态斜率为 **4.54–4.61 TB/s**（线性拟合 4.59 TB/s，即图上 ◆），正好落在曲线上。单次 37.7 MB 启动的表观带宽较低，是因为除 `37.7 MB ÷ 4.59 TB/s ≈ 8.2 µs` 的稳态传输外，线性拟合截距显示每次启动还要付约 **6.4 µs** 的固定开销：其中单 warp 空 kernel 启动加事件计时实测为 3.81 µs（约 3.8 µs，第 0.5 章首轮为 3.68 µs），其余约 2.6 µs 为拟合残差（`%globaltimer` 时间线显示 2,304 个 CTA 在 0.16 µs 内全部启动，但完成时间分布在 7.7–12.6 µs 之间，最后 10% 的线程束比前 90% 晚 2.4 µs 结束，推断收尾期在途字节下降使 HBM 未跑满）。

## 4. 跨 SM 交换数据：为什么必须走 L2 同步？

<!-- FIG ch02-c: 图 2-3 上方画 SM A 与 SM B 各自独立的私有缓存及中央共享的 L2 cache（内含硬件原子加法器，移动块对应 K-halves 前半块 SM A 与后半块 SM B 写出部分和并经 L2 计数器交接合并的过程）。下方画通过 device 级 release 排空到 L2、再通过 acquire 失效本地旧缓存并从 L2 读到新值的交接时间线。 -->

同一 **cluster**（线程块集群）内的 CTA 可直接互读片上内存。但 K-halves 的两个半块与阶段 2（P1 注意力）的各拆分块由任意空闲 SM 接手，不保证在同一 cluster 内。因此跨任意 SM 汇总必须走全卡唯一的一致点 L2（所有 SM 看到同一份数据的位置；P1 注意力的无返回值原子加与原地重缩放合并见第 7 章第 2 节）。

以 K-halves 合并尾部第 `row` 行为例。前半块（SM A，算列 `0..4095`，读 8 KiB 的 `W` 与 8 KiB 的 `x`）和后半块（SM B，算列 `4096..8191`）各自算出标量部分和 `sum`（FP32，4 B）。它们先把 `sum` 写入全局数组 `partial[half_id * M + row]`（FP32，4 B，位于 L2/HBM）。再通过计数器 `done_cnt[row]`（`int32`，4 B，位于 L2），由后到者算出 `y[row] = partial[row] + partial[M + row]`（FP32，4 B，写回 HBM）。x86 CPU 的 TSO（总存储序）内存模型保证同一核发出的写入按程序顺序对其他核可见。ARM 等弱序 CPU 不保证跨地址顺序，而硬件缓存一致性本身只保证同一地址的写入顺序。在 GPU 上，各 SM 的私有缓存（见第 3 章的 L1 cache）之间硬件不自动保持一致。普通写入也不保证跨地址顺序：计数器 `done_cnt[row]` 的更新可能先于 `partial` 到达 L2，后到半块的普通读取也可能命中本 SM 私有的旧缓存行。因此跨 SM 交接必须指定 **device**（全卡作用域）的 **release / acquire**（释放/获取）内存序。实战中把两步合成一个带 `acq_rel`（兼具 release 与 acquire）的原子加法。每个半块写完 `partial` 后，对 `done_cnt[row]` 执行 `fetch_add(1, memory_order_acq_rel)`。拿到旧值 `1` 的后到半块读取另一半部分和相加写回 `y[row]`，并把计数器复位为 `0` 供下一次 CUDA Graph 重放。

```cuda
#include <cuda/atomic>
// 每个半块块内归约后，0 号线程写出本半块部分和，并以 device 级 acq_rel 递增计数器
__syncthreads();
if (threadIdx.x == 0) {
    partial[half_id * M + row] = sum;
    cuda::atomic_ref<int, cuda::thread_scope_device> cnt(done_cnt[row]);
    if (cnt.fetch_add(1, cuda::memory_order_acq_rel) == 1) {
        y[row] = partial[row] + partial[M + row];
        cnt.store(0, cuda::memory_order_relaxed); // 复位供下一次 CUDA Graph 重放
    }
}
```

如图 2-3 所示，先选“只用 relaxed（不指定内存序）”，读数为：`relaxed：0 条栅栏 · B 侧交接链 506（H200 实测）+ 54.4 = 560.4 个周期`；`结果：B 读到旧的部分和，y[r] 错`。再选“device 级 acq_rel”，读数为：`acq_rel：每次原子加 5 条 SASS（含 MEMBAR.ALL.GPU、CCTL.IVALL）`；`B 侧交接链 1078（H200 实测）+ 327.8 = 1405.8 个周期 · y[r] 正确`。其中 `MEMBAR.ALL.GPU` 把当前线程此前的写入排空到 L2 并等确认（全卡栅栏 `fence.acq_rel.gpu` 空载实测 269.0 个周期，带 1 条未决写入时升至 475 个周期）。`CCTL.IVALL` 则在获取后将本 SM 的私有 L1 整块置为无效。指令本身仅多约 3 个周期，但后续再读原本驻留在 L1 的数据（如重读 16 KiB 的 `x`）会退化为从 L2 重填，耗时从 319.8 个周期涨到 596.6 个周期（多付约 277 个周期）。按该同步微基准实测的 1.98 GHz SM 自旋时钟换算，B 侧带未决写入的 `acq_rel` 原子加（1,078 个周期，约 0.54 µs）加上从 L2 近端命中读取 `partial[row]`（327.8 个周期，按 1.7964 GHz 约 0.182 µs、按 1.98 GHz 约 0.166 µs）合计 **1,405.8 个周期**（约 **0.71–0.78 µs**）。这与独立测得的 256 次写入加 `release / acquire` 跨 SM 交接中位数（**0.67 µs**）及第 1 章的 PDL 交接边（0.64 µs）同量级。所以能留在单 SM 内部完成的计算不跨 SM 交接。

## 5. gemv 演化（v2 → v3 → v4）：K-halves 切尾波与 L2 缓存留存提示

<!-- FIG ch02-d: 图 2-4 K-halves：尾部一行切成两半，两个 SM 各算一半，最后到达的那个读两半相加写 y（done_cnt 计数），时间线对比切半前后（64 轮约 21.4 µs vs 32 轮加合并约 11.2 µs）。 -->

按第 3 章的驻留规则，**v2**（`<<<2304, 128>>>`）每 SM 驻留 16 个 CTA，全卡单轮容量为 2,112 个 CTA，第二轮留下 `r = 192` 个尾波 CTA。由于 `192 ≤ 2,112 ÷ 2` 满足第 1 节“余数不超过单轮容量一半”的切半条件，**v3** 把最后 192 行拆成 384 个半行 `K/2` 的 CTA（启动 2,496 个 CTA）。两半按第 4 节的 L2 `acq_rel` 原子计数由后到者合并写回。

图 2-4 用单个尾波 CTA 的串行往返链来建模切半收益：每个尾波 CTA 只有 `128 × 2 B = 256` 字节在途，算完一整行要走 `8,192 ÷ 128 = 64` 次串行往返。按空载单次 `0.334 µs`（600.2 个周期 ÷ 1.7964 GHz）估算，图 2-4 读数为：`不切半：一个 CTA 64 轮，约 21.4 µs`。切半后每个半块只走 32 次往返（图 2-4 模型按两次 L2 近端命中每次 `0.182 µs` 加 `0.15 µs` 错开估算），读数变为：`切半：两个 CTA 各 32 轮 + L2 合并，约 11.2 µs`（单 CTA 链模型估算省约 10.2 µs）。第三行读数显示：`实测（整个 kernel）：v1 58.88 µs → v3 48.26 µs`（`1.22×`，约为 7.9 µs 下界的 `16.3%`）。实测节省的 **10.6 µs** 大于简单按半轮波次比例的预测（整个 kernel 层面的精确拆解未单独测量），与图 2-4 的单 CTA 串行往返模型同量级。

接着 **v4** 用 `createpolicy` 为中央 L2 加上留存提示（`.L1::evict_first` 与 `.L1::evict_last` 同时提示本 SM 的 L1）。权重 `W` 每字节只读 1 次，标为 **`evict_first`**（读完优先淘汰）；向量 `x`（16 KiB）被重复读取，标为 **`evict_last`**（优先留在缓存）。

```cuda
// v4：用 createpolicy 生成 L2 策略描述符，W 标 evict_first，x 标 evict_last
asm volatile("createpolicy.fractional.L2::evict_first.b64 %0, 1.0;\n"
             "ld.global.L1::evict_first.L2::cache_hint.b16 %1, [%2], %0;" : "=&l"(pW), "=h"(w) : "l"(Wp));
asm volatile("createpolicy.fractional.L2::evict_last.b64 %0, 1.0;\n"
             "ld.global.L1::evict_last.L2::cache_hint.b16 %1, [%2], %0;" : "=&l"(pX), "=h"(xv) : "l"(xp));
```

在写 512 MiB 清空 L2 的冷缓存测试下，H200 实测 v3 → v4 从 `48.26 µs` 变为 **43.94 µs**（`1.10×`，约为 7.9 µs 下界的 `17.9%`）。但对照实验表明，这一 `1.10×` 并非来自 `x` 的命中率提升（有无提示下 `x` 在 L2 均为 100% 命中，且在途量仍为 4.0 KiB/SM），而是**在该测试中由写 512 MiB 脏行清缓存带来的测法假象**。当改用**读取** 512 MiB 干净清空 L2 时，v3 为 `42.88 µs`、v4 为 `43.49 µs`，提速彻底消失（推断原因是未加 `evict_first` 的 `W` 挤出 L2 脏行时触发了回写竞争，这一脏冲刷假象同样把普通读取的 v0–v3 冷缓存耗时相对 v4+ 垫高了约 4–6 µs；在真实多层推理中前序 kernel 写出的脏 L2 下该提示是否有益，本实验未测量）。而在不清空缓存的热缓存重复测试中，`W`（37.7 MB）本可装进 L2，`evict_first` 阻止了 `W` 留存，使 v3 → v4 的热缓存耗时从 `29.02 µs` 退化到 `42.88 µs`。

**带走一句话：** 普通读取需在每个 SM 挂起约 64 KiB 在途字节才能跑满 4.54 TB/s 的 HBM 稳态带宽（跨 SM 经 L2 交接一次约 1,406 个周期即 0.7 µs），而 v3 用 K-halves 切平尾波将 `qkv_gate` 从 58.88 µs 压到 48.26 µs（v4 的 43.94 µs 在本测试中是写脏行清 L2 的假象，干净清 L2 下与 v3 持平）。
