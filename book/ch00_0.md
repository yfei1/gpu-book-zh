# 第 0.0 章（导引）：一句话怎样穿过 62 层大模型变成下一个词？

**本书地图：** 前言 → **【第 0.0 章：一句话穿过 62 层模型】** → 第 0 章 → 第 0.5 章 → 第 1 章 [第 0 级] → 第 2 章 [第 1 级] → 第 3 章 [第 2 级] → 第 4 章 [第 3 级] → 第 5 章 [第 4 级] → 第 6 章 [第 5 级] → 第 7–9 章

承接前言的问题（从整网闭环到单层入口）：当用户输入一句话时，大模型到底经历了哪几步计算、张量形状与数据类型怎样变化、每一层算完如何把结果交给下一层，又为什么必然分裂成 **prefill**（预填充）、**decode**（逐词解码）与 **verify**（投机解码检验）三种工作模式？

---

## 1. 入站（步骤 1–2）：从一句话到词元编号，再查表变成 8,192 维向量

<!-- FIG ch00_0-a: 图 0.0-1 一句话穿过 Muse Spark Open：分词 → 嵌入 → 62 层 → lm_head → 采样，以及 prefill / decode / verify 三种走法。 -->

GPU 的算术单元只认识固定宽度的数字数组，不认识原始文本。如图 0.0-1 的步骤 1 与步骤 2 所示，一句话进入 `Muse Spark Open` 后，先经历两步入站转换，把变长字符串变成第 0 层能直接相乘的浮点数矩阵。
- 步骤 1（分词与取词编号，`Tokenize`）。分词器把用户输入的文本切成 `L` 个基本词元（称为 **token**，图 0.0-1 示例提示词取 `L = 5`）。每个词元对应词表（共 `202,048` 个词项）里的一个整数编号。
  - 公式：`ids = Tokenizer(text)`。
  - 输入：用户文本字符串（在自回归循环的后续步中，直接取上一步采样出的整数编号）。
  - 输出：词元编号数组 `ids`，形状为 `[L]`，类型为 32 位整数（`int32`，每词 4 字节，`L = 5` 时共 20 字节），写入 GPU 的 **HBM**（高带宽显存）。
  - 交给下一步：`ids [L]` 通过 HBM 显存地址交给步骤 2 的词表嵌入查表。
- 步骤 2（词表嵌入查表，`Embedding Lookup`）。模型在 HBM 中常驻一张巨大的词嵌入矩阵 `W_embed`。程序拿 `ids` 里的 `L` 个整数当作行号，从 `W_embed` 中直接取出对应的 `L` 行向量。
  - 公式：`stream_0[t, :] = Float32(W_embed[ids[t], :])`，并算出首层入口归一化激活 `x_0[t, :] = RMSNorm(stream_0[t, :]) * (1 + w_norm0)`。
  - 输入：词元编号 `ids`（`[L]`，`int32`，位于 HBM）与词嵌入表 `W_embed`。`W_embed` 的形状为 `[202048, 8192]`，类型为 **BF16**（脑浮点，每元素 2 字节），整张表占 `202,048 × 8,192 × 2 B =` **3.31 GB**（位于 HBM）。
  - 输出：两条贯穿全网的初始张量。第一条是高精度主干 **residual stream**（残差流）`stream_0`（形状 `[L, 8192]`）。它的类型为 **FP32**（单精度浮点，每元素 4 字节，每词占 `32 KiB`，写回 HBM）。第二条是第 0 层入口激活 `x_0`，形状为 `[L, 8192]`，类型为 BF16（每词占 `16 KiB`，写回 HBM）。
  - 交给下一步：`(x_0, stream_0)` 通过 HBM 全局指针交给步骤 3 的第 0 层（`layers.0`）。
  - 本步硬件代价：GPU 无需读取整张 3.31 GB 的 `W_embed`，只需按行号从 HBM 收集 `L` 行。每词读取 `16 KiB`、写出 `32 + 16 = 48 KiB`（当 `L = 5` 时共读 `80 KiB`、写 `240 KiB`）。

## 2. 穿过躯干（步骤 3）：62 层堆叠的纵向跨层交接与横向 KV 缓存留存

拿到初始的 `(x_0, stream_0)` 后，数据流要依次穿过模型躯干的 **62 层**解码器层（`layers.0` 到 `layers.61`）。这 62 层的接口形状完全相同，但在注意力视野与专家量化精度上有两处规律性的排布。
- 第一处是 **46 个滑窗层**与 **16 个全长层**按 `3 : 1` 交替排布。下标为 `1, 5, 9, ..., 61`（即每 4 层中的最后 1 层，`l % 4 == 1`）的 16 层是全长注意力层。在这些层上，每个词要回顾从第 0 个位置到当前位置的全部历史上下文（上限 `1,048,576` 个位置），且不施加旋转位置编码（`RoPE`）。其余 46 层是滑动窗口注意力层，每个词只回顾最近 `2,048` 个位置，并在注意力前对查询与键施加 `RoPE`。
- 第二处是 **60 个 NVFP4 量化专家层**与 **2 个首尾非 NVFP4 层**。每层内部都包含一个 256 选 8 的混合专家（MoE）半区。中间 60 层（`layers.1` 至 `layers.60`）的专家权重压缩为 4 位浮点 **NVFP4**（平均每权重 `0.5625` 字节，单专家 `28.3 MB`）。首尾第 0 层与第 61 层则被排除在 NVFP4 量化之外。

在图 0.0-1 的步骤 3 中，点开任意第 `l` 层（`l = 0 .. 61`），它与前后层及未来时间步之间的契约都可以精确写为以下四项。
- 公式：`(x_{l+1}, stream_{l+1}, K_cache[l], V_cache[l]) = Layer_l(x_l, stream_l, K_cache[l], V_cache[l], pos)`。
- 输入：本层入口激活 `x_l`（`[L, 8192]`，BF16，HBM）与本层残差流 `stream_l`（`[L, 8192]`，FP32，HBM）。第三个输入是第 `l` 层专属的分页 **KV cache**（键值缓存）`K_cache[l], V_cache[l]`。该缓存类型为 **FP8**（`E4M3`，每元素 1 字节，位于 HBM）。在 8 卡张量并行下，单张 H200 负责 2 个键值头、每头宽 64，因此每个词在每一层的缓存格大小固定为 `2 (K与V) × 2 (头) × 64 (宽) × 1 B =` **256 字节**。
- 输出：更新后的残差流 `stream_{l+1}`（`[L, 8192]`，FP32，每词 `32 KiB`，HBM）与顺手为下一层算好的预归一化激活 `x_{l+1} = RMSNorm(stream_{l+1}) * (1 + w_next_pre_attn)`（`[L, 8192]`，BF16，每词 `16 KiB`，HBM）。同时输出原地写入第 `l` 层缓存页的新键值 `K_new, V_new`（每新词 `256 B`，FP8 `E4M3`，HBM）。
- 交给下一步（两条正交的交接路径）：
  1. 纵向跨层交接（`Layer l → Layer l + 1`）。只有 `(x_{l+1}, stream_{l+1})` 沿网络深度传给第 `l + 1` 层（第 61 层的输出传给步骤 4 的最终归一化）。因为第 `l` 层的收尾操作已经把第 `l + 1` 层的入口归一化算好写进 `x_{l+1}`，第 `l + 1` 层一进场就能直接启动矩阵乘，省去了一次独立的跨层归一化读写。
  2. 横向跨时间步留存（留在 `Layer l` 原地）。第 `l` 层写入 HBM 的 `K_cache[l], V_cache[l]` **绝不传给第 `l + 1` 层**。它留在第 `l` 层自己的显存页里，专门等后续生成第 `t + 1, t + 2, ...` 个新词再次路过第 `l` 层时，作为历史上下文被第 `l` 层的注意力直接读取。
- 本步单层与 62 层总代价：当单趟词数 `L ≤ 8` 时，单层 5 个稠密投影矩阵必读权重为 `37.7 + 16.8 + 67.1 + 8.4 + 8.4 =` **138.4 MB**。62 层稠密权重合计 `62 × 138.4 MB =` **8.58 GB**（每个被激活的本地 NVFP4 专家另加 `28.3 MB`）。单层稠密投影每词运算 **0.134 GFLOP**（62 层每词合计 `8.31 GFLOP`）。

## 3. 出站与回流（步骤 4–8）：最终归一化、词表投影、软上限与采样闭环

当数据穿完第 61 层（吐出 `stream_62`）后，模型还要走完图 0.0-1 右侧的步骤 4 至步骤 8。这五步把 8,192 维的浮点向量还原成下一个词的整数编号，并闭环送回第 0 层。
- 步骤 4（最终归一化，`Final Norm`）。生成下一个新词时，只需要最后一个位置（下标 `L - 1`，即行数 `R = 1`）的隐状态去预测未来；而在投机检验 8 个草稿词时，则取全部 `R = 8` 行。
  - 公式：`h = RMSNorm(stream_62[rows, :]; w_norm)`。
  - 输入：`stream_62` 的目标行（`[R, 8192]`，FP32，每行 `32 KiB`，HBM）与最终归一化权重 `w_norm`（`[8192]`，BF16，HBM）。
  - 输出：归一化后的特征 `h`（`[R, 8192]`，BF16，每行 `16 KiB`，写回 HBM），交给步骤 5。
- 步骤 5（词表线性投影，`lm_head`）。把 8,192 维特征乘上独立的输出词表矩阵 `W_lm_head`（在 `Muse Spark Open` 中不与 `W_embed` 共享权重，且保持未量化的 BF16），为词表里的 `202,048` 个候选词逐一打分。
  - 公式：`z = h @ W_lm_head.T`。
  - 输入：`h`（`[R, 8192]`，BF16，HBM）与 `W_lm_head`（形状 `[202048, 8192]`，BF16，占 `202,048 × 8,192 × 2 B =` **3.31 GB**，HBM）。
  - 输出：原始词表打分 `z`（形状 `[R, 202048]`，写回 HBM），交给步骤 6。
  - 本步代价：从 HBM 读取 **3.31 GB** 权重（按 H200 的 `4.8 TB/s` 峰值带宽计算，单是读完 `W_lm_head` 至少就要 **0.69 ms**）。每行执行 `2 × 202,048 × 8,192 =` **3.31 GFLOP** 乘加运算（算术强度仅 `R FLOP/B`）。
- 步骤 6（对数几率软上限，`Logit Softcapping`）。为防止极端打分导致数值不稳定，模型用双曲正切函数把打分平滑限制在 `(-20, +20)` 区间内。
  - 公式：`logits = 20.0 * tanh(z / 20.0)`（配置常数 `final_logit_softcapping = 20.0`）。
  - 输入与输出：输入 `z [R, 202048]`，输出限幅后的 `logits [R, 202048]`（HBM），交给步骤 7。
- 步骤 7（概率归一化与采样，`Sample`）。把 `202,048` 个打分转为概率分布并挑出下一个词。
  - 公式：`p = softmax(logits / T_temp)`，`next_id = sample(p)`（贪心解码时直接取最大值下标 `argmax(logits)`）。
  - 输入与输出：输入 `logits [R, 202048]`，输出新生成的词元编号 `next_id`（形状 `[R]`，`int32`，每词 4 字节，HBM），交给步骤 8。
- 步骤 8（自回归回流，`Feedback`）。
  - 公式：`ids_next = [next_id]`，位置游标 `pos ← pos + 1`。
  - 交接闭环：刚刚采出的单个 `next_id`（4 字节）拉回步骤 2 的入口，作为下一趟前向计算的唯一输入词元去查 `W_embed`，从而启动生成下一个词的循环。

## 4. 为什么必然分裂成 Prefill、Decode 与 Verify 三种走法？

切换图 0.0-1 顶部的三个模式按钮，观察同一个 62 层模型在处理“5 个提示词”、“生成第 7 个词”与“检验 8 个草稿词”时的顶部读数。这三种工作模式不是人为规定的软件分支，而是自回归因果律作用在 HBM 带宽上的必然结果。
- 第一阶段：**prefill**（预填充，对应本书赛题 P5）。用户刚提交整句提示词时（图 0.0-1 示例取 `L = 5`；真实服务首轮按 `L = 16,384` 分块，或多轮在 `80,000` 历史词上追加 `L = 753`），这 `L` 个词在计算前全部已知。因此它们可以叠成 `[L, 8192]` 矩阵，一次性并排流过全部 62 层（每层注意力用下三角因果掩码保证第 `j` 个词只看自己及之前的词）。这一趟顺手把每层的 `L` 格新键值写进 KV 缓存，最后只取第 `L - 1` 行特征送入 `lm_head` 采出第 1 个新词（即第 6 个词）。图 0.0-1 在该模式下的读数为：`本趟 5 个词同时流过 62 层 · 每层写入 KV 5 格 · 产出第 6 个词`；`读权重 11.89 GB（不含专家）· 平均每个词摊 2.38 GB · 带宽下界 2.48 ms`。
  算清这笔总账：62 层稠密权重（`8.58 GB`）加上 `lm_head`（`3.31 GB`）共需从 HBM 读取 **11.89 GB**（不含专家）。按 H200 的 `4.8 TB/s` 带宽上限，光读完这 11.89 GB 至少需要 **2.48 ms**（全网写 KV 共 `62 × 5 × 256 B = 79,360 B`，稠密加 `lm_head` 共 `41.5 + 3.31 = 44.81 GFLOP`）。因为 5 个词共享同一次权重读取，平均每个词只分摊 **2.38 GB**。当真实预填充块达到 `L = 16,384` 个词时，权重被一万六千个词共享，瓶颈彻底从 HBM 读权重翻转为 Tensor Core 算力。
- 第二阶段：**decode**（逐词解码，对应赛题 P1–P4 的单词档）。一旦第 6 个词在步骤 7 被采样出来，要去生成第 7 个词、第 8 个词时，处境就彻底变了。因为第 8 个词依赖第 7 个词的采样结果，在算完第 7 个词之前，第 8 个词根本不存在。于是从这一刻起，每一趟前向计算的输入被迫退化为只有刚吐出的那 **1 个新词**（`L = 1`）。前 5 个词的键值已经在预填充时留在了各层的 KV 缓存里。本趟每层只需写入第 6 个词的 **1 格** KV（`256 B`），并连同已缓存的 5 格一起读出 **6 格** KV（每层 `1,536 B`，62 层共读 `95,232 B`、写 `15,872 B`）。图 0.0-1 在该模式下的读数为：`本趟 1 个词流过 62 层 · 每层读 KV 6 格、写 1 格 · 产出第 7 个词`；`读权重 11.89 GB（不含专家）· 平均每个词摊 11.89 GB · 带宽下界 2.48 ms`。
  对比两行读数就能看到单请求 decode 的根本痛点。虽然稠密运算量降到了 `8.3 + 3.31 = 11.61 GFLOP`，但为了算这 1 个词，GPU 依然要把 62 层稠密权重和 `lm_head` 共 **11.89 GB** 从 HBM 重读一遍（带宽下界仍是 **2.48 ms**）。结果每个词都独自背负全部 11.89 GB 的权重读取。
- 第三阶段：**verify**（投机解码检验，对应赛题 P1–P4 的 8 词档）。既然在 decode 下花 2.48 ms 读一遍权重只算 1 个词让算力单元几乎全程空等，SGLang 默认打开投机解码。它先让一个极快的轻量草稿模型连猜 **8 个候选词**（位置 `6..13`，`L = 8`），再把这 8 个草稿词拼成 `[8, 8192]` 一次性送进 62 层大模型同时检验。每层写入 8 格 KV，并连同原有 5 格共读出 `5 + 8 =` **13 格**（`3,328 B`）KV（62 层共读 `206,336 B`、写 `126,976 B`；末尾全取 `R = 8` 行送入 `lm_head` 一次算出 8 个位置的打分）。图 0.0-1 在该模式下的读数为：`本趟 8 个草稿词一次流过 62 层 · 每层读 KV 13 格、写 8 格`；`读权重 11.89 GB（不含专家）· 平均每个词摊 1.49 GB · 带宽下界 2.48 ms`。
  这一趟同样读取 **11.89 GB** 权重（带宽下界同为 **2.48 ms**，稠密加 `lm_head` 运算增至 `66.5 + 26.48 = 92.98 GFLOP`）。8 个候选词把平均每词分摊的权重读取压低了 8 倍至 **1.49 GB**。只要草稿猜中前几个词，就能用一趟前向的时间吐出多个词。

看清了整座 62 层大模型的全貌后，为什么本书接下来的所有章节都只拆开其中 **1 层**？因为这 62 层就像 62 节接口完全一致的流水线：每一层都从 HBM 接过上一层留下的 `(x_l BF16 [T, 8192], stream_l FP32 [T, 8192])`，读写本层自己的 FP8 KV 缓存，再把 `(x_{l+1}, stream_{l+1})` 交给下一层。只要把这 **1 层**内部的全部计算与硬件交接压到物理极限，62 层合起来就达到了整网极限。

---

**带走一句话：** 一句话穿过 `Muse Spark Open` 的 62 层时，纵向靠 `(x_l BF16, stream_l FP32)` 跨层交接、横向靠留在各层原地的 `256 B/词` FP8 KV 缓存跨时间步复用，而“已知提示词可并排共享 `11.89 GB` 权重、未知生成词只能逐个重读权重”的因果差异，把推理必然劈成了 `prefill`、`decode` 与 `verify` 三种模式。
