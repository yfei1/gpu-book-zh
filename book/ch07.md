## 1. 阶段 2 算法契约与起点（`a0`）：为什么标量逐头设计会多读 8 倍 KV 缓存，如何把 8 个查询头叠成矩阵乘的行并把序言五步合一？

<!-- FIG ch07-gqa: 图 7-1 画阶段 2 分页 GQA 注意力起点（a0）的数据流解剖：上方对比标量逐查询头独立读取历史 KV 缓存（同一键值页重复读 8 次）与 GQA 8:1 分组将同一 KV 头的 8 个查询头叠成 Tensor Core 矩阵乘的 M 行（共享 1 次 256 B/词元 FP8 键值读取，DRAM 流量降 8 倍）；下方展示将按头均方根归一化、滑窗层 RoPE 与新键值 FP8 写入缓存合并为单次序言启动的算法步。 -->

在单张 TP8 的 H200 上，阶段 2 接收阶段 1 产出的 `qkv` 张量，在分页 `FP8 E4M3` 键值缓存上完成注意力计算与门控输出归一化。在动手优化之前，先把阶段 2 的五步数学契约、张量形状与三区间下界一次立住。
- 公式（五步计算）：
  1. 按头均方根归一化与查询缩放：将 `qkv` 切分为查询 `q_in [B, L, 16, 64]`、键 `k_in [B, L, 2, 64]`、值 `v_in [B, L, 2, 64]` 与门控 `gate [B, L, 16, 64]`，按头（64 维，无权重，`eps = 1e-5`）计算 `q = rmsnorm(q_in, 1e-5) * 5.473` 与 `k = rmsnorm(k_in, 1e-5)`。
  2. 旋转位置编码（仅 46 个滑窗层执行，16 个全长层跳过）：对 `q` 与 `k` 的交错对 `(2i, 2i+1)` 按绝对位置 `pos` 施加 `RoPE(theta = 500,000)`。
  3. 量化并原地写入分页缓存：将 `q` 舍入为 `FP8 E4M3`（在乘 `5.473` 之前），将新算出的 `k, v_in` 除以标量 `k_scale, v_scale` 量化为 1 字节 `FP8 E4M3`，按物理页槽索引 `cache_loc [T]` 原地写进 `K_cache, V_cache`。
  4. 分组查询注意力（GQA `8:1`）：本卡 16 个查询头均分为 `2` 组，每组 **8 个查询头共享 1 个 KV 头**。对请求 `b` 中位置为 `p = seq + j` 的第 `j` 个新词元，全长层读取 `0..p` 的全部可见键，滑窗层只读取最近 `max(0, p - 2047)..p` 的可见键（块内 `L` 个新词元之间满足下三角因果掩码），计算 `P = softmax((q_fp8 @ K_visible.T) / 8)` 与 `o_raw = P @ V_visible`（缩放因子 `sm_scale = 64^-0.5 = 1/8`）。
  5. 门控输出归一化：对每个查询头的输出独立执行无权重均方根归一化并乘上门控激活，`o_attn = rmsnorm(o_raw, 1e-5) * sigmoid(gate)`。
- 输入：`qkv`（形状 `[B, L, 2304]`，BF16，每词 `4.5 KiB` 即 `4,608 B`，位于 HBM 或 L2）、序列长度 `seq_lens`（`[B]`，`int32`，位于 HBM）、分页页表 `page_table`（`[B, max_pages]`，`int32`，每页存 1 个词元，位于 HBM）以及分页缓存 `K_cache, V_cache`（形状 `[pages, 1, 2, 64]`，FP8 `E4M3`，单卡每历史词元每层占 `2 × 2 × 64 × 1 B =` **256 B**，位于 HBM）。
- 输出与交给下一步：注意力输出 `o_attn`（形状 `[T, 1024]`，BF16，每词 `2 KiB`，写回 HBM 或 L2），交给阶段 3 的 `o` 输出投影；同时新写入的 `K_new, V_new`（每新词 `256 B`，FP8 `E4M3`）留在当前层的 `K_cache, V_cache` 显存页中，供后续时间步复用（见第 0.0 章第 2 节）。
- 三区间代价与瓶颈迁移：
  - 在**区间 I**（逐词解码 `L = 1, T = B`，历史 `ctx = 80,000`）下，滑窗层每请求只读 `2,048 × 256 B = 0.52 MB`（`B = 1` 下界仅 `0.11 µs`、`B = 32` 下界 `3.3 µs`，完全受固定启动与归约延迟限制）；全长层每请求读 `80,000 × 256 B = 20.5 MB`（`B = 1` 执行 `0.328 GFLOP`，算术强度 `16 FLOP/B`，带宽下界 `4.3 µs`；`B = 32` `agentic` 负载共读 `606.5 MB`，带宽下界 `126.4 µs`）。
  - 在**区间 II**（8 词投机检验 `L = 8, T = 8B`）下，同一个请求内的 8 个查询词元共享同一批历史键值页，全长层算术强度提升 8 倍至 `127.5 FLOP/B`（`B = 32, T = 256` 时读 `608.6 MB`、执行 `77.6 GFLOP`，带宽下界 `126.8 µs`、算力时间 `78.5 µs`），仍低于 `206 FLOP/B` 平衡点，但每个词元 8 个查询头 × 8 个检验词已凑齐 `64` 行，必须切入 Tensor Core 执行（见第 5 章第 2 节）。
  - 在**区间 III**（长分块预填充 `L = 753` 或 `16,384`）下，查询词元数暴增使同一键值页被成百上千行查询复用，全长层运算量在 `T = 753 / 3,012` 下达 `248 / 992 GFLOP`，在首轮 `T = 16,384, ctx = 65,536` 下更高达 **4,948 GFLOP**（算力下界约 `5.00 ms`，而读键值缓存仅 `4.4 µs`），彻底翻转为 Tensor Core 与 SFU 管线受限。

从 SGLang 的 5 核基线（依次启动 `FusedQKNorm`、写缓存、查询转 FP8、`flash_attn_with_kvcache` 与 `rms_norm_gate`）迈出的第一步（**演化步 `a0`**），是在踏入主循环前做出的两项结构决策（图 7-1）：
1. **决策一（GQA `8:1` 分组矩阵化，主讲机制）：将同一 KV 头的 8 个查询头叠成矩阵乘的 M 行，让每次键值读取被 8 个头共享**。若按朴素标量设计让每个查询头各自启动线程去读对应的历史键值页，同一个 KV 头的 `128 B/词` 数据会被 8 个查询头从 HBM 重复读取 8 次。`a0` 按 KV 头组织 CTA：在单词解码（`L = 1`）下，把归属同一 KV 头的 **8 个查询头直接排作矩阵乘左操作数 `Q` 的 8 行**（在 8 词 verify `L = 8` 下，8 个词 × 8 个查询头恰好排满 `wgmma` 的 `M = 64` 行），使从显存搬进片上的每一页 `K` 与 `V` 当场与全部 8 个查询头相乘，直接将历史 KV 的 DRAM 读取字节砍到标量设计的**八分之一**（同时将查询 `Q` 在序言中直接量化为 `FP8 E4M3`，使第一段矩阵乘 `Q · K^T` 直接跑在吞吐翻倍的原生 FP8 Tensor Core 上，省去对 `K` 的解包指令，见第 6 节）。
2. **决策二（序言与尾声融合，回指第 1 章第 1 节与第 4 章第 2 节）**：把散落在主核前后的按头归一化、`RoPE`、查询转 `FP8` 与新键值入库合为单次序言启动（在 `T = 1` 整层中更直接折入阶段 1 `qkv_gate` 尾声，见第 9 章；在预填充 `T = 3,012 / 16,384` 中采用每词元 1 个线程组、把方差归约树留在寄存器内的融合序言核，将 `T = 16,384` 序言耗时从 `52.75 µs` 压到 `31.0 µs`），并在预填充注意力主核尾声直接融合 `rmsnorm(out) * sigmoid(gate)`（删去外部 FlashAttention-3 调用与独立 `o_norm` 启动，将全算例总耗时从 `233.07 ms` 压至 `231.36 ms`）。

## 2. 全卡波次与 Split-KV 调度（`a0 → a1`）：当请求长度参差不齐或并发数填不满 132 个 SM 时，怎样切分键值维才既不留长尾波、又不被每块固定开销反噬？

起点内核 `a0` 按“请求数 `B` × 本地 KV 头数 `2`”派发 CTA。这立刻在 132 个 SM 上暴露出两道波次困局：当 `B = 1` 时全卡只有 `2` 个 CTA（130 个 SM 闲置）；即使打开 **Split-KV**（又叫 Flash-Decoding，把长历史键值沿序列维切成 `S` 段并行算出局部加权和 `o_i` 与对数分母 `lse_i = m_i + log2(l_i)`，再由合并核按 `2^(lse_i - lse_total)` 精确重缩放求和），若机械地给每个形状固定切分块数，又会撞上**每 CTA 固定启动开销**与**请求间长度偏斜长尾**的两难。演化步 **`a0 → a1`** 用五项调度决策解开这一困局（图 7-2 模式 1 与图 7-3）。
- **决策一（按并发请求数 `B` 反比调节切分度数 `S`，平衡波次填充与每 CTA `6.6 µs` 固定成本，主例）**：每个 Split-KV 分片 CTA 除了流式处理键值分块（每分块约 `2.04 µs`），还要固定付出约 **`6.6 µs` 的序言、尾声与写出局部缓冲开销**（合并核还要读取全部 `S` 份局部结果）。
  - 在单请求解码（`B = 1` 全长，`T = 1`）下，`128` 路切分仅产生 `256` 个小 CTA（`0.24` 个驻留波次，有效带宽仅 `1.34 TB/s`），将切分数翻倍至 **`256` 路**可挂起更多在途读取，带宽升至 `1.51 TB/s`，实测省下 **1.07–1.42 µs**（NCU 核耗时 `15.52 → 13.82 µs`）。
  - 反之，当并发请求升至 **解码 16 与 32 请求全长（`T = 16 / 32`）** 时，若仍沿用 `128 / 64` 路切分，总 CTA 数会膨胀到 `3.88` 个波次，数千个 CTA 重复支付 `6.6 µs` 固定成本并塞满合并核；将切分数果断下调为 **`32 / 16` 路**（合并核缩为 2 个 warp），在解码 16 与 32 请求全长上立省 **12.10 µs（`+12.9%`）与 9.74 µs（`+5.6%`）**！同理，在 **verify 16 / 32 请求全长（`T = 128 / 256`）** 上将切分从 `32` 路减半为 **`16` 路**，合并核读取的部分和减半（耗时从 `7.87 / 12.58 µs` 降至 `5.70 / 7.58 µs`），实测省下 **2.54 µs 与 7.74 µs**；但若继续砍到 `8` 路切分，总块数跌至 `0.48` 个波次，耗时立刻**暴涨 `+101 µs`**。
- **决策二（264-CTA 虚拟键空间等分 `FLAT` 与按实际键数比例切分，主例，图 7-2 模式 1）**：在 `agentic` 负载下，各请求历史长度在 `±7.5%` 内均匀分布（最长约为最短的 `1.16` 倍）。若给每个请求机械分配相同数量的切分块，长请求 CTA 会比短请求慢约 **15%** 并拖出尾波（见第 2 章第 1 节）。`a1` 在 **verify 32 请求全长（`T = 256`）** 上直接启动 **`264` 个 CTA（`2 × 132` 个 SM，刚好凑满 `1.00` 个整波次，消除原 `256` CTA 的 `0.97` 波次空槽）**，将 32 个请求的虚拟键值空间拼成一条连续带（每个请求边界预留 5 个虚拟分块），让每个 CTA 领走相等的键值页数（每 SM 最少活跃周期占比从 `63.8%` 跃升至 `94.9%`）。在 verify 32 请求全长上，P1 实测缩短 **3.90 µs**，P3 缩短 **9.5 µs**（verify 16 请求全长缩短 `2.0 µs`；在预填充 `T = 16,384` 全长层上，把 `1,366` 个 CTA 即 `10` 波余 `46` 块中最轻的 40 个查询块各拆成 4 个子块扩为 `1,606` 个 CTA，同样在 `ctx = 32K / 65K` 上直接省下 **210 µs 与 345 µs**）。在图 7-2 模式 1 中切换两种切分方式，读数分别为：`按请求切分：收尾 = 最长 CTA，长 CTA 慢约 15%` / `比按键数切分多 3.90 µs（P1）/ 9.5 µs（P3），32 请求全长`，以及 `按实际键数切分：6 个 SM 同时收尾` / `比按请求切分少 3.90 µs（P1）/ 9.5 µs（P3），32 请求全长`。
- **决策三（网格启动顺序重排让共享同一 128 B 键值行的两个 CTA 相邻启动，主例，图 7-3 中间）**：在单头全长 verify 内核中，两个 KV 头的键值存放在同一个离散 128 B 行里（每头占 64 B 半行）。将网格维度顺序排为 `(HKV, batch, splits)`，使读取同一随机 128 B 行前半段和后半段的两个 CTA 紧挨着先后启动；第二个 CTA 发起读取时，第一个 CTA 刚从 HBM 拉回的 128 B 缓存行仍驻留在 60 MiB L2 中，零寄存器与共享内存代价就在 **verify 32 请求全长（`T = 256`）** 上实测省下 **11.90 µs（`+4.4%`）**（在 verify 16 请求全长上为中性）。
- **决策四（跳过空切分块与无效掩码区，主例，图 7-3 下方）**：当切分数固定时，短序列或滑窗边界处会出现 `start >= end` 的空分片。`a1` 让空分片只写出 `lse = -inf` 而不写全零的局部输出张量 `po`，由合并核直接按 `lse == -inf` 掩码跳过读取（比特级精确；在预填充中则配合 `Q_CHUNK = 8` 紧致因果/滑窗键界与掩码/非掩码分块列表，从源头省去无效掩码区计算）。
- **决策五（按形状路由表分派最优内核，主例）**：没有任何单一内核或切分参数能通吃三个物理区间。`a1` 建立按 `(batch, q_len, window)` 索引的静态分派表（例如在 verify 16 请求滑窗切换为单头 `vws` 核省 `1.06 µs`、在 verify 16 请求全长将双头 `vw2` 门槛从 `32` 降为 `16` 省 `2.24 µs`、在 verify 16 请求滑窗将集群数从 `NS = 8` 缩为 `7` 消除 16 个 3-CTA SM 争抢省 `1.31 µs`［机制见第 3 章第 1 节］），全 12 个评测形状加权几何平均耗时从 `3,473.0 µs` 降至 **3,193.4 µs（提速 `-8.05%`）**。
- **什么时候变成亏本（请求内动态偷取分块的实测反例）**：既然静态切分需要精心计算比例，能否像第 8 章的持久专家核那样，给每个（请求, KV 头）设一个全局原子计数器，让同组 CTA 动态认领（steal）键值分块？实测在注意力中这是灾难性的反例：因为注意力的单个 64-key 分块耗时不到 `1 µs`（远小于专家核每作业 `17 µs`），每次动态认领的元数据交接与 128 线程 `bar.sync` 使单分块成本直接上涨 `10%` 并打断页表预取，在 **verify 32 与 16 请求全长**上反而**暴跌 `+22.6 µs` 与 `+10.0 µs`**；同理，尝试在分块区入口用 `acq_rel CAS` 动态接管槽位会排空 `cp.async` 环形缓冲，在 verify 32 请求全长上**暴跌 `+18.90 µs`** 被否决（阶段树早期仅做纸面估算的 LPT 排序也因未实测验证而未合入）。

## 3. 分页 KV 收集与记分牌破链（`a1 → a2`）：当每页只有 1 个词元、每次读键值都要走三跳指针追踪时，怎样藏住 640 ns 页表往返并防住预取冲刷？

<!-- FIG ch08-a1: 图 7-4 画第 3 级打破三跳指针追踪链与小表片上预载数据流（对应阶段 2 P1 分页注意力入口“读 seq_lens（600 ns）→ 读 page_table（640 ns）→ 发 cp.async（1,150 ns）”三跳串行长记分牌等待、单请求满长投机并发与跨轮提前流水化，以及阶段 6 P2 专家入口把 64 个浮点缩放小表预载入 SMEM 的算法步）。 -->

在 `a1` 排平全卡 132 个 SM 的波次后，打开单个 CTA 的指令剖析器，瓶颈落在了分页 KV 缓存的离散收集（`page_size = 1`）上。因为 Hopper 的硬件 TMA 不支持按索引列表收集离散的 64 字节或 128 字节行，注意力内核只能用 `cp.async` 逐行收集（首先在布局上将两个 KV 头合并为整条 128 B 行、每行 8 个线程各发 16 B `cp.async` 并配 128 B XOR Swizzle，把随机行带宽从 64 B 半行的 `2.6–3.1 TB/s` 拉到 `4.0–4.1 TB/s`，在解码 32 请求全长与滑窗上分别省下 `15.58 µs` 与 `2.11–2.27 µs`，机制见第 3 章第 2、5 节；同时给页表加载打上 `evict_last` 留存提示，见第 2 章第 3 节）。即便如此，剖析器仍显示在首次使用页表加载结果的指令（`IMAD.WIDE`）处，有 **37%–42%** 的停顿卡在第 4 章第 2 节的长记分牌上。

为什么 `cp.async` 环形缓冲没能藏住这段等待？因为读取一个历史键值页必须走三跳 **pointer chasing**（指针追踪）串行链（图 7-4 模式 1）：第 1 跳从全局内存读序列长度 `seq_lens[b]`（约 `600 ns`），第 2 跳用算出的页号读离散页表 `page_table[b, page]`（约 `640 ns`），到第 3 跳才能拿到物理页地址并发起 `cp.async` 搬运（约 `1,150 ns`）。后一跳的地址依赖前一跳返回的数据，在 **verify 1 请求全长算例（`T = 8`）** 上实测串行耗费 **2,400 ns**（约 `2.4 µs`）。演化步 **`a1 → a2`** 用两项页表延迟隐藏决策拆开这条串行链（图 7-4 模式 2 与模式 3），并配合序言前置加载（把不依赖前序结果的 `sigmoid(gate)`、等分块边界、`seq_lens` 读取放在 PDL 等待之前，只让持有新写入行的那 1 个 CTA 执行块内屏障，以及把滑窗序言的 4 代串行加载合并为 1 代并发发出，省 `0.11–1.05 µs`，机制见第 3 章第 3 节；在主循环中则用 6 分块展开配 `pg_a / pg_b` 奇偶两套页号寄存器消除 `if` 汇合处的假拷贝等待，省 `0.16–0.86 µs`，见第 4 节）。
- **决策一（页表索引跨 4 块提前预取 `tile j + 4` + PDL 等待前预载前 4 块，主例，图 7-4 模式 3）**：为了让 `640 ns` 的页表读取彻底离开每轮 `cp.async` 的发射关键路径，`a2` 在解码内核中用寄存器随身携带第 `j + 2` 与 `j + 3` 分块的 `int32` 页表项，并在第 `j` 轮循环中提前发出第 **`j + 4`** 分块的页表读取（同时在序言进入等待前先把第 `0..3` 分块的页表项读出来，并将解码滑窗 16 / 32 请求的 `cp.async` 环加深为 3 级）。这样当主循环走到第 `j + 4` 轮时，物理页号早已在寄存器中就绪，在 **解码 1 请求全长、解码 16 请求滑窗、解码 16 请求全长与解码 32 请求滑窗** 上实测分别省下 **0.18–0.26 µs、0.35–0.53 µs、0.99–1.58 µs 与 0.50–0.74 µs**（在双头 verify 内核中同样在第 `k` 轮屏障前发出第 `k + 1` 轮页表读取，该变体的单独收益未分离测量；图 7-4 模式 3 读数为：`跨轮提前流水化：第 k+1 轮的页表读取藏进第 k 轮` / `这一项的单独实测收益 UNKNOWN（记录里没有）`）。
- **决策二（单请求满长投机并发读取，图 7-4 模式 2）**：在 **解码 1 请求全长算例（`T = 1`）** 中，内核在入口不等第 1 跳 `seq_lens[0]`（`600 ns`）返回，直接根据页表数组跨度（`pt_stride`）猜测键值范围，把第 2 跳（第 `0..3` 分块的页表读取）与第 1 跳 `seq_lens[0]` **同时发出**，并在 `griddepcontrol.wait` 之前校验猜测（猜错则回退，实测全猜错代价为 `0.000 [-0.016, +0.016] µs`）。这把前两跳从串行压成并发（范围就绪时间戳从 `1,024 ns` 提前到 `832 ns`，首组 `cp.async` 发射从 `1,248 ns` 提前到 `1,088 ns`），在解码 1 请求全长上实测省下 **0.26 µs**（`-0.256 µs`；移植到 P3 解码注意力后在 16 / 32 请求全长上也分别提速 `0.53%` 与 `0.45%`）。图 7-4 模式 1 与模式 2 的读数分别为：`3 跳串行：每跳只有 1 条独立指令，约 2.4 µs（verify 1 请求全长算例实测 2,400 ns）` / `首次使用页表结果的 IMAD.WIDE 处，37%–42% 的停顿是长记分牌（P1 记录，形状 UNKNOWN）`，以及 `投机并发：前两跳同时发出，长记分牌等待从 3 次变 2 次` / `解码 1 请求全长算例实测省 0.26 µs`（图 7-4 模式 4 的缩放小表片上预载读数 `小表放进 SMEM：每次查询 328 周期（L2 命中）→ 23 周期` / `verify 16 / 32 请求算例实测省 0.47–0.55 µs；SASS 全局读取 36 → 21 条` 属阶段 6 专家核，将在第 8 章展开）。
- **什么时候变成亏本（预取过远触发寄存器溢出、提前循环挤占第 0 块队列、以及 L2 预取被冲刷的四个实测反例）**：
  1. **页表预取距离过远撑爆 32 寄存器预算**：既然提前预取页表有效，能否在 verify 32 请求全长的双头内核里把页表 `LDG` 的领先距离从 82 条指令拉大到 152 条指令？实测结果反而**变慢 `+2.4% / +2.6%`**！这是因为生产者分区仅有 32 个寄存器预算，更长的在途生命周期直接引发 `28 B` 写出与 `56 B` 读入局部内存溢出（且微扰删除实验证实，把该核的页表加载彻底删掉的天花板也仅快 `1%–2%`，见第 10 章第 4 节）。同理，在第 8 章的 MoE 核中尝试两级权重预取或地址外提，也因寄存器从 `72` 涨到 `91` 个、每 SM 驻留从 `5` 跌到 `4` 个 CTA 而**暴跌 `+6.88..+26.54 µs`**。
  2. **盲目把循环起点提前却不缩短循环终点（`K-end`）**：在解码全长核中尝试把序言重排使主循环提前 `1.0–2.1 µs` 启动（或批量加载页号），实测在解码 16 / 32 请求全长上反而**变慢 `+0.13..+0.56 µs`**（verify 1 请求全长慢 `+0.11..+0.16 µs`）——因为提前发出的请求排在第 0 分块前面占住了显存队列，使第 0 分块的等待时间等量拉长，内核结束时刻分毫无损。
  3. **在合并核里无条件预载局部输出 `po`**：尝试在合并核判断 `lse` 掩码前提前并发预载 `po`，导致在 verify 16 请求全长上多读了 2 倍的无效分片字节，实测反而**变慢 `+0.80 µs`** 被否决。
  4. **在 PDL 等待前发 `cp.async.bulk.prefetch.L2` 预取页表被 KV 流冲出（图 7-5 模式 2 反例，回指第 2 章第 3 节）**：单线程在 PDL 等待前把页表切分块预取进 L2，因中间流过数 MB 的 KV 数据把预取行冲出 60 MiB L2，导致页表从 DRAM 读了两次，在解码 16 / 32 请求全长上多读 **`4.3 / 8.5 MB` 显存**、变慢 `0.03–0.53 µs`（图 7-5 模式 2 读数为：`不预取：页表行 DRAM 读 1 次` / `作为对照基准` 与 `PDL 等待前预取：页表行 DRAM 读 2 次` / `全卡多读 4.3–8.5 MB · 耗时多 0.03–0.53 µs`；模式 1 的 `pooler` 多播读数 `各 SM 独立单播：事件时间 0.849 ms` / `L2 读取 8.8 TB/s · 每个 SM 68.3–69.6 B/ns` 与 `开启多播：事件时间 1.812 ms（慢 2.1 倍）` / `L2 读取 3.0 TB/s · 每个 SM 32.4 B/ns` 见第 3 章第 4 节）。

当注意力进入 8 词 verify（`T = 128 / 256`，区间 II）与长序列预填充（`T = 753..16,384`，区间 III）时，每个分块的矩阵乘切换进 4-warp 协同的 `wgmma`（见第 5 章第 3 节），瓶颈随之从显存等待转变为 **CTA 内部的生产者/消费者角色争用** 与 **SMSP 发射槽上的冗余指令开销**。演化步 **`a2 → a3`** 用四项核内重构解开这一瓶颈（图 7-6 与图 7-7）。
- **决策一（双头共驻单 CTA + 生产者设为默认分区消除跨 `setmaxnreg` 8 B 溢出，主例，图 7-7 上方）**：在 **verify 32 与 16 请求全长（`T = 256 / 128`）** 中，本卡的 2 个 KV 头各自拥有同一请求的历史页表。`a3` 将 2 个 KV 头合进同一个双头内核（`vw2`，每线程 80 寄存器，每 SM 驻留 2 个 CTA）：由 1 个生产者分区按每词元一条 `256 B` 宽行一次性收集两个 KV 头的数据，同时喂给 2 个 4-warp 消费者 warpgroup（每组负责 1 个 KV 头的 8 个查询头 × 8 个检验词 = 64 行 `wgmma`），单是合为双头收集就在 verify 32 请求全长上省下 **4.80 / 3.97 µs**（将 verify 16 请求全长也切入该双头核再省 `2.24 / 2.30 µs`）。
  然而在编写线程束分工（`warp_specialize`，机制见第 3 章第 1 节）时，若按惯例把消费者当作默认分区，编译器会把生产者的一个键值行变量提升到工作分区派发点之上；当各分区随后执行 `setmaxnreg` 重划寄存器配额时，这个跨越配额边界的存活变量会直接触发 **8 字节局部内存溢出（Spill）**！将**生产者反过来设为默认分区**并配合消费者循环剥离后，8 字节溢出彻底归零，全核指令数减少 `2.2%`、分支减少 `23%`、长记分牌停顿减少 `18%`（NCU 核耗时从 `248.90 µs` 骤降至 `229.44 µs`，发射槽活跃度从 `51.5%` 升至 `55.1%`），在 **verify 32 请求全长**上实测一举省下 **15.78 / 15.46 µs（`+6.8%`）**——这是 P1 全程单步最大的实测收益！
- **决策二（两个消费者 warpgroup 通过命名屏障 4/5 乒乓交错，主例，图 7-7 中间）**：在双头内核（`vw2`）内部，两个消费者 warpgroup 若同时挤向 Tensor Core 发射 `wgmma`、又同时停下跑在线 Softmax 与 `V` 转置，会导致矩阵管线与算术管线交替空转。`a3` 引入两条 256 线程的命名屏障（`bar.sync 4, 256` 与 `bar.sync 5, 256`），让两个消费者 warpgroup 错开半拍轮流进入 `[QK(0)]` 与随后的 `[PV(j), QK(j+1)]` 矩阵乘窗口：当第 0 组在跑在线 Softmax 与 `V` 准备时，第 1 组独占 Tensor Core 连续发射 `[PV(j), QK(j+1)]`，反之亦然，在 **verify 32 请求全长**上实测再省 **2.32 / 1.65 µs（`+0.94%`）**。
- **决策三（无掩码内部循环与有掩码边界循环剥离，主例，图 7-7 下方）**：在 8 词 verify 与长分块预填充中，绝大部分历史键值分块都完全落在因果与滑窗视野内部（无掩码），只有最后几个边界分块才需要逐元素判断因果或窗口掩码。`a3` 在 `nu = (unmasked_end - start) // BLOCK_N` 处把消费者主循环一分为二：前半段跑不含任何位置掩码分支的紧凑循环，后半段只对边界分块跑带掩码循环，在 **verify 16 请求全长（`T = 128`）** 上实测省下 **3.38 / 2.56 µs（`+2.74%`）**（在早期双头核未解决第 1 条的寄存器吃紧前直接做剥离曾引发 8 B 溢出，待默认分区修复后才顺利合入）。
- **决策四（全 warp 一致变量提纯进统一寄存器 `UR` + 解码 6 分块 `pg_a / pg_b` 轮换 + 消除栈帧与 64 位软件除法，图 7-6 模式 2）**：在预填充全长注意力消费者主循环中，将全 warp 相同的环槽号、相位位与矩阵描述符从私有向量寄存器 `R` 移入每个 warp 共用的 **uniform register**（统一寄存器 `UR`），外提 `Q` 与全 `1` 描述符，并将每分块一次的 128 线程 `bar.sync` 改为 12 个消费者 warp 在 `wgmma.wait_group<0>` 后各自独立向 `EMPTY` 的 `mbarrier` 报到，使非上抬路径每分块静态指令从 `304` 条降至 **284** 条（未掩码循环 `354 → 334` 条，预估目标约 `269` 条）。在图 7-6 中选模式 2（模式 1 读数 `串行 256 步 → 8 个 warp 并行：每个 warp 1 次读 + 1 次 ballot + 1 次 popc` / `ballot+popc+bfind 约 40 周期；单 token 与 8-token 算例合计省 0.62 µs 与 2.46 µs` 属阶段 6 专家路由，见第 8 章），读数为：`UR：不上抬路径每分块指令 304 → 284 条（预估目标约 269）` / `与归一化融合同轮合并：比上一步提速 0.60%，比更早的统一注意力版本提速 1.35%`。同时在解码与滑窗核中：(1) 将主循环展开为 6 个分块一轮，偶数块用 `pg_a`、奇数块用 `pg_b` 寄存器，彻底消除 `if` 汇合点复制未就绪 `LDG` 结果引发的前三大假记分牌停顿（在解码 32 请求全长上省 **0.86 / 0.70 µs**）；(2) 对 `vw_qprep` 加 `__forceinline__` 消除函数调用栈帧的 `STL / LDL` 局部内存往返，并将 `FLAT` 切分中的两处 64 位有符号除法（`__cuda_sm20_div_s64` 软件例程）替换为 32 位无符号除以 `gridDim.x`（在 verify 16 滑窗、32 滑窗与 32 全长上省 **0.24、0.22 与 0.40 µs**）；(3) 在单请求滑窗核中删去 3 个永不执行的死分块循环（寄存器 `110 → 72`，SASS `2,672 → 1,248` 行，省 **0.40–0.48 µs**），在滑窗 `K1 / K1V` 中改用 `ldmatrix.trans` 收集 `V^T`（LSU 指令减 `28%–41%`，提速 `1.2%–2.6%`）。
- **什么时候变成亏本（单 CTA 双头下放到解码慢 2 倍、只锁 `[QK]` 窗口慢 `4.8 µs`、以及乒乓压浅环深慢 `2.5 µs` 的三个实测反例）**：
  1. **在单词解码（`L = 1`）下强行用 1 个 CTA 服务 2 个 KV 头**：在 8 词 verify（`T = 256`）下双头共驻 1 个 CTA 大赢 `4.80 µs`，但当在另一赛道的解码（`B = 16 / 32, L = 1`）上把两个 KV 头塞进同一个 CTA 时，全卡 CTA 总数直接减半，实测在两档批量上反而**慢了整整 2 倍（`0.543× / 0.549×`）**！因为 `L = 1` 下单个 KV 头只有 8 行查询，合进同一 CTA 既填不满 `wgmma` 又砍半了全卡并发度。
  2. **乒乓调度只包裹 `[QK(j)]` 而不合并 `[PV(j), QK(j+1)]` 窗口**：在 `vw2` 乒乓试验中，若让命名屏障只夹住单次 `[QK(j)]`，每轮多出的两次 256 线程同步等待反而使 verify 32 请求全长**变慢 `+4.5 / +4.8 µs`**。
  3. **为凑双组乒乓而把环形缓冲槽数从 3 槽砍成 2 槽**：在第 8 章的 MoE 持久核中尝试同样的双消费者组乒乓时，为在 228 KiB SMEM 内塞下双倍 `x` 缓冲，被迫把 36 KiB 权重环从 3 槽（在途 `72 KiB`）压成 2 槽（在途跌至 `36 KiB < 48 KiB` TMA 平台，见第 3 章第 4 节），结果在 verify 16 / 32 请求上反而**变慢 `+1.17..+2.47 µs`**（160 个种子中 155–160 个变慢）被否决。

## 5. 攻克 Online Softmax 与 4 通道 SFU 瓶颈（`a3 → a4`）：怎样跳掉非必要的历史重缩放，并把指数运算搬上 ALU/FMA、把行求和搬上空闲的 Tensor Core？

在 `a3` 理顺 Warpgroup 分工与标量控制后，注意力消费者循环里最沉重的算术包袱浮出水面——**在线 Softmax**。在每处理一个键值分块时，标准在线 Softmax 要依次执行四件事：(1) 求当前分块每行最大值 `m_tile` 并与历史最大值 `m_old` 比较；(2) 一旦 `m_tile > m_old`，立刻调 `exp2f(m_old - m_new)` 把此前累加的输出向量 `O` 和分母 `l` 重缩放一遍；(3) 对当前分块每个分数调 `exp2f` 算出注意力权重 `P` 并打包成 `FP8 E4M3`；(4) 将 `P` 按行求和累加进分母 `l`。
回顾第 5 章第 1 节，每个 SMSP 的特殊函数管线（SFU / XU）只有 **4 条通道**，发射间隔（8 周期）是 32 通道 FMA 管线（1 周期）的 **8 倍**！在 P3 的 64-key 分块循环（共 `288` 条 SASS 指令）中，Softmax 一项就占去 **58%** 的指令；而在 P5 的 128-key 分块循环中，每个 warp 每块要发 `64` 条 `MUFU.EX2`，使 XU 管线占用率高达 **77.3%**，单是 SFU 一项就锁死了每分块 `1,548` 个周期的物理下界。演化步 **`a3 → a4`** 用三项跨管线手术彻底解开这一瓶颈（图 7-8 与图 7-9）。

- **决策一（固定参考与 `__any_sync` 投票惰性重缩放，消除非必要的历史 `O` 重缩放链，主例，图 7-8 模式 1）**：标准在线 Softmax 逢新最大值就重缩放，是为了防 `exp2f` 上溢。但在赛题给定的归一化查询与键值下，当权重 `P` 存为 `BF16`（单精度指数上限 `2^127`）时，输入对数分数绝对值有界（`|s| ≤ 71.3` 对数单位）。
  - 在 `P` 为 `BF16` 的双头全长内核中，直接以固定上限 `72` 为参考计算 `p = exp2(min(s * qk_scale, 72))`，省去每块的行最大值归约、`alpha` 因子与历史 `O` 重缩放链，在 **verify 16 与 32 请求全长（`T = 128 / 256`）** 上实测立省 **2.77 / 2.66 µs 与 6.69 / 6.38 µs**！
  - 当下一节把 `P` 进一步压成量程较窄的 `FP8 E4M3`（最大正规数 `448`）时，改为保留第 0 块参考最大值，每轮由全 warp 执行一次 **`__any_sync` 投票**：给指数留出 `2^T` 余量（使 `P' = 2^(8-T) p ≤ 256 < 448`），只有当某行新分块最大值超出参考值加阈值 `T` 时才触发重缩放分支。在单头全长核中开启投票重缩放（使全核执行的 `FMUL` 从 `0.50 M` 降至 `0.17 M`），在 **verify 1 请求全长（`T = 8`）** 上省 **0.38 µs**；在单头滑窗核中设 `T = 8`，在 **verify 32 / 16 请求滑窗**上省 **0.83 / 0.14 µs**；在双头全长核中将阈值从 `T = 4` 放宽到 `T = 6`（使触发率从每块 `7%–18%` 进一步降到 `2%–8%`），在 **verify 32 / 16 请求全长**上再省 **1.42 / 0.46 µs**（预填充全长核同样用 `__any_sync` 跳过未抬升重缩放）。图 7-8 模式 1 读数为：`惰性重缩放：SFU 不再逢新最大值就调 exp2f` / `vw2 T = 4 → 6 省 1.42 / 0.46 µs（verify 32 / 16 全长）；vws T = 8 省 0.83 / 0.14 µs（verify 32 / 16 滑窗）；vw 投票省 0.38 µs（verify 1 全长）`。
- **决策二（管线重平衡：用 Mitchell 线性近似在 ALU/FMA 上直接生成 `FP8 E4M3` 指数编码，并把行求和 `P × 1` 搬上空闲 Tensor Core，主例，图 7-8 模式 2 与图 7-9 模式 3）**：
  1. **指数从 4 通道 SFU 迁往 32 通道 FMA + 16 通道 ALU（图 7-9 模式 3）**：因为注意力权重 `P = 2^y` 紧接着就要量化为 1 字节 `FP8 E4M3` 送进 `QGMMA`，而 `2^y` 的 `E4M3` 无符号字节整数值近似等于线性函数 **`8(y + 7)`**（`E4M3` 的 3 位尾数自然构成 Mitchell 分段线性近似 `2^f ≈ 1 + f`），P5 直接在空闲的 FMA 与 ALU 管线上用饱和乘加（`FFMA.SAT` 将 `y` 映射到 `u = (y + 7) / 15`）、打包半精度乘加（`n = 120u`）与 `PRMT` 字节提取一步算出 `E4M3` 权重字节（行求和 `l` 仍用同一批 `P` 字节乘全 `1` 矩阵算出，保持分子分母自洽）。这把每分块的 `MUFU.EX2` 从 `66` 条骤降到 **2** 条（仅留行最大值重缩放），NCU 实测 XU 管线占用率从 `77.3%` 暴跌至 **0.58%**，单分块周期从 `2,003` 降至 `1,645.6`（`ctx = 65K` 全长注意力核耗时从 `6,651.9 µs` 降至 **5,471.4 µs**），在预填充全长与滑窗注意力上分别使整层实测提速 **2.33% 与 0.55%**（将该 Mitchell ALU 指数移植到 P3 解码/verify 注意力同样把每包发射槽从 80 压到 72 条，使整层提速 `0.12%`、达到 P3 排行榜最高的 `2.1958×`）。图 7-9 模式 2 与模式 3 读数分别为：`惰性重缩放：减少 exp2f 的调用次数，而不是改指令` / `P1 vw2 T = 4 → 6 省 1.42 / 0.46 µs（verify 32 / 16 全长）；vws T = 8 省 0.83 µs（verify 32 滑窗）`，以及 `ALU/FMA 直接生成 E4M3 字节：SFU 32 周期 → 0，发射槽 4 → 约 10（每 4 个值）` / `每个分块 MUFU.EX2 66 → 2 条；整层实测提速 2.33%`。
  2. **行求和 `P × 1` 从 FMA/洗牌管线迁往空闲 Tensor Core（图 7-8 模式 2）**：在 P3 全长 verify 注意力中，按行累加 `64 × 64` 权重矩阵 `P` 原本要在算术管线上发 `38` 条 `FADD` 加 `4` 条洗牌指令（共 `42` 条），把发射槽塞满而此时 64 行宽的 Tensor Core 正空闲。在 SMEM 中放一块全为 `1.0` 的常数矩阵，直接发出 **4 条 `wgmma.m64n8k16`** 计算 `P × 1`（每条算 16 列，4 条覆盖 64 列），净省 **38** 条指令（42 减 4），在 P3 的 **verify 16 / 32 请求全长**上分别缩短 **3.9 / 3.4 µs**；在 P1 发射槽受限的双头全长核（`vw2`）中补回 `QGMMA` 行求和（配合保持 `P · V` 在途）同样使全核指令数减少 **13%**（单精度算术指令减 `56%`），在 verify 16 / 32 全长上缩短 **1.6%–2.6%**。图 7-8 模式 2 读数为：`行求和：38 条 FADD + 4 条 SHFL → 4 条 wgmma；P3 verify 16 / 32 请求全长缩短 3.9 / 3.4 µs` / `P1：Tensor Core 受限的 vw / vws 删掉它反省 0.25–0.26 / 0.13 µs；发射槽受限的 vw2 补回它，指令 -13%，缩短 1.6%–2.6%`。
- **决策三（用 `f16` 非规格化数舍入打包与 `VHMNMX` 三输入最大值树夺回发射槽，主例）**：把指数从 SFU 挪到 ALU/FMA 后，每 4 个权重值占用的发射槽从 4 条涨到了约 9–10 条；微扰删除实验（见第 10 章第 4 节）显示，此时字节打包链与每行 62 条 `FMNMX` 最大值树分别占去预填充全长注意力耗时的 **24.5% 与 9.7%**。`a4` 紧接着连砍三刀指令数：(1) 把 `FFMA.SAT` 系数乘上 `2^-21` 使 `t = n × 2^-24` 落入半精度非规格化数区间（最小步长恰好为 `2^-24`），让 `cvt.rn.f16x2.f32` 在硬件转换时直接把 `n` 舍入为整数，每 4 个值删掉 2 条 `HFMA2` 与 2 条 `MOV`（全长核省 64 条、滑窗核省 96 条 `HFMA2`），在 `ctx = 65K` 全长核上立省 **78.3 µs**，整层提速 **0.96%**；(2) 将行最大值归约与 `E4M3` 编码合并为打包 `f16x2` 指令（被 `ptxas` 融合为三输入 `VHMNMX` 比较指令加 1 条带 `1024` 偏置的 `f16x2` 乘加），使 `FMNMX` 从 `138` 条降至 **14** 条、每分块再省 **28** 条指令，整层提速 **0.60%**（达到 P5 排行榜最高的 `1.7963×`；在 P3 verify 全长核中把 32 条 `FMNMX` 换为 16 条单调位等价的 `min.bf16x2` 同样使循环从 `250` 降至 `234` 条指令，提速 **0.74% / 0.54%**）。
- **什么时候变成亏本（`ex2.approx.f16x2` 伪打包、FMA 多项式指令膨胀、Tensor Core 反向抢占与阈值越界的六个实测反例）**：
  1. **`ex2.approx.f16x2` 半精度打包指数在 Hopper 上不省 SFU 周期（图 7-9 模式 1 反例）**：Hopper 的 4 通道 SFU 是纯标量硬件，`ptxas` 会把一行 `ex2.approx.f16x2` 拆成 **2 条串行的 `MUFU.EX2.F16` 加 1 条 `PRMT`**，SFU 周期分毫无省，反而多占 2 周期 ALU（图 7-9 模式 1 读数：`f16x2：2 × MUFU.EX2.F16 + 1 × PRMT，SFU 每个值的时间与 f32 相同` / `SFU 周期按 8/条估算（半精度版未单独实测）；PRMT 多占 ALU 2 周期`）。
  2. **用通用 FMA 多项式模拟 `exp2` 引发指令膨胀**：在预填充全长核中尝试用多项式（`emu2 / emu4`）在 FMA 上算 `exp2`，每消掉 1 条 `MUFU` 要多发 **7.5 条指令**，在发射槽受限下实测反而**变慢**被否决；同理，不触发 `VHMNMX` 三输入融合的 `f16x2` 最大值变体每分块多出约 24 条指令，实测比融合版**慢约 `0.46%–0.55%`**；而在 P3 中把 Mitchell ALU 指数换回值精确的 `MUFU.EX2` 版，因 XU 已 `52%` 忙，实测在 verify 16 / 32 全长上**倒退 `-0.86% / -0.78%`**。
  3. **在 Tensor Core 受限的内核里强行用 `wgmma` 求行和**：在 P1 的单头全长与滑窗内核（`vw / vws`）中，Tensor Core 周期本身是瓶颈，把 `wgmma` 行求和**删掉**（每块 `HGMMA` 从 `16 / 24` 减半为 `8 / 12` 条）反而在 verify 32 滑窗与 verify 1 全长上**省下 `0.25–0.26 µs` 与 `0.13 µs`**。
  4. **惰性重缩放阈值 `T = 8` 突破 `FP8` 精度门限**：在 `vw2` 中把阈值从 `T = 6` 推到 `T = 8` 虽快 `3.74 / 1.44 µs`，但因小权重下溢超出容差被拒；同核多加 64 条指令的 `C1` 变体在 verify 16 / 32 全长上**慢 `+5.2 / +9.2 µs`**；等指令数重排 `EX2/pack` 顺序（因 `ptxas` 已将 12 条 `EX2` 塞进 `FFMA` 块内无空隙）与滑窗投票跳过重缩放也均无收益被拒。

## 6. 原生 FP8 `P·V`、跨轮重叠与免启动归约收官（`a4 → a5 → a6`）：怎样把 `P·V` 搬上吞吐翻倍的 `QGMMA`、把 `V` 转置藏进 `Q·K^T` 阴影，并在核内直接完成跨分片归约？

<!-- FIG ch08-b2: 图 7-10 画第 4 级 P1 原生 FP8 QGMMA 及跨管线异步重叠时间线（对应阶段 2 在发出 Q·K^T 的 wgmma 后、wait_group<0> 之前利用 1 条 LDSM + 8 条 PRMT + 8 条 STS 并行完成 V 分块转置，以及在 verify 16 请求全长上让 P·V 的 FP8 QGMMA 跨入下一轮 wait_group<1> 重叠的算法步）。 -->

当 `a4` 解开在线 Softmax 之后，注意力主循环与出站边界还剩最后两块硬骨头：一是第二段矩阵乘 `P · V` 与第一段 `Q · K^T` 之间的转置与排空等待（`a4 → a5`）；二是分片算完后还要单独启动一个合并 kernel 把各 Split-KV 分片加起来（`a5 → a6`）。
- **第一步（`a4 → a5`：将 `P · V` 搬上原生 FP8 `QGMMA`、在无掩码块用 `F16` 累加 `Q · K^T`，并把 `V` 转置藏进 `Q · K^T` 阴影，主例，图 7-10）**：
  1. **原生 FP8 `QGMMA` 计算 `P · V`（取代半精度过渡环）**：分页缓存里的 `V` 原本就是 1 字节 `FP8 E4M3`。早期版本先由生产者把 `V` 从 `E4M3` 解包转成 2 字节 `FP16` 存入双缓冲环（虽然比转 `BF16` 省了消费者转换并在解码 1/16/32 全长与 verify 16 全长上省 `0.32–2.62 µs`，但仍占用了转换指令与双倍共享内存）。`a5` 直接把在线 Softmax 产出的权重 `P` 量化为 `FP8 E4M3`（在双头全长核 `vw2` 中按 `2^(8-T)` 缩放并将惰性阈值从 `15` 调为 `T = 4`），直接调用吞吐翻倍的原生 FP8 Tensor Core 指令 **`QGMMA`**（`wgmma.m64n64k32.f32.e4m3.e4m3`，机制见第 5 章第 4 节）计算 `P · V`。这一举删掉了每分块 `V` 的解包转换并省下 `8,192–16,384 B` 共享内存（P3 全长 verify 核 SMEM 从 `107,648 B` 降至 `93,312 B`）：在 P1 双头全长核（`vw2`）的 **verify 32 与 16 请求全长（`T = 256 / 128`）** 上实测立省 **8.77 µs 与 3.04 µs**（注：早先草稿曾误把 `8.77 µs` 记在 `T = 4` 惰性阈值名下，实查记录证实它是切换原生 FP8 `P · V` 的收益），在单头滑窗核（`vws`）的 **verify 32 请求滑窗**上省 **0.74–0.77 µs**，在 P3 的 **verify 16 / 32 请求全长**上同样提速 **1.51% 与 2.13%**。同时，在 P5 预填充的无掩码内部完整分块上，因为归一化查询保证了 `|S| ≤ 30,464 < 65,504`，将第一段 `Q · K^T` 的累加器直接设为半精度 `F16`（`wgmma...m64n128k32.f16.e4m3.e4m3`，机制见第 5 章第 4 节），一举删掉每分块 **34 条 `f32 → f16x2` 转换指令**并释放 **32 个累加器寄存器**，使 `ctx = 65K` 全长注意力核耗时再降 **14.5%–16.8%**、单步整层提速 **1.79%**！
  2. **把 17 条 `V` 转置指令藏进 `Q · K^T` 的 `wgmma` 异步阴影（`QKS`）与跨轮 `P · V` 在途重叠（`PVW1`）**：因为 FP8 `QGMMA` 不支持硬件自动转置输入、要求右矩阵 `V` 按行主序连续存放，必须在片上用 `1 条 ldmatrix (LDSM) + 8 条 PRMT + 8 条 STS`（共 17 条指令）手动完成字节转置。若等 `Q · K^T` 算完再转置，这 17 条指令就会暴露在关键路径上。`a5` 把这 17 条转置指令插在 `Q · K^T` 的提交点（`commit_group`）与等待点（`wait_group<0>`）之间，趁 Tensor Core 在后台算 `Q · K^T` 时用 ALU 与 LSU 把 `V` 转置好（记作 `QKS`）；同时在 **verify 16 请求全长（`T = 128`）** 中删去分块末尾的等待，让本轮 `P · V` 跨过循环回边与下一轮 `Q · K^T` 保持在途重叠（`wait_group<1>`，记作 `PVW1`，见第 5 章第 4 节）。实测在 **verify 32 请求全长（仅开 `QKS`）** 上再省 **1.79 µs**，在 **verify 16 请求全长（`QKS + PVW1`）** 上合计省 **1.71 µs**。图 7-10 模式 1 与模式 2 读数分别为：`V 转置（QKS）：1 条 LDSM + 8 条 PRMT + 8 条 STS，插在 commit_group 与 wait_group<0> 之间` / `verify 32 全长（仅 QKS）省 1.79 µs；FP8 QGMMA P·V：vw2 省 8.77 / 3.04 µs（verify 32 / 16 全长），vws 省 0.74–0.77 µs（verify 32 滑窗）`，以及 `wait_group<1>（PVW1）：P·V 跨入下一轮，与下一轮的 Q·K^T 在途重叠` / `只用于 verify 16 请求全长：QKS + PVW1 合计省 1.71 µs（空档宽度不按比例）`。
- **第二步（`a5 → a6`：折叠序言并按区间选用 L2 原子或同 GPC 集群 `DSMEM` 核内归约，彻底消掉独立合并核，主例，图 7-2 模式 2 与图 7-11 模式 1）**：
  1. **序言就地折叠（回指第 1 章第 1 节）**：在解码与小批量 verify 中，让每个分片 CTA 直接从 `qkv` 就地重算本 CTA 所需的 `q` 行，并由持有最新位置的那 1 个 CTA 将新 `K, V` 写入缓存页，省去独立序言启动与一条 PDL 边，在解码 1 / 16 / 32 全长与 verify 1 / 16 全长上省 **0.72–1.76 µs**（当保留独立合并核时，将部分和工作区 `po` 存为 `BF16` 以减半读写字节，最大相对误差仅 `0.00332`）。
  2. **三路免启动核内归约（回指第 2 章第 4 节与第 3 章第 4 节）**：为彻底砍掉耗时 `3.7–7.2 µs` 的独立合并核，**`a6`** 按并发规模与物理位置分别采用三条片上/L2 归约通路：
     - **L2 无返回值向量原子加 `red.global.add.v4.f32` + 核尾按行协作归一（主例，图 7-2 模式 2）**：在 P1 的 **verify 16 / 32 请求全长（`T = 128 / 256`）** 中，各分片 CTA 在尾声直接向 L2 单精度工作区发 `red.global.add.v4.f32`（不等 L2 返回），随后由各 CTA 在同一内核末尾按行协作完成除法归一。虽然主注意力核自身因承担收尾变长 `2.1–2.8 µs`，但彻底删掉了 `5.2 / 7.2 µs` 的独立合并核与启动空隙，端到端净省 **1.73–2.98 µs**（核跨度缩短 `1.82–3.61 µs`）。
     - **L2 `acq_rel` 票据 + 最后到达者原地重缩放合并（图 7-2 模式 2）**：在 P3 的 **解码 16 请求全长（`T = 16`）与 32 请求滑窗/全长（`T = 32`）** 中，各分片把按 `f = ex2(min(m, 126))` 缩放的结果用 `red.global.add.v4.f32` 加进工作区后，通过 `atom.acq_rel.gpu` 票据由最后到达的 CTA 原地完成归一化与门控，分别提速 **1.35% 与 1.22% / 0.51%**（见图 7-2 模式 2 读数：`单独合并 kernel（对照）：多 1 个 kernel + 1 个切换空隙` / `两种免启动方案都省掉它`、`最后到达者原地合并：0 个额外 kernel，每个 CTA 1 次原子往返` / `P3 解码 16 请求全长提速 1.35%`、以及 `无返回值向量原子加：0 个额外 kernel，不等 L2` / `省 1.73–2.98 µs（P1，16 / 32 请求全长，核跨度 1.82–3.61 µs）`）。
     - **同 GPC 集群 `DSMEM` `st.async + mbarrier` 直写合并（图 7-11 模式 1）**：当同一请求的分片数在 `2–16` 之间时，将其声明为一个 cluster，各分片通过 `st.async` 直接把局部结果推进接收方 CTA 的共享内存并触发 `mbarrier`（绕开中央 L2 与全局原子）。在 P3 的 **6 个 verify 算例变体**上省下 **0.95–3.65 µs**（16-CTA 集群省 `2.14 µs`；图 7-11 模式 1 读数为：`经 L2 汇总：写 L2 + 原子往返 + 读 L2` / `作为 DSMEM 方案的对照基线` 与 `DSMEM 直写：0 次 L2 往返、0 个计数器` / `6 个 verify 算例变体省 0.95–3.65 µs`）；在 P1 滑窗 verify（`vws`）上用 `st.async` 推模式替代集群屏障尾省 **0.49 / 0.25 µs**（单核 DSMEM 合并省 `0.63 / 1.52 µs`），而在单请求滑窗（解码 1 与 verify 1）上更将序言、分片与 16-CTA 集群 `DSMEM` 合并压进**单个 C++ 内核（`K1 / K1V`）**，将 3 次启动减为 1 次，再省 **0.58–1.57 µs**（同样地，`st.async + mbarrier` 还被用于阶段 3/8 的集群边界归一化以消除 `MEMBAR.ALL.GPU`，每次启动省 `0.86–0.99 µs`，见第 9 章第 3 节）。
- **什么时候变成亏本（跨轮重叠寄存器溢出、编译期 `MUFU` 下沉、小批量核内原子串行化、以及延迟受限核强上集群 `DSMEM` 的六个实测反例）**：
  1. **在 80 寄存器满配的 `FLAT` 内核（verify 32 全长）上开启 `PVW1` 跨轮在途重叠**：多维持一轮 `P · V` 输入片段直接导致 **20 字节寄存器溢出（`5 条 STL + 5 条 LDL`）**，故该格必须关闭 `PVW1`、只开 `QKS`。
  2. **在 P5 预填充全长核中强行把 Softmax 与 `P · V` 做二级流水或乒乓重叠**：`ptxas` 将 66 条 `MUFU` 全部下沉到了末尾 `wait` 之后，且静态指令增加 `+10.9%`（在 `0.49` 指令/周期的依赖链限制下），实测反而**倒退 `-0.51%` 与 `-2.72%`**；在 128-key 块内再拆 64-key 子块流水虽减少 `64%` `wgmma` 等待，却因指令增加 **`+18%`** 使净收益归零。
  3. **把核内协作收尾直接内联进 `K` 循环函数内**：在 `vw2` 中尝试把协作合并放进 `K` 循环所在函数，结果扰乱了 `ptxas` 对 `K` 循环的指令排布，在 verify 16 / 32 全长上反而**变慢 `+1.50–3.39 µs` 与 `+0.35–0.64 µs`**。
  4. **在单请求全长（`B = 1`）上照搬核内 `red.global.add` 原子合并**：在解码 1 请求全长（256 个 CTA 同时往同一个输出行发原子加造成严重串行化）与 verify 1 请求全长上，核内归约尾耗时高达 `5.3–6.2 µs`（远超原本 `2.5 µs` 的独立合并核），实测反而**倒退 `+2.96 µs` 与 `+0.62 µs`**（解码全长单核 `gpu` 级释放 + 收尾同样锁死 `0.924 µs` 下界，在解码 16 / 32 全长上落败）。
  5. **在延迟受限的小矩阵（P4 `router` `T = 8..32`）上强用集群 `DSMEM` 归约**：`router` 仅读 `8.4 MB`（DRAM 仅占峰值的 `27%`），改用 8-CTA 集群 `DSMEM` 归约因限制最大活跃集群数（16 集群仅能驻留 15 个，掉入 2 个波次）并触发 8 路 bank 冲突，实测反而**变慢 `+2.5..+6.6 µs`**（在 `qkv_gate` `T = 128 / 256` 上也慢 `+2.4 / +5.9 µs`）。更严重的是，在 `router` `T = 32` 上，3-CTA 集群 `st.async` `DSMEM` 内核在判官评测中两次出现偶发精度越界（相对 L2 误差 `1.6e-3 > 1e-4`，本地千次重放无法复现的罕见集群竞态）；最终**彻底移除集群 `DSMEM` 机制类别**，改用无集群的 `128` 块 `wgmma` + `4` 个零 CTA 单调标志核（见第 2 章第 2、4 节），不仅 `1,000 / 1,000` 满分通过（最大误差 `2.6e-6`），耗时还从临时修复版的 `23.04 µs` 压到了 **9.95 µs**！

### 本章演化总复盘：`paged_attn` 从 `a0` 到 `a6` 如何通吃三个物理区间？

把本章的七个演化台阶（`a0 → a6`）串成一张表，就能看清同一个阶段 2 分页注意力算子在横跨区间 I（`T = 1..32` 解码）、区间 II（`T = 8..256` 投机检验）与区间 III（`T = 753..16,384` 预填充）时，每一步究竟拆掉了哪一堵硬件墙：

| 演化步 | 解决的唯一核心痛点 | 打开的机制（与被拒/关闭的反例边界） | 代表性实测跃迁（H200 冷 L2） |
