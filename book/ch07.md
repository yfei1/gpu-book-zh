# 第 7 章：Decode 与 Verify 下的一层模型实战解剖——从稠密投影、分页注意力、路由专家到整层交接

**本书地图：** 第 0.0 章 → 第 0 章 → 第 0.5 章 → 第 1 章 [第 0 级] → 第 2 章 [第 1 级] → 第 3 章 [第 2 级] → 第 4 章 [第 3 级] → 第 5 章 [第 4 级] → 第 6 章 [第 5 级] → **【第 7 章：Decode 与 Verify 单层实战解剖】** → 第 8 章 → 第 9 章

承接第 6 章末尾的问题（第二部分：Decode 与 Verify 单层实战）：第一部分拆开了六级硬件，并把第一阶段 `qkv_gate` 的单词矩阵乘推进到了 15.49 µs。当 `T = 1..32`（逐词解码 decode）或 `T = 8..256`（8 词投机检验 verify）的词元流过 `Muse Spark Open` 的完整一层（即赛题 P3）时，八个阶段各自卡在哪一级硬件，怎样改造并交接才能把整层耗时一步步压向 40.0 µs（滑窗层）与 44.2 µs（全长层）下界？

## 1. 阶段 1 与稠密投影族（P4）：从 `qkv_gate` 片上融合出站，到 `T = 32..256` 的环形缓冲与 TMA 块归约

<!-- FIG ch07-c1: 图 7-1 画第 2 级单个 SM 内的生产者-消费者 warpgroup 寄存器分工与环形缓冲槽数数据流（对应阶段 5 pooler 在 T=32 下将 24 KiB/槽的 TMA 环形缓冲从 6 槽扩至 7 槽使在途权重从 80 KiB 升至 96 KiB、以及 3-warpgroup 内核调用 setmaxnreg 40 / 232 与阶段 6 专家 3 槽对 2 槽乒乓的算法步）。 -->

词元进入单层后的第一棒是阶段 1 的 `qkv_gate` 投影。它与阶段 3 的 `o`、阶段 4 的 `router`、阶段 5 的 `pooler` 及阶段 7 的 `unpooler` 共同构成赛题 P4 的五个稠密投影。在小批量解码下，这五个投影占去单请求整层耗时的约三分之一。
- 公式：`qkv = x_in @ W_qkv_gate.T`。输出按列切分为查询 `q`、键 `k`、值 `v` 与输出门控 `gate`。其余四个稠密投影同样计算矩阵乘 `y = x @ W.T`。
- 输入：本层入口激活 `x_in`（形状 `[T, 8192]`，BF16，每词 `16 KiB`，位于 HBM 或 L2）与权重 `W_qkv_gate`（形状 `[2304, 8192]`，BF16，占 `37.7 MB`，位于 HBM）。同属 P4 的另外四个权重矩阵都驻留在 HBM：`W_o [8192, 1024]`（BF16，占 `16.8 MB`）、`W_router [256, 8192]`（FP32，占 `8.4 MB`）、`W_pooler [4096, 8192]`（BF16，占 `67.1 MB`）以及 `W_unpooler [8192, 4096]`（BF16，当 `T ≤ 8` 时只算前 `1,024` 列读 `8.4 MB`，当 `T > 8` 时算满 `8,192` 列读 `67.1 MB`）。
- 输出：拼接张量 `qkv`（形状 `[T, 2304]`，BF16，每词 `4.5 KiB` 即 `4,608 B`）。每行依次包含 `q [16, 64] = 1,024` 列、`k [2, 64] = 128` 列、`v [2, 64] = 128` 列与 `gate [16, 64] = 1,024` 列。
- 交给下一步：SGLang 基线用 cuBLAS 把 `qkv [T, 2304]` 写回 HBM，再启动独立内核交给阶段 2（P1 分页注意力）。在 `T = 1` 下，竞赛方案直接运行第 6 章第 4 节的 `v10` C12 寄存器流水内核（见第 6 章，共 `576` 个 CTA、每 CTA 4 个 warp 各算 1 行输出）。算出每行内积后，值向量（`v` 的 128 行）由所在线程直接量化写进 `FP8 E4M3` 分页缓存；查询与键的 18 个头（每头 64 行跨 16 个 CTA）则通过 L2 的 `acq_rel` 原子计数，由每头最后到达的 CTA 从 L2 读齐 64 个元素，在同一内核尾声完成按头均方根归一化、滑窗层旋转位置编码（`RoPE`）并量化写进 `q_out` 与 `k_cache`，从而省掉独立归一化与写缓存的内核启动。
- 本步代价：`T = 1` 时 `qkv_gate` 执行 `37.7 MFLOP`（算术强度 `1.0 FLOP/B`），BF16 带宽下界为 `7.9 µs`（C12 下界 `5.9 µs`，实测 `15.49 µs`）。全层五个稠密投影在 `T = 1` 下共读 `138.4 MB`，理论下界合计 `28.9 µs`。当 `T = 256`（32 请求 verify）时，`qkv_gate`、`pooler`、`unpooler` 的算术强度升至 `224–234 FLOP/B`。它们跨过 `206 FLOP/B` 平衡点进入 Tensor Core 受限区，下界分别为 `9.8 µs`、`17.4 µs` 与 `17.4 µs`。

当批量从 `T = 1` 增大到 `T = 8..256` 时，P4 的五个投影依次遇到第 2 级（单个 SM 环形缓冲与启动序）和第 1 级（整卡 Split-K 的 L2 归约）的瓶颈。
- 第 2 级（单个 SM 环形缓冲槽数、首块提前发射与旁路操作数预拼装）。在 `T = 32` 的 `pooler`（读 `67.1 MB`）中，内核用第 3 章的 TMA 环形缓冲搬运分块（见第 3 章第 4 节），并开启 128 字节 `XOR Swizzle` 消除共享内存 bank 冲突（见第 3 章第 5 节）。每个环形槽存放 `16 KiB` 权重块（`64 × 128 × 2 B`）与 `8 KiB` 激活块（`32 × 128 × 2 B`），合计每槽 `24 KiB`。基线 6 槽环（占 `144 KiB` SMEM）只能保持 5 槽权重（`80 KiB`）在途，尚未完全覆盖满载显存往返延迟。将其从 6 槽扩充到 **7** 槽后，SMEM 增至 `168 KiB`，在途权重升至 `96 KiB`，H200 实测耗时立即缩短 **0.75–1.04 µs**。在图 7-1 右半选 6 槽与 7 槽，读数分别为：`6 槽：SMEM 144 KiB · 在途权重 80 KiB` / `消费者每轮有空等`，以及 `7 槽：SMEM 168 KiB · 在途权重 96 KiB` / `实测缩短 0.75–1.04 µs`。此外，在 P4 的 `T = 8..32` 流式分块内核中，把第 0 槽权重拷贝移到首道屏障之后的第 1 条指令发出，在 7 个形状上实测省下 **0.08–0.19 µs**（如 `unpooler` `T = 16` 省 `0.08 µs`、`o` `T = 16` 省 `0.19 µs`）；在 P3 的 C12 `pooler / unpooler` 中，把旁路（escape）修正操作数在最后一步 `K` 循环运行期提前拼好，在 16 与 32 请求滑窗 decode（`T = 16 / 32`）和单请求滑窗 verify（`T = 8`）上实测省下 `0.40 / 1.23 / 0.18 µs`（单请求全长 verify 为 `-0.02 µs`，四格提速比 `0.24%–0.46%`）。
- 第 1 级（整卡 Split-K 的 TMA 异步二维块原子加）。在 `T = 128 / 256` 下，`qkv_gate` 与 `pooler` 沿求和维 `K` 切分（Split-K）以铺满 132 个 SM。为省掉最后到达者串行汇总或逐线程发射 `BF16x2` 向量原子加的尾步开销，改造方案让第 0 切分块的 TMA 生产者 warp 在发完最后一次加载后释放清零标志。这避开了在 `wgmma` 循环内放分支触发的第 6 章第 1 节 `C7515` 串行化告警。随后各切分块 CTA 将 `BF16` 部分和写入共享内存，由单线程发出 1 条 **TMA 异步二维块原子加**（`cp.reduce.async.bulk.tensor.2d...add`，SASS 为 `UTMAREDG.2D.ADD`），把整个二维分块直接送往中央 L2 异步累加。单看归约阶段时间戳，在 `qkv_gate`（`T = 128 / 256`）与 `pooler`（`T = 128`）三格上，TMA 块归约耗时 `0.60 / 1.02 / 0.56 µs`，比 `BF16x2` 向量原子加（`1.00 / 2.62 / 0.61 µs`）快 `0.40 / 1.60 / 0.05 µs`。端到端替换旧归约尾步后，在 `qkv_gate`（`T = 128 / 256`）上实测省下 **1.24–1.84 µs**，在 `pooler`（`T = 128 / 256`）上省下 **0.72–2.66 µs**（其中 `pooler` `T = 256` 尾步从 `4.9 µs` 压至 `2.06 µs`）。这对应下一节图 7-4 模式 3 的读数：`BF16x2 向量原子加：32 条 warp 指令，4 个 warp 全程发射` / `对照基线`，以及 `TMA 异步二维块原子加：1 条指令 + 1 次 SMEM 暂存` / `比 BF16x2 省 1.24–1.84 µs（qkv_gate）/ 0.72–2.66 µs（pooler）`。

- 第 1–2 级实测反例（在热 L2 下给 `pooler` 开启 TMA 集群多播，实测反而慢 **2.1 倍**）。Hopper 的 TMA 支持集群多播（`.multicast::cluster`）：同集群多个 SM 需要同一块权重时，由 L2 读一次同时广播写进各 SM 的共享内存，目的 CTA 则通过跨 SM 远端 `mbarrier.arrive` 通知发起方以复用缓冲槽。在 `pooler`（`T = 128`）微基准中，当权重块已驻留在 `8.8–10.1 TB/s` 的热 L2 时，各 SM 独立单播读取各自分块耗时 `0.849 ms`（所有 CTA 读同一分块、不开多播的热 L2 基线为 `0.745 ms`，对应 `10.1 TB/s`）。而开启 TMA 多播耗时 `1.812 ms`，比独立单播慢了 **2.1 倍**（比同分块无多播慢 **2.4 倍**；该微基准的具体集群大小与硬件停顿原因未在记录中保存，属未知）。在图 7-2 模式 1 中切换单播与多播，读数分别为：`各 SM 独立单播：事件时间 0.849 ms` / `L2 读取 8.8 TB/s · 每个 SM 68.3–69.6 B/ns`，以及 `开启多播：事件时间 1.812 ms（慢 2.1 倍）` / `L2 读取 3.0 TB/s · 每个 SM 32.4 B/ns`。

## 2. 阶段 2（P1 分页注意力）：从页表三跳指针追踪、按实际键数切波次，到惰性重缩放、FP8 `QGMMA` 与 L2 免启动归约

接过阶段 1 算出的查询、键、值与门控向量后，数据流进入阶段 2 的分页注意力（即赛题 P1）。SGLang 基线将其拆成按头归一化、写缓存、查询转 FP8、FlashAttention-3 与门控输出归一化 5 个独立 kernel。
- 公式：
  1. 按头均方根归一化与缩放（若未在阶段 1 尾声融合）：`q = rmsnorm(q_in, 1e-5) * 5.473`，`k = rmsnorm(k_in, 1e-5)`。
  2. 位置编码（仅 46 个滑窗层执行，16 个全长层跳过）：对 `q, k` 的交错对 `(2i, 2i+1)` 施加旋转位置编码 `RoPE(theta = 500,000)`。
  3. 原地写分页缓存：`K_cache[cache_loc] = FP8_E4M3(k / k_scale)`，`V_cache[cache_loc] = FP8_E4M3(v_in / v_scale)`。
  4. 分组查询注意力（单卡 2 个 KV 头各服务 8 个查询头，即 GQA `8:1`；滑窗层看最近 `2,048` 个键，全长层看 `0..pos` 全部键，块内带因果掩码）：`P = softmax((q_fp8 @ K_visible.T) / 8)`，`o_raw = P @ V_visible`。
  5. 门控输出归一化：`o_attn = rmsnorm(o_raw, 1e-5) * sigmoid(gate)`。
- 输入：`qkv`（形状 `[B, L, 2304]`，BF16，位于 HBM 或 L2）、序列长度 `seq_lens`（形状 `[B]`，`int32`，位于 HBM）、分页页表 `page_table`（形状 `[B, max_pages]`，`int32`，每页 1 个词元，位于 HBM）以及分页缓存 `K_cache, V_cache`（形状 `[pages, 1, 2, 64]`，FP8 `E4M3`，位于 HBM）。在单张 TP8 卡上，每个历史词元在每层占 `2 × 2 × 64 × 1 B = 256 B`。
- 输出与交给下一步：注意力输出 `o_attn`（形状 `[T, 1024]`，BF16，写回 HBM 或 L2），经 PDL 交给阶段 3 的 `o` 输出投影。同时新算出的 `K_new, V_new` 原地留在当前层的 `K_cache, V_cache` 显存页中，供后续生成步读取（见第 0.0 章第 2 节）。
- 本步代价：单请求 `T = 1`、历史 `80,000` 词时，滑窗层只读 `2,048 × 256 B = 0.52 MB`（带宽下界仅 `0.11 µs`，受固定启动与归约延迟限制）。全长层读 `80,000 × 256 B = 20.5 MB`，执行 `0.328 GFLOP`（算术强度 `16 FLOP/B`），带宽下界为 `4.3 µs`。8 词 verify 下全长层强度升至 `127.5 FLOP/B`（32 请求下界 `126.8 µs`），依然低于 `206 FLOP/B` 平衡点。

<!-- FIG ch08-a1: 图 7-3 画第 3 级打破三跳指针追踪链与小表片上预载数据流（对应阶段 2 P1 分页注意力入口“读 seq_lens（600 ns）→ 读 page_table（640 ns）→ 发 cp.async（1,150 ns）”三跳串行长记分牌等待、单请求满长投机并发与跨轮提前流水化，以及阶段 6 P2 专家入口把 64 个浮点缩放小表预载入 SMEM 的算法步）。 -->

顺着数据进入注意力的顺序，首先在第 3 级（单个 SMSP 记分牌，见第 4 章第 2 节）撞上页表寻址的串行依赖链。主循环虽然用上了 `cp.async` 环形缓冲收集离散的 64 字节键值行（见第 3 章第 3 节），但剖析器显示在首次使用页表结果的指令（`IMAD.WIDE`）处，仍有 **37%–42%** 的停顿卡在长记分牌上（该占比对应的具体算例形状未在记录中单列）。读取一个历史键值页要走三跳 **pointer chasing**（指针追踪）：第 1 跳从全局内存读序列长度 `seq_lens[b]`（约 `600 ns`），第 2 跳用算出的页号读离散页表 `page_table[b, page]`（约 `640 ns`），到第 3 跳才能拿到物理页地址并发起 `cp.async` 搬运（约 `1,150 ns`）。后一跳的地址依赖前一跳返回的数据，在 **verify 1 请求全长算例（`T = 8`）** 上实测串行耗费 **2,400 ns**（约 `2.4 µs`）。P1 用两项改造拆开这类串行依赖链（图 7-3 模式 1 至模式 3）。
- 单请求满长投机预取（图 7-3 模式 2）。在 **解码 1 请求全长算例（`T = 1`）** 中，内核在入口不等 `seq_lens[0]` 返回，直接根据页表数组跨度（`pt_stride`）猜测键值范围，把前 4 个分块的页表读取与 `seq_lens[0]` 同时发出（返回后再校验，实测猜错代价为 `0.000 µs`）。这把前两跳从串行压成并发，在解码 1 请求全长算例上实测省下 **0.26 µs**（`0.256 µs`）。图 7-3 模式 1 与模式 2 的读数分别为：`3 跳串行：每跳只有 1 条独立指令，约 2.4 µs（verify 1 请求全长算例实测 2,400 ns）` / `首次使用页表结果的 IMAD.WIDE 处，37%–42% 的停顿是长记分牌（P1 记录，形状 UNKNOWN）`，以及 `投机并发：前两跳同时发出，长记分牌等待从 3 次变 2 次` / `解码 1 请求全长算例实测省 0.26 µs`。
- 跨轮页表提前流水化与序言加载跨代合并（图 7-3 模式 3）。在主循环第 `k` 轮进入片上屏障等待之前，先把第 `k + 1` 轮要用的页表项读取发出去，让 `640 ns` 的页表读取藏进当前轮等待里（这一跨轮预取的单独实测收益未在记录中保存，图 7-3 模式 3 读数为：`跨轮提前流水化：第 k+1 轮的页表读取藏进第 k 轮` / `这一项的单独实测收益 UNKNOWN（记录里没有）`）。此外，在滑窗注意力序言中，编译期静态重排把原本分 4 代串行等待的输入加载（`loc[b]`、`qkv` 字、缩放指针与旋转频率）合并为 1 代在 `seq` 分支前并发发出，单独该项在 32 请求滑窗 decode（`T = 32`）上实测省下 `0.11 µs`。
- 第 1–3 级实测反例（在 PDL 等待前发出页表 L2 预取，实测反而多读 **4.3–8.5 MB** 显存）。为进一步掩盖页表延迟，曾尝试在 PDL 等待点之前由单线程提前发出块预取指令（`cp.async.bulk.prefetch.L2`）。然而在三个测试形状上，H200 实测不仅耗时变慢 `0.03–0.53 µs`，全卡 HBM 读取量还反常增加了 `4.3–8.5 MB`。预取进 60 MiB L2 的页表缓存行在真正被消费前就被中间流过的键值数据冲出了缓存，等到使用时又得从 HBM 重读第二次（见上节图 7-2 模式 2 读数：`不预取：页表行 DRAM 读 1 次` / `作为对照基准` 与 `PDL 等待前预取：页表行 DRAM 读 2 次` / `全卡多读 4.3–8.5 MB · 耗时多 0.03–0.53 µs`）。

进入第 1 级（整张芯片 132 个 SM，见第 2 章第 1 节），当并发请求数较少或各请求历史长度不一时，只按“请求 × 注意力头”派发 CTA 会导致波次失衡。**Split-KV**（又叫 Flash-Decoding）把长历史序列沿键值维切成多段，并行算出局部加权和 `o_i` 与对数分母 `lse_i = m_i + log2(l_i)`，最后按 `2^(lse_i - lse_total)` 重缩放合并。但在 `agentic` 负载下，各请求历史长度在 `±7.5%` 范围内均匀波动（`1.075 ÷ 0.925 ≈ 1.16`，即最长请求约为最短的 `1.16` 倍）。若给每个请求机械分配相同数量的切分块，长序列 CTA 会比短序列慢约 **15%**（`15%–16%`）并拖出尾波。P1 与 P3 改为在 `264` 个 CTA（`132 SM × 2`）上按每个请求的**实际历史键数比例**分配切分块，使各 SM 分到的键值页数均匀对齐。在 **32 请求全长 verify（`T = 256`）** 算例上，P1 实测缩短 **3.90 µs**，P3 缩短 **9.5 µs**（在 16 请求全长 verify 即 `T = 128` 算例上 P3 缩短 `2.0 µs`）。在图 7-4 模式 1 中切换两种切分方式，读数分别为：`按请求切分：收尾 = 最长 CTA，长 CTA 慢约 15%` / `比按键数切分多 3.90 µs（P1）/ 9.5 µs（P3），32 请求全长`，以及 `按实际键数切分：6 个 SM 同时收尾` / `比按请求切分少 3.90 µs（P1）/ 9.5 µs（P3），32 请求全长`。

分块进入第 4 级（物理执行管线与 Tensor Core，见第 5 章）后，在线 Softmax 与两段矩阵乘（`Q · K^T` 和 `P · V`）在 4 通道 SFU、算术发射槽与 Tensor Core 之间展开三项跨管线协同。
- 惰性重缩放（Lazy Rescaling）卸下 4 通道 SFU（图 7-5 模式 1）。每个 SMSP 的 SFU 只有 4 条通道，发射间隔（8 周期）是 FMA 管线（1 周期）的 8 倍（见第 5 章第 1 节）。标准在线 Softmax 只要发现新分块最大值 `m_tile > m_old`，就立刻调 `exp2f(m_old - m_new)` 把此前累加的输出向量 `O` 重缩放一遍，使 SFU 在长上下文 verify 中持续满载。P1 给单精度指数留出 `2^T` 的动态范围余量（单精度指数上限达 `2^127`）。只要新分块最大值未超出当前参考基准加阈值 `T`，就跳过本轮对历史累加器的 `exp2f` 与乘法修正。在 P1 的 **32 请求全长 verify（`T = 256`）** 算例上，引入阈值 `T = 4`（配合 `2^(8-T)` 的 FP8 权重缩放）实测省掉 **8.77 µs**，将双 warpgroup 内核阈值调到 `T = 6` 又再省 **1.42 µs**（单 warpgroup 滑窗内核取 `T = 8` 在 **32 请求滑窗 verify** 即 `T = 256` 上省 `0.83 µs`、在 16 请求滑窗 verify 即 `T = 128` 上省 `0.14 µs`）。图 7-5 模式 1 读数为：`惰性重缩放：SFU 不再逢新最大值就调 exp2f` / `P1 32 请求全长 verify：T = 4 省 8.77 µs；T = 6 再省 1.42 µs`。
- 空闲 Tensor Core 算行和卸下算术发射槽（图 7-5 模式 2）。即便跳过历史重缩放，在线 Softmax 每轮仍要把当前 `64 × 64` 分块的权重矩阵 `P` 按行求和以更新分母 `l`。在 P3 全长 verify 注意力中，反汇编显示每个 64-key 分块循环共 `288` 条 SASS 指令（Softmax 占 `58%`）。单是按行累加 `P` 就要在算术管线上发 `38` 条 `FADD` 加 `4` 条洗牌指令（共 `42` 条），把发射槽塞满，而此时 64 行宽的 Tensor Core 却在空闲等待。P3 在共享内存中放一块全为 `1.0` 的常数矩阵，直接发出 **4 条 `wgmma.m64n8k16`** 计算 `P × 1`（每条算 16 列，4 条覆盖 64 列），用空闲 Tensor Core 一步算出 64 行之和。这净省下 **38** 条指令（42 减 4；随后再把分数的上限截断由 32 条单精度 `FMNMX` 改为 16 条打包 `min.bf16x2` 再省 16 条指令）。在 P3 的 **verify 16 请求与 32 请求全长**（`T = 128` 与 `T = 256`）算例上，行求和改造分别实测缩短 **3.9 µs 与 3.4 µs**。图 7-5 模式 2 读数为：`行求和：38 条 FADD + 4 条 SHFL → 4 条 wgmma，净省 38 条` / `P3 verify 16 / 32 请求全长缩短 3.9 / 3.4 µs；每个 64-key 分块 288 条，Softmax 占 58%`。

- 原生 FP8 `QGMMA` 与 `V` 转置跨管线重叠（图 7-6）。KV 缓存原本就以 1 字节 FP8 存放，基线却先用 ALU 指令把 `V` 解包成 2 字节 BF16 再调 BF16 的 `wgmma`。P1 直接把权重 `P` 转为 FP8，在吞吐翻倍的原生 FP8 Tensor Core（SASS 为 **`QGMMA`**）上计算 `P · V`。这省掉了 `V` 的解包并使矩阵乘周期减半，在 **32 请求滑窗 verify（`T = 256`）** 上实测省下 **0.74–0.77 µs**。由于 FP8 `QGMMA` 不支持硬件自动转置输入、要求右矩阵 `V` 按行主序连续存放，必须在片上用 `1 条 ldmatrix (LDSM) + 8 条 PRMT + 8 条 STS`（共 17 条指令）手动转置 `V`。P1 把这 17 条转置指令插在 `Q · K^T` 的提交点（`commit_group`）与等待点（`wait_group<0>`）之间，趁 Tensor Core 在后台算 `Q · K^T` 时用 ALU 与 LSU 把 `V` 转置好（在 16 请求全长 verify 上还同时让 `P · V` 跨入下一轮循环与下一轮 `Q · K^T` 保持 `wait_group<1>` 在途重叠，见第 5 章第 3 节），在 **32 请求全长 verify（`T = 256`）** 上实测再省 **1.79 µs**（16 请求全长 verify 省 `1.71 µs`）。图 7-6 模式 1 与模式 2 读数分别为：`V 转置：1 条 LDSM + 8 条 PRMT + 8 条 STS，插在 commit_group 与 wait_group<0> 之间` / `与 wait_group<1> 合计再省 1.79 µs（32 请求全长）；FP8 P·V 省 0.74–0.77 µs（32 请求滑窗）`，以及 `wait_group<1>：P·V 跨入下一轮，与下一轮的 Q·K^T 在途重叠` / `与 V 转置合计，32 请求全长 verify 算例再省 1.79 µs（空档宽度不按比例）`。

<!-- FIG ch07-b2: 图 7-7 画同 GPC 集群 DSMEM 跨 SM 直写与奇偶双账本免清零数据流（对应阶段 2 P3 注意力中同 GPC 内多个 SM 组成 cluster 通过片上 DSMEM 直接汇总分块结果绕开中央 L2、以及阶段 6 P2 持久专家内核交替使用偶账本 doneA[0..1023] 与奇账本 doneA[1024..2047] 的算法步）。 -->

在阶段 2 出站交接给阶段 3（`o` 投影）时，Split-KV 切出的多个分片必须汇总。为省掉单独启动第二个合并 kernel 的切换空隙（在 P3 解码中单独合并 kernel 耗时 **`3.7–5.1 µs`**，NCU 实测 `3.68–4.58 µs`），P1 与 P3 在第 1 级采用了三种免启动归约方案（图 7-4 模式 2 与图 7-7 模式 1）。
- 中央 L2 原子计数加最后到达者原地合并（图 7-4 模式 2）。在 P3 的 Split-KV 解码注意力中，每个分片 CTA 将按指数基准缩放后的局部结果用 `red.global.add.v4.f32` 累加进单精度工作区后，对 L2 计数器执行一次带 `acq_rel` 的原子加（见第 2 章第 4 节）。拿到最后序号的 CTA 直接从 L2 读出汇总结果，原地完成除法归一、`rmsnorm(out) * sigmoid(gate)` 并清零工作区。在 **解码 16 请求全长（`T = 16`）** 算例上，该方案实测提速 **1.35%**，在 **解码 32 请求滑窗与全长（`T = 32`）** 上分别提速 `1.22%` 与 `0.51%`。
- 中央 L2 无返回值向量原子加配合按行协作归一（图 7-4 模式 2）。在 P1 的全长 verify 注意力中，各分片直接向 L2 的单精度工作区发出无返回值的向量原子加指令（`red.global.v4.f32`）。L2 硬件原子加法器直接完成累加，随后各 CTA 在同一内核尾声按行协作完成最终除法归一，在 **16 / 32 请求全长 verify（`T = 128` 与 `T = 256`）** 上实测省下 **1.73–2.98 µs**（核跨度缩短 `1.82–3.61 µs`）。图 7-4 模式 2 的三条读数分别为：`单独合并 kernel（对照）：多 1 个 kernel + 1 个切换空隙` / `两种免启动方案都省掉它`、`最后到达者原地合并：0 个额外 kernel，每个 CTA 1 次原子往返` / `P3 解码 16 请求全长提速 1.35%`、以及 `无返回值向量原子加：0 个额外 kernel，不等 L2` / `省 1.73–2.98 µs（P1，16 / 32 请求全长，核跨度 1.82–3.61 µs）`。
- 同 GPC 集群 DSMEM 跨 SM 直写（图 7-7 模式 1）。在 P3 注意力的内核设计对比中，若同一请求切出的 `2–16` 个分片 CTA（超过 8 个需开启非可移植集群属性）同属一个物理 GPC（见第 2 章第 4 节），可将其声明为一个 cluster。它们直接通过 GPC 内部的分布式共享内存（DSMEM，`st.async` 单程约 `181–213` 周期）互写片上存储、绕开中央 L2，在 **6 个 verify 算例变体**上省下 **0.95–3.65 µs**（其中 16-CTA 集群省 `2.14 µs`）。图 7-7 模式 1 读数为：`经 L2 汇总：写 L2 + 原子往返 + 读 L2` / `作为 DSMEM 方案的对照基线`，以及 `DSMEM 直写：0 次 L2 往返、0 个计数器` / `6 个 verify 算例变体省 0.95–3.65 µs`。

## 3. 阶段 3、4、5 到阶段 6（P2 路由专家）：从并联分叉交接、位图路由与 33 字消冲突，到 NVFP4 寄存器解码、双核 PDL 与编译器防退化

注意力输出 `o_attn [T, 1024]` 从阶段 2 出来后，先经过阶段 3 的输出投影与第一道残差边界。随后数据流在阶段 4（`router`）与阶段 5（`pooler`）处发生**并联分叉（fork）**，最终在阶段 6（即赛题 P2，32 个本地 NVFP4 路由专家）汇合。
- 阶段 3（`o` 输出投影 + 门控残差 1 + `pre_ffn_norm`）解剖与分叉交接：
  - 公式：`a = o_attn @ W_o.T`。门控残差更新为 `stream_1 = alpha_1 * stream_0 + beta_1 * rmsnorm(a, 1e-8)`（其中 `beta_1 = sigmoid(g_1 / 0.3)`，`alpha_1 = sqrt(max(sigmoid(-g_1 / 0.3) * (1 + beta_1), 1e-3))`）。预归一化为 `h = rmsnorm(stream_1) * (1 + w_pre_ffn)`（`pre_ffn_norm` 等后续层间归一化的 `eps` 常数未在赛题说明中单列）。
  - 输入与输出：输入 `o_attn [T, 1024]`（BF16）、`W_o [8192, 1024]`（BF16，占 `16.8 MB`，`T = 1` 下界 `3.5 µs`，位于 HBM）与入口残差流 `stream_0 [T, 8192]`（FP32，每词 `32 KiB`，位于 HBM）。输出更新后的残差流 `stream_1 [T, 8192]`（FP32，写回 HBM，留给阶段 8）与预归一化激活 `h [T, 8192]`（BF16，每词 `16 KiB`，位于 HBM 或 L2）。
  - 交给下一步：`h [T, 8192]` 同时分叉送入阶段 4（`router`）与阶段 5（`pooler`）。
- 阶段 4（`router` + Top-8 选择）与阶段 5（`pooler` + `pre_expert_norm`）解剖与汇合交接：
  - 阶段 4 公式与代价：`scores = sigmoid(0.1767767 * (Float32(h) @ W_router.T))`（`W_router [256, 8192]`，FP32，占 `8.4 MB`，算术强度 `0.5 × T FLOP/B`，`T = 1` 下界 `1.8 µs`）。随后对 `scores + b_router` 挑出最大的 8 个全局专家编号 `topk_ids [T, 8]`（`int32`），并将对应的 8 个无偏置 `scores` 归一化为和等于 1 的 `topk_weights [T, 8]`（FP32）。P3 将 `top-8` 选择改为每词元 1 个 warp，在寄存器内每轮用 2 条 `redux.sync` 指令直接选出胜者（替代 5 步洗牌加共享内存屏障，warp 指令数减少 `61%`）。这在 `T = 1`（单请求滑窗与全长 decode）上使整层提速 `1.29% 与 2.81%`，在 **`T = 256`（32 请求滑窗 verify）** 上将 `top-8` 核耗时从 `4.96 µs` 压到 `3.65 µs`。在 `T = 16 / 32` 的 `router` 矩阵乘中，P4 增加第 5 个辅助 warp（160 线程 CTA）在等待 `cp.async` 数据期间提前取票并轮询清零标志，并剥离尾部空预取，实测省下 `0.50–0.57 µs`（`router 16` 省 `0.57 µs`、`router 32` 省 `0.50 µs`）。
  - 阶段 5 公式与代价：`p = rmsnorm(h @ W_pooler.T) * (1 + w_pre_expert)`（`W_pooler [4096, 8192]`，BF16，占 `67.1 MB`，`T = 1` 下界 `14.0 µs`）。它把隐状态从 `8,192` 维压窄一半为专家输入 `p [T, 4096]`（BF16，每词 `8 KiB`）。因为阶段 4 与阶段 5 共享同一个输入 `h`，P3 在 `T = 128`（16 请求滑窗与全长 verify）下把 `pooler` 与 `router` 合并进单次启动，使合并核提前约 `10 µs` 进场、消除两者间 `8.5 µs` 的启动空隙（净省约 `3 µs`，整层提速 `0.88%–1.30%`）。同时在 `T = 1..32` 下，P3 把 `pre_expert_norm` 的按列乘增益与每行平方和累加拆入 `pooler` 尾声，由阶段 6 专家入口乘均方根倒数，直接省掉独立的归一化启动（在 `T = 1` 上将整层启动从 12 次减为 11 次，实测省下 **0.82–1.47 µs**）。
- 阶段 6（P2 路由专家）完整解剖：
  - 公式：在 8 卡专家并行（EP8）下，本卡驻留 32 个本地专家 `[local_start, local_start + 32)`。对每个命中的本地 `(tok, slot, e)` 对依次执行五步：(1) 上投影 `[h_gate | h_up] = p[tok] @ dequant_nvfp4(W13[e], sf13[e], gs13[e]).T`（`[4096] → [8192]`）；(2) 门控激活 `inter = silu(h_gate) * h_up`（`[4096]`）；(3) 下投影 `y = inter @ dequant_nvfp4(W2[e], sf2[e], gs2[e]).T`（`[4096] → [4096]`）；(4) **每专家独立后归一化**（在加权求和之前）：`y_norm = rmsnorm(y * (1 + w_post_expert), 1e-8)`；(5) 按槽位加权累加：`m[tok] += topk_weights[tok, slot] * y_norm`（未命中本卡专家的词元输出为 0）。
  - 输入与输出：输入 `p [T, 4096]`（BF16，位于 HBM 或 L2）、`topk_ids [T, 8]`（`int32`）、`topk_weights [T, 8]`（FP32），以及本卡 32 个专家的 NVFP4 权重 `W13 [32, 8192, 2048] uint8` + 块缩放 `sf13 [32, 8192, 256] fp8` + 全局缩放 `gs13 [32] fp32` 与 `W2 [32, 4096, 2048] uint8` + `sf2 [32, 4096, 256] fp8` + `gs2 [32] fp32`（每权重 `0.5625 B`，单专家 `28.3 MB`，32 个本地专家共 `906 MB`，位于 HBM）。输出汇总后的专家激活 `m [T, 4096]`（BF16，每词 `8 KiB`，写回 HBM 或 L2），交给阶段 7（`unpooler`）。
  - 本步代价：每对 `(tok, e)` 执行 `100.7 MFLOP`（算术强度 `3.6 FLOP/B`），需约 `58` 个词元复用同一专家才跨过 `206 FLOP/B` 平衡点。在 Decode（`T = 1..32`）与 Verify（`T = 8..256`）下，最忙卡每个被命中的本地专家平均最多仅分到**约 16 个词元**（`T = 256` 时为 390 对落于约 24.6 个专家，更小批量下更少），全部受 HBM 读权重限制（`T = 1` 下 P2 读约 `1.93` 个专家 `54.7 MB`，下界 `11.4 µs`；P3 按 `1.87` 个专家 `53 MB` 计入，约 `11.0 µs`；`T = 256` 下界 `108.9 µs`）。

进入阶段 6 内部，从入口路由分桶、片上缓冲、双核交接到寄存器反量化，P2 与 P3 在第 3 级、第 2 级、第 0–1 级与第 5 级上依次完成了四组改造。
- 第一组（第 3 级与第 2 级：8-warp `__ballot_sync` 位图路由、SMEM 33 字填充消冲突与缩放小表片上预载）。
  1. 在路由准备阶段（Phase 0），每个本地专家要从 `topk_ids` 里筛出命中自己的词元并紧缩成连续索引。基线用串行 256 步循环逐个扫描，造成分支空等（见第 4 章第 3 节）。P2 与 P3 改为让 8 个 warp 并行读取命中条件，每个 warp 调用硬件投票指令 **`__ballot_sync`** 一步生成 32 位命中位图，再调位计数指令（`__popc`）算出连续写入偏移（`ballot + popc + bfind` 合计约 `40` 周期）。这对应第 8 章图 8-2 模式 1 的读数：`串行 256 步 → 8 个 warp 并行：每个 warp 1 次读 + 1 次 ballot + 1 次 popc` / `ballot+popc+bfind 约 40 周期；单 token 与 8-token 算例合计省 0.62 µs 与 2.46 µs`。配合首轮权重 TMA 错峰预发（在 `T = 1` 下还将上投影分块按 `blockIdx.x + 132 j` 轮转派发，使 132 个并发 TMA 请求在显存地址上紧邻，分块节拍提速约 `7%`、省 `0.66 µs`），位图路由在 `T = 1` 与 `T = 8` 上实测合计省下 **0.62 µs 与 2.46 µs**。
  2. 同时，P3 在共享内存中构建 32 个本地专家的路由计数表时，原始按 2 的幂次（32 或 64 个 4 字节字）对齐的行宽使不同行同一专家列全部撞在同一个 bank 上（产生 32 路冲突，见第 3 章第 5 节）。如图 7-8 所示，把计数表行宽填充为 **33** 字奇数行宽（使相邻行同一列错开 1 个 bank）并合并 `topk_ids` 重复读取后，在 P3 的四个 verify 形状上实测省下 **1.28–7.49 µs**（提速 `0.6%–2.1%`）。图 7-8 的三条读数分别为：`32 字行宽：32 路 bank 冲突，读 1 列 = 32 轮` / `读 32 列 = 1,024 轮 · 表占 4,096 B`、`64 字行宽：32 路 bank 冲突，读 1 列 = 32 轮` / `读 32 列 = 1,024 轮 · 表占 8,192 B`、以及 `33 字行宽：读 1 列 = 1 轮，读 32 列 = 32 轮` / `实测 P3 省 1.28–7.49 µs（0.6%–2.1%）`。

- 第二组（第 2 级：生产者-消费者动态寄存器配额与 3 槽对 2 槽乒乓反例）。
  - 在大批量 `wgmma` 内核中，同一 CTA 内发 TMA 的生产者只需几十个寄存器，而跑 `wgmma` 的消费者需上百个寄存器存累加器，因此采用 **warp specialization**（线程束分工）。在 P3 与 P5 的 3-warpgroup 矩阵乘内核中，1 个生产者 warpgroup（`128` 线程）在入口调 `setmaxnreg.dec 40` 退还寄存器（占 `128 × 40 = 5,120` 个），2 个消费者 warpgroup（`256` 线程）调 `setmaxnreg.inc 232` 扩充到每线程 **232** 个（占 `59,392` 个，全 CTA 合计 `64,512 ≤ 65,536` 个）。这对应第 1 节图 7-1 模式 1 的读数：`统一 232：需要 89,088 个寄存器 > 65,536` / `超出 23,552 个，累加器溢出`，以及 `分工：5,120 + 59,392 = 64,512 ≤ 65,536 个寄存器` / `零溢出，Tensor Core 跑满`。而在 P2 的 4 消费者 warpgroup 持久专家内核中，若 4 个消费者都拿 232 个寄存器会需要 `4 × 128 × 232 = 118,784 > 65,536` 个寄存器；因此其 `576` 线程变体（4 个消费者 warpgroup 加 2 个生产者 warp，被 `ptxas` 按 640 线程粒度计费）保持每线程 **96** 个寄存器的上限，而补齐为 `640` 线程（5 个完整 warpgroup）的变体则让生产者调 `setmaxnreg.dec 24..32`、4 个消费者调 `setmaxnreg.inc 112`。
  - 在环形缓冲槽数上，P2 的单个权重分块为 `36 KiB`（在 P3 的 verify 专家中，进一步把块缩放因子从 8 位无损压成 6 位，使每分块从 `36,864 B` 缩至 `35,840 B`、少读 `2.78%` 权重字节，整层 verify 提速 `0.38%–0.66%`）。3 槽环（总容量 `108 KiB`，保持 2 槽即 `72 KiB` 在途）已跨过 TMA 的 `48 KiB` 平台（见第 3 章第 4 节）。实测反例显示，若为追求两组消费者交替算尾声的乒乓调度而把双倍分块塞进 SMEM，环形缓冲就会退化为 **2 槽**（在途只剩 1 槽即 `36 KiB < 48 KiB` 平台），H200 实测反而变慢 **1.2–1.6 µs**（见第 1 节图 7-1 模式 2 右侧读数：`3 槽：在途 72 KiB > 48 KiB 平台` / `消费者一直有数据可算` 与 `乒乓调度，2 槽：在途 36 KiB < 48 KiB` / `实测慢 1.2–1.6 µs`）。
- 第三组（第 0–1 级：`w13 → w2` 拆成双核 PDL 串联、按 `blockIdx.x` 削减分块与奇偶双账本免清零）。
  - 在小批量（`T = 8 / 16 / 32`）下，P2 将上投影 `w13` 与下投影 `w2` 拆成两个由 PDL 串联的 kernel。后继 `w2` 在 PDL 等待前提前预载静态权重环，在 16 与 32 请求 decode（`T = 16 / 32`）上将交接段重叠掉 **5–11 µs**，比带 `1.4 µs` 全网格栅栏的协作大核净快 **0.70–0.82 µs**（单请求 verify 即 `T = 8` 净快 `0.37 µs`，见第 1 章第 3 节）。针对第 2 章第 2 节观察到的硬件按 `blockIdx.x` 顺序派发导致 `131` 号 CTA 比前序块晚 `2–3 µs` 启动，P2 对 `100..131` 号高编号 CTA 按二次曲线少分 `w2` 工作单元，在 16 与 32 请求 decode 上再省 **0.27–0.31 µs**。
  - 在大批量（`T = 128 / 256`）持久专家内核中，各子任务一方面按填充后词元数从大到小（LPT）动态领任务并对尾部 66 个 `w2` 子任务做 K-halves 对半切分以削平尾波（见第 2 章第 1 节），另一方面在跨轮 CUDA Graph 重放时开辟奇偶交替的 **双账本**（偶账本 `doneA[0..1023]` 与奇账本 `doneA[1024..2047]`，每本 `1,024` 个 4 字节整数）。每次启动用票据选择其中一本，由空闲的生产者通道顺带清零另一本供下一轮使用。这既省掉独立清零 kernel，又删掉了内核末尾的退出同步链（SASS 中 `MEMBAR` 从 29 降至 25、`BAR.SYNC` 从 16 降至 14），在 16 与 32 请求 verify（`T = 128 / 256`）算例上实测省下 **0.29 µs 与 0.33 µs**（`0.286 / 0.331 µs`；见上节图 7-7 模式 2 读数：`清零 kernel：每轮多 1 次 kernel 启动` / `作为双账本的对照基线` 与 `奇偶双账本：0 个额外 kernel 启动` / `后台 warp 清零 1,024 个字`）。此外，将每子任务完成后的 `red.release.gpu` 从消费者 warpgroup 移交专门的第 18 号释放 warp（消费者只做片上 `red.release.cta`），使全卡 `MEMBAR.ALL.GPU` 从 11 处降至 2 处，在 `T = 128 / 256` 上实测再省 **1.49–1.74 µs**（加上独立释放 warp 再省 `0.77–0.85 µs`）。

- 第四组（第 5 级：8 指令异或寄存器反量化、SwiGLU 缩放折叠与 `ptxas` 防下沉 / 防重物化，图 7-9）。
  - 在寄存器比特排布上，P2 与 P3 在预处理阶段（`prepare()`）把每 8 个 4 位权重（NVFP4）预先重排成 Tensor Core 片段所需的线程顺序，并进一步做 GF(2) 异或（XOR）编码（同时把块缩放常数 `0x60006000` 放进常量缓存用单条三输入 `LOP3` 拼装，在 32 请求 decode 与 16 / 32 请求 verify 上省 `0.58–0.99 µs`）。这使运行期只需执行第 6 章第 3 节的 **8 条整数指令**（`2 条 SHF + 2 条 IMAD.SHL + 4 条 LOP3`，从 9 条减为 8 条）加 `4 条 HMUL2`，即可无分支还原出 4 个 `BF16x2` 寄存器（见第 6 章）。在 P3 全 12 个算例上，启用该异或解码几何平均提速 **0.58%**，在 **解码 32 请求滑窗（`T = 32`）** 算例上最高提速 **1.01%**。同时利用 `SwiGLU(g, u) = 0.5 * g * u * (1 + tanh(0.5 * g))` 对上投影 `u` 的线性性，把反量化缩放因子代数折入外层系数，将尾声每元素指令从 `9` 条减至 `7` 条（在 `T = 128 / 256` 上省 `0.54–0.60 µs`）。
  - 检查专家后归一化（`pn`）内核的 SASS 反汇编还抓出并修复了两处典型的编译器退化（图 7-9 模式 1 与模式 2）：
    1. 预取指令被编译器下沉（图 7-9 模式 1）。为配合 PDL 提前预读权重，代码把只读缓存加载（`ld.global.nc`）写在了 `cudaGridDependencySynchronize()`（SASS 为第 5 条指令 `ACQBULK`）之前。但只读加载形式给了编译器重排自由度，`ptxas` 把这批加载全部下沉到了 `ACQBULK` 之后，使 PDL 预读完全失效。改用带 `volatile` 的普通全局加载内联汇编后，6 条 16 字节预取（`LDG.E.128`）被牢牢锁在 `ACQBULK` 之前，单改此项在单请求与 16 请求 decode（`T = 1 / 16`）上实测省下 **0.45–0.67 µs**。
    2. 循环不变量被编译器重物化（图 7-9 模式 2）。在后归一化主循环外预先算好的 `nw[i] = 1.0f + norm_w[i]`（16 个浮点数），被 `ptxas` 为省寄存器而拆回展开后的 2 相 × 8 槽内层循环里重复执行（多出 `321` 条 `FADD`）。在循环外对该数组加上一行零运行时开销的空内联汇编 `asm volatile("" : "+f"(nw[i]));`（告诉编译器该寄存器不可重算）后，整个内核的静态 SASS 指令数从 `1,603` 条骤降到 **1,120** 条（净省 **483** 条），在 decode 1 / 16 / 32 请求算例上实测省下 **0.21–0.30 µs**（`0.208 / 0.300 / 0.304 µs`）。图 7-9 的三条读数分别为：`volatile 加载：6 条 16 B 预取排在 ACQBULK 之前，恢复预读重叠` / `普通 .nc 加载被 ptxas 下沉到 ACQBULK 之后，PDL 预读失效`、`空 asm：PN 的静态 SASS 1603 → 1120 条（少 483 条）` / `H200 实测省 0.21–0.30 µs（decode 1/16/32）；运行期不生成指令`、以及 `8 条整数指令（2 SHF + 2 IMAD.SHL + 4 LOP3）+ 4 条 HMUL2，无分支` / `ALU、FMA 管线各 12 周期；P3 异或解码几何平均提速 0.58%，最高 1.01%（解码 32 请求滑窗）`。

## 4. 阶段 7、8 与整层收官（P3）：从切片 `unpooler`、边界门控残差融合到 11 核同流 PDL 整层流水线

从阶段 6 的本地专家出来后，数据流经过阶段 7 的 `unpooler` 升维投影与阶段 8 的第二道门控残差边界，最终合拢为赛题 P3 的完整单层流水线。
- 阶段 7（`unpooler` 升维投影）解剖与 `T ≤ 8` 切片规则：
  - 公式：当 `T ≤ 8`（单请求 decode 与单请求 8 词 verify）时，只计算前 `1,024` 列切片 `f[:, :1024] = m @ W_unpooler[:1024, :].T`，其余 `1024..8191` 列填 0（线上由 8 张卡各算 `1,024` 列再做跨卡 `All-Gather`，单卡赛题省去通信）。当 `T > 8` 时计算完整 `8,192` 列 `f = m @ W_unpooler.T`。
  - 输入与输出：输入阶段 6 汇总的专家输出 `m [T, 4096]`（BF16，每词 `8 KiB`，位于 HBM 或 L2）与 `W_unpooler [8192, 4096]`（BF16，全矩阵 `67.1 MB`，`T ≤ 8` 切片读 `8.4 MB`，位于 HBM）。输出 `f [T, 8192]`（BF16，写回 HBM 或 L2），交给阶段 8。
  - 本步代价与改造：`T ≤ 8` 时 `unpooler` 只读 `8.4 MB`（下界 `1.75 µs`），而到 `T = 16` 时跃升为读完整 `67.1 MB`（下界 `14.0 µs`），单是 `unpooler` 一项的下界就跳增 `12.2 µs`（叠加 16 请求的专家与键值读取后，P3 整层下界从 `T = 8` 的单请求 verify 到 `T = 16` 的 16 请求 decode 在滑窗层跳增 **14.4 µs**［`62.3 → 76.7 µs`］、在全长层跳增 **71.1 µs**［`66.4 → 137.5 µs`］）。在 `T = 8` 下，基线 `unpooler` 网格仅 `64` 个 CTA（`16 × 1 × 4`），占不满 132 个 SM 的一半。P3 改用 `128` 个 CTA 的 8 路 Split-K 12 位无损 C12 切片内核（权重从 `8.4 MB` 压至 `6.3 MB`），使单请求 verify 滑窗与全长整层分别提速 **1.29% 与 1.42%**（`109.0 → 106.8 µs`、`119.0 → 118.0 µs`）。
- 阶段 8（`post_ffn_norm` + 门控残差 2 + `next_pre_attn_norm`）解剖与跨层交接：
  - 公式：`f_scaled = f * (1 + w_post_ffn)`。第二条可学习门控残差更新为 `stream_2 = alpha_2 * stream_1 + beta_2 * rmsnorm(f_scaled)`。最后顺手为第 `l + 1` 层算好入口预归一化 `x_next = rmsnorm(stream_2) * (1 + w_next_pre_attn)`。
  - 输入与输出：输入 `f [T, 8192]`（BF16）与阶段 3 留下的 `stream_1 [T, 8192]`（FP32，位于 HBM）。输出更新后的高精度残差流 `stream_2 [T, 8192]`（FP32，每词 `32 KiB`，写回 HBM）与下一层入口激活 `x_next [T, 8192]`（BF16，每词 `16 KiB`，写回 HBM）。
  - 交给下一步（纵向跨层交接）：`(x_next, stream_2)` 直接成为第 `l + 1` 层阶段 1（`qkv_gate`）和阶段 3 的输入（见第 0.0 章第 2 节）。在阶段 3 与阶段 8 的集群边界归一化内核中，基线用 `barrier.cluster.arrive.release` 交换部分平方和，每次都会在 `sm_90a` 上编译出 `MEMBAR.ALL.GPU + ERRBAR + CGAERRBAR`（占未发射采样周期的 `36%–46%`）。P3 改用 `st.async` 配合本地 `mbarrier` 完成跨 CTA 交换，将 `MEMBAR.ALL.GPU` 清零，每次启动省下 **0.86–0.99 µs**（整层几何平均提速 **0.46%**）。

退回到第 0 级（整层时间线，见第 1 章），把阶段 1 到阶段 8 串起来看（图 7-10 与图 7-11）。SGLang 基线把单层拆成约 17 个独立 kernel 依次投递，未融合的层间归一化与残差读写占去单请求 decode 耗时的约四分之一。经过前三节的片上尾声融合与免启动归约，单层在 `T = 1` 下被压成 11 个首尾相接的 kernel（具体哪 11 个内核对应哪几个阶段的逐一名称未在记录中单列）。当相邻两个阶段因并行切分维度不同（如注意力按请求与键值分片切 CTA、`o` 投影按输出通道切 CTA；`pooler` 按通道切 CTA、专家按本地命中对切 CTA）而无法合进同一个 kernel 时，P3 在同一条 `stream` 上用 **PDL**（编程依赖启动，见第 1 章第 2 节）将 11 个 kernel 焊成无缝流水线。在图 7-11 中选方式 1，读数为：`11 个 kernel · 每条 PDL 串行边约 0.64 µs（基线约 17 个）` / `一层最短 40.0 µs（滑窗层，共读 191.9 MB）`。
- 同流 PDL、等待前静态权重预读与早期专家跨流竞态修复（图 7-10 模式 2 与图 7-11 方式 2–3）。后继 kernel 把等待点 `cudaGridDependencySynchronize()` 放在静态权重预读指令之后，趁前序最后一个波次收尾的空档提前进场。在 P3 上，开启同流 PDL 在 `T = 128`（16 请求滑窗与全长 verify）算例上实测省下 **1.9–3.2 µs**。让 `o` 投影在等待前用 `prefetch.global.L2` 预取前几阶权重，又使 **verify 1 请求滑窗（`T = 8`）** 算例提速 **0.80%**（在 16 请求滑窗 decode 与 32 请求全长 decode 上分别提速 `0.61%` 与 `0.19%`）。在 `T = 1 / 8 / 16` 下，P3 还把小批量专家内核（占 132 个 SM）设为 `pooler`（占 64 个 SM）的 PDL 后继，让专家 CTA 先在空闲的 68 个 SM 上跑完 `1.4 µs` 的路由预处理与 `1.8 µs` 的首轮权重 TMA（共 `3.2 µs`）再进入 `griddepcontrol.wait`，使单请求滑窗/全长 decode 与单请求全长 verify 整层提速 **1.46%–1.96%**（若含单请求滑窗 verify `1.00%` 与 16 请求全长 decode `0.77%`，五格提速区间为 `0.77%–1.96%`）。
  同时，当旁路 `stream` 上的 `top-8` 在入口过早调用触发函数时，捕获进 CUDA Graph 的跨流汇合边会变成编程依赖边，导致专家内核在 `top-8` 写出结果前就被放行并读到上一轮重放留下的旧 `topk_ids`（图模式重复运行残差相对 L2 误差高达 `0.7–1.09`）。P3 将 `top-8` 改为入口只等待不触发、在出口才触发完成边，彻底消除了跨流读脏值竞态（延迟触发的单独微秒代价未记录）。在图 7-11 中切换方式 2 与方式 3，读数分别为：`早期专家 + top-8 入口触发：专家读到上一轮的 topk_ids` / `图模式重复运行失败：残差相对 L2 0.7–1.09；eager 全部通过`，以及 `早期专家 + top-8 出口触发：专家读到本轮的 topk_ids` / `判官式复现 0/240 次失败；T = 1 / 8 / 16 整层提速 1.46%–1.96%`。在图 7-10 模式 2 中切换三档选项，读数分别为：`不开 PDL：交接段不重叠` / `作为对照基线`、`开 PDL，先等待再读权重：去掉切换空隙` / `P3 实测省 1.9–3.2 µs`、以及 `开 PDL，等待前预读权重：W2 读取与收尾重叠` / `P2 重叠 5–11 µs；P3 verify 1 请求滑窗再提速 0.80%`。图 7-10 模式 1 的跨核归一化拆入尾声读数（`独立归一化 kernel：多 1 个 kernel + 49.3 MB HBM 往返` / `T = 3,012 时该 kernel 约 14 µs` 与 `拆入尾声：少 1 个 kernel、少 49.3 MB 往返` / `单项几何平均提速 0.23%；合并测试 0.60% / 1.35%`）将在第 8 章第 3 节详细拆解。
- 第 0 级实测反例（把全层多个阶段强塞进单个协作大 kernel，大纲记录变慢 **5–8 µs**，图 7-10 模式 3）。既然减少启动次数能省空隙，能否像第 3 节探讨过的那样，用 `cudaLaunchCooperativeKernel`（见第 1 章第 3 节）把整层多个不同形状的阶段合写进同一个全层协作大 kernel？在 P3 与 P5 中尝试全层合写大 kernel，大纲记录其耗时反而比按阶段拆开再用 PDL 串联慢了 **5–8 µs** 并被否决（具体测试形状与硬件停顿构成未在记录中保存）。图 7-10 模式 3 的两条读数直接对比了这一边界：`合写大 kernel：全网格栅栏约 1.4 µs` / `P3、P5 合写被否决；大纲记 5–8 µs（形状 UNKNOWN）`，以及 `拆成两个 kernel，PDL 串联：没有栅栏` / `批量 16 与 32 解码净快 0.70–0.82 µs`。

**带走一句话：** 顺着 Decode 与 Verify 下的一层数据流（P4 稠密投影 → P1 分页注意力 → P2 路由专家 → P3 整层收官），把同维度小操作片上融合、跨维度阶段用同流 PDL 预读串联，并在每一阶段内部用三跳投机并发、按实际键数切波次、惰性重缩放、FP8 `QGMMA`、L2/DSMEM 免启动归约、33 字消冲突与 8 指令异或反量化逐级削平瓶颈（同时避开热 L2 多播、过早页表预取、2 槽乒乓与全层协作大核四个反例），才能将单层 11 个内核推近 40.0 µs 与 44.2 µs 的物理下界。
