# 前言

本书围绕公开的 GPU 内核优化竞赛（Open Kernel Challenge）展开。目标是在单张 NVIDIA **H200** GPU（**Hopper** 架构）上运行大模型 **Muse Spark Open**。单层是模型里重复堆叠的一段计算，本书要把单层推理耗时推到读完权重所需的最短时间附近。竞赛以开源推理服务框架 **SGLang** 的耗时除以参赛者耗时计分，所以全书用 SGLang 作为基线对照。

全书顺着 **profiler**（性能剖析器）由粗到细的六级放大顺序（第 0 级 → 第 5 级）推进。从第 2 章起，每章只拆开上一章刚看到的那个硬件部件，因为先看清部件的物理边界，才能判断哪项代码改动缩短耗时。从第 0.5 章起每章结尾给出 `gemv_kernel` 的一个新版本，展示本章机制带来的代码改动。

# 本书导读：六级放大目录（第 0 级 → 第 5 级）

- 第 0 章（工作负载）：单层模型做哪几步计算，理论最短时间是多少？
- 第 0.5 章（最小 CUDA 程序）：一段 20 行的代码怎样算出全部输出行？
- 第 1 章 [第 0 级：时间线]：一串小 kernel 之间的时间空隙从哪里来？
- 第 2 章 [第 1 级：整张芯片]：132 个 SM 怎样接住一个 kernel？
- 第 3 章 [第 2 级：单个 SM]：单个 SM 的资源池、合并访问与片上搬运各自限制什么？
- 第 4 章 [第 3 级：单个 SMSP]：子分区调度器每个周期怎么选 warp 并发射指令？
- 第 5 章 [第 4 级：执行管线与 Tensor Core]：指令发出去后在哪个物理管线里算？
- 第 6 章 [第 5 级：单条指令与比特]：一行代码如何变成机器指令与寄存器比特？
- 第二部分（第 7–8 章：实战案例库）：五道竞赛计时题的演进与反例怎样复盘？
- 第三部分（第 9 章：性能诊断法）：如何用剖析器定位瓶颈？

# 读者对象、先修知识与全书约定

- 先修要求：读者只需熟悉基本 C/C++ 语法与矩阵乘法，阅读本书不需要手头有 H200 硬件。写过推理服务或没碰过大模型的读者都可从第 0 章读起，因为第 0 章只用数组建立模型概念，第 0.5 章至第 6 章从零拆解硬件。
- 单位约定：模型权重与显存标称容量和带宽使用十进制单位（MB、GB、TB/s）。芯片内部的片上缓存与分块容量使用二进制单位（KiB、MiB），因为显存厂商按十进制标称带宽，而片上硬件缓冲按 2 的幂次对齐。
