# 第 5 章 [第 4 级]：指令发出去后，在哪个物理管线里算？

**本书地图：** 第 0 章 → 第 0.5 章 → 第 1 章 [第 0 级] → 第 2 章 [第 1 级] → 第 3 章 [第 2 级] → 第 4 章 [第 3 级] → **【第 5 章 [第 4 级]：执行管线与 Tensor Core】** → 第 6 章 [第 5 级] → 第 7–8 章 → 第 9 章

承接第 4 章末尾的问题（第 4 级：执行管线与 Tensor Core）：第 4 章中 SMSP 调度器每周期挑出 1 个就绪 warp 发出指令。指令发出后会进入背后的哪条物理管线，怎样让所有管线同时忙碌以缩短总周期数？

## 1. 发射间隔（`32 ÷ 通道数`）与结果延迟

<!-- FIG ch05-a: 图 5-1 上方画单个 SMSP 的向量寄存器文件通往背后的四条基础管线（FMA 32 通道、ALU 16 通道、SFU 4 通道、LSU 读写单元）与本 SMSP 的 Tensor Core（移动块对应 gemv 的 v9 循环或在线 Softmax 循环发往各管线的 warp 指令）。下方画相邻周期交替发往不同管线与连续发往同一管线触发回压停顿的时间线，读数显示各管线的通道数、发射间隔（1 : 2 : 8）与 SFU 结果延迟（约 17 周期）。 -->

衡量图 5-1 的执行管线需区分两个周期数。**issue interval**（发射间隔，即管线吞吐率的倒数）是管线收下 1 条 warp 指令后被占用的周期数。在这段周期内，该管线不能接收下一条同类指令。它等于 `32 ÷ 管线硬件通道数`（1 条通道每周期处理 1 个 thread 的 1 次运算）。**latency**（结果延迟）则是从指令发出到结果写回寄存器可供读取的总周期数（图 5-1 读数）。每个 SMSP 背后的四条基础管线彼此并联独立。
- **FMA**（fused multiply-add，融合乘加，发射间隔 1 周期）管线。共 32 条通道，执行单精度浮点乘加、加法与乘法；其重型子管线也执行整数乘加 `IMAD`（第 6 章用它分担移位）。
- **ALU**（arithmetic logic unit，算术逻辑单元，发射间隔 2 周期）管线。共 16 条通道，执行整数加法、移位、比较与按位逻辑。
- **SFU**（Special Function Unit，特殊函数单元，发射间隔 8 周期）管线。共 4 条通道，执行快速指数 `exp2f`、倒数与平方根倒数 `rsqrtf` 等超越函数。
- LSU（见第 3 章）。执行全局与共享内存读写地址生成。

调度器在前一周期把指令发给某条管线后，下一周期可立刻把另一条指令发给其他管线。当本 SMSP 上的 warp 向同一管线发指令的速度超过它的发射间隔时，管线队列排满，调度器就会因 **back-pressure**（回压）停发。因此一段循环的理论最短周期数由累计占用周期数最多的那条最慢管线（或每周期 1 条的共享发射槽上限）决定。在 `gemv` 的 v9 循环（见第 4 节）中，每处理 1 个装有两个 BF16 的 32 位字，需要 2 条 ALU 整数移位掩码指令拆包，再配 2 条 FMA 乘加指令。FMA、ALU 与 SFU 的发射间隔相差 **1 : 2 : 8**。每 2 个元素的 FMA 只占 2 个周期，而 2 条 ALU 拆包要占 `2 × 2 = 4` 个周期，使 ALU 成为该循环的最慢管线。注意力采用 **online Softmax**（在线 Softmax，即边读分块边做指数归一化，FlashAttention 的做法）。同理，其中每个元素做 2 条 FMA 配 1 条 8 周期的 `exp2f`，SFU 就是最慢管线。

## 2. 最宽的矩阵管线 Tensor Core：`mma.sync`（16 行）与 `wgmma`（64 行）

<!-- FIG ch05-b: 图 5-2 上方画单个 SMSP 的 Tensor Core，对比单 warp 同步指令 mma.sync（16 行，约达三分之二峰值）与 4-warp 协同异步指令 wgmma（64 行，SS 模式在 N>=64 时耗时 N/2 周期几乎跑满峰值，及 RS 模式）的数据通路（移动块对应 64 × N × 16 矩阵乘的 A、B 分块与累加器 D）。下方对比小批量 token 下直接填充 64 行与交换矩阵左右方向的利用效率。 -->

单 token decode 的 `gemv` 不用矩阵单元。但在 verify / prefill 与多 token 专家计算中，主力算力来自每个 SMSP 的 1 个 **Tensor Core**。它专门计算矩阵分块乘加 `D = A × B + C`。用来反复累加乘积结果的寄存器集合 `C / D` 称为 **accumulator**（累加器，对应第 0.5 章的 `acc`）。先从第 0 章的 989 TFLOP/s 标称峰值算出单个 Tensor Core 每周期的运算量。全卡有 132 个 SM，每 SM 含 4 个 SMSP。按标称峰值对应的 1.83 GHz 时钟（即第 4 章的约 1.8 GHz）计，每个 Tensor Core 每周期完成 `989 TFLOP/s ÷ 132 ÷ 4 ÷ 1.83 GHz ≈ 1,024` 次 BF16 运算。整 SM 4 个分区每周期合计完成 4,096 次运算。一条 `64 × N × 16`（`N ≥ 64`）的 BF16 矩阵乘共做 `2 × 64 × N × 16 = 2,048 × N` 次运算，除以 4,096 即得理论耗时 `N / 2` 个周期（图 5-2 读数）。

如图 5-2 所示，Hopper 提供两条不同粒度的 Tensor Core 指令族。
- **`mma.sync`**（单 warp 同步矩阵乘，每次算 16 行）。由本 SMSP 的 1 个 warp 独立驱动 Tensor Core。输入分块 `A`、`B`（需先从 SMEM 读入寄存器）与累加器 `D` 全在私有寄存器里。
- **`wgmma`**（warpgroup 异步矩阵乘，每次算 **64 行** × N 列）。由 1 个 warpgroup（见第 3 章）的全部 128 个线程联手发起。这要求 4 个 warp 都不分化、128 个线程同时走到同一条 `wgmma`（分化见第 4 章），若分支让部分线程跳过该指令，硬件行为是未定义的。其右矩阵 `B` 由硬件根据 **matrix descriptor**（矩阵描述符，编码 SMEM 地址、步长与 swizzle 模式的整数）从 SMEM 读取。
- `wgmma` 的两种左矩阵模式。左矩阵 `A` 可选从 SMEM 读取的 **SS mode**（Shared-Shared 模式，`N ≥ 64` 时耗时约 `N / 2` 周期）。它也可选从私有寄存器读取的 **RS mode**（Register-Shared 模式）。例如注意力里刚算出的权重已在寄存器中，用 RS 模式即可省掉写回 SMEM 的步骤。

如果某个专家只分到 1 个 token 并直接放在 `wgmma` 固定 64 行的那一维，64 行里只有 `1 ÷ 64 ≈ 1.6%` 的行有用，其余 63 行全是零填充（图 5-2）。在 decode 下，这些空行会锁住 4 个 warp 和它们的累加器寄存器；一旦进入受算力限制的区间，空算更会拖慢耗时。因此当 token 数很少时，要么利用转置恒等式 `(A · B)^T = B^T · A^T` 交换 `A` 和 `B` 让权重的输出维填满 64 行、把少量 token 放在 `N` 维，要么改用只占 16 行的 `mma.sync`。

## 3. 异步矩阵乘的寄存器所有权与 `wait_group<1>` 跨管线重叠

<!-- FIG ch05-c: 图 5-3 上方画 1 个 warpgroup 同时向 Tensor Core 异步队列与 ALU/FMA/SFU 管线派发指令的数据通路，标出两套交替使用的输入寄存器 A0/A1 与累加器（移动块对应第 k 组正在 Tensor Core 计算的 A0 与第 k+1 组正在 ALU/FMA 解码准备的 A1）。下方对比 wait_group<0> 串行等待与 wait_group<1> 跨管线重叠的时间线。 -->

要让总耗时只等于最慢管线、而不是各管线之和，就必须让 Tensor Core 与算术管线同时忙碌。`wgmma` 发出后，warp 无需停下等待，下一周期即可向 FMA、ALU 或 SFU 管线发射其他指令。这与第 4 章受 scoreboard 自动保护的普通指令不同。在 `wgmma` 后台运行期间，硬件 scoreboard 不会阻止线程读写正在被 Tensor Core 使用的累加器或 RS 模式输入寄存器 `A`。如果不加等待就读取累加器，硬件不会停顿，结果是未定义的（可能读到尚未写完的值）。

因此，程序必须用 `commit_group` 把已发出的 `wgmma` 打包成组。访问相关寄存器或向第 3 章的 `empty[s]` 报到前，程序必须调用 **`wait_group<N>`**（阻塞等待，直到在途未完成的 `wgmma` 组数不超过 `N`）。最后一条指令发出到结果写回累加器的尾延迟称为 **drain latency**（排空延迟）。如图 5-3 所示，`wait_group<0>` 每次都会暴露约 53 个周期的排空延迟。反之，在寄存器里准备两套交替使用的输入缓冲，发完前一组 `wgmma` 后立刻用 ALU 和 FMA 管线准备下一组数据。等下一组也提交后再调 **`wait_group<1>`**。这会等到最多剩 1 组在途（前一组已完成，最新 1 组在 Tensor Core 上算），使算术管线与 Tensor Core 并行重叠。

## 4. gemv 演化（v8 → v9）：ALU 整数位移拆包与 8 路独立累加链

<!-- FIG ch05-d: 图 5-4 v9 的 ALU 拆包与 8 路独立 FMA 累加树：每个 32 位打包字经 ALU 左移与掩码拆成偶奇两路 FP32，分流进 acc0..acc7 八条独立累加链，对比单条串行 acc 依赖链阻塞后续读取发射的时间线。 -->

如图 5-4 所示，在 **v8**（第 4 章，在途 61.1 KiB/SM）基础上，每条 `uint4` 装有 8 个 BF16（打包在 4 个 32 位字里）。BF16 正好是 FP32 的高 16 位（见第 6 章第 2 节）。本章的 **v9**（在途 61.1 KiB/SM）用 ALU 管线的左移（`<< 16`）与按位与（`& 0xffff0000u`）把权重字 `w` 和输入字 `xv` 各自拆成两路 FP32，并分别加进 8 个独立的累加器变量 `acc0..acc7`。

```cuda
// v9：用 ALU 位运算把 32 位打包字 w 与 xv 各拆成两个 FP32，分 8 路独立累加器乘加
float w_lo = __uint_as_float(w << 16), w_hi = __uint_as_float(w & 0xffff0000u);
float x_lo = __uint_as_float(xv << 16), x_hi = __uint_as_float(xv & 0xffff0000u);
acc0 += w_lo * x_lo; acc1 += w_hi * x_hi; // 共 8 路独立累加链
```

warp 按程序顺序发射指令（见第 4 章），拆成 8 路独立累加链可避免单条串行累加链阻塞后续读取发射。剖析器显示全核执行的指令总数从 `2.67 M` 降到 `2.02 M`（减少 `24%`）。但由于单 token decode 受 HBM 带宽限制，H200 实测耗时为 `15.62 →` **15.58 µs**（`1.00×`，约为 7.9 µs 下界的 `50.5%`），印证了总耗时由最慢资源决定。

**带走一句话：** FMA、ALU 与 SFU 按 **1 : 2 : 8** 的发射间隔并行工作，异步 `wgmma` 配合双缓冲与 `wait_group<1>` 可隐藏约 53 周期的排空延迟。
