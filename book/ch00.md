## 1. 单层模型的七个计算阶段与层间小操作

<!-- FIG ch00-a: 图 0-1 画单张 GPU 上单层模型串联的 7 个计算阶段柱状图（移动块对应单步推理中 1 个 token 的残差流向量依次流经 qkv_gate -> attention -> o -> router -> pooler -> MoE -> unpooler 七步）。读数显示各阶段权重 MB 数：qkv_gate 37.7、attention KV 0.5（滑窗）/ 20.5（全长，全长层下界约 44 µs）、o 16.8、router 8.4、pooler 67.1、最忙卡本地专家约 53（约 1.87 个专家）、unpooler 切片 8.4。 -->

每个用户的输入文本是一个 **request**（请求）。它被切成一串 **token**（词元）。自回归生成每步都要用刚算出的词去预测下一个词，所以在 **decode**（逐词生成）阶段，每个请求每步只输入 1 个新 token。每个 token 在层内是一个固定宽度的浮点数向量，叫 **residual stream**（残差流）。各阶段从残差流读入向量并输出中间向量。这些中间向量统称 **activation**（激活），其中 `o` 与 `unpooler` 把结果加回残差流。

本层是 **MoE**（混合专家）结构，共有 256 组独立的专家权重矩阵，每步只为每个 token 挑 8 个专家。线上由 8 张 H200 分担同一层。卡间通信不计入赛题耗时，所以本书只测单张卡分到的部分。每张卡放 32 个专家，单 token 挑出的 8 个专家平摊到各卡上平均每卡只有 `8 × 32 ÷ 256 = 1` 个。但挑中的专家不会均匀落到各卡上。一步推理必须等命中专家最多的最忙卡算完，所以单卡下界要按**接近平均数两倍**（约 1.87 个）的专家权重计算（图 0-1）。

一次算完用户整段输入的所有 token 称为 **prefill**（预填充）。竞赛把单层拆成 5 道计时题：P1 注意力、P2 专家、P3 小批量整层、P4 五个稠密矩阵乘（下文第 1、3、4、5、7 阶段）、P5 预填充整层。如图 0-1 所示，单张卡上的一层依次执行七个核心阶段。各阶段前后夹着不读大矩阵权重的归一化与残差相加小操作，以稳定每步投影后的数值范围。
- `qkv_gate` 投影（读 37.7 MB）。把残差流乘上 **BF16**（脑浮点，每参数 2 字节）权重矩阵，算出查询（Q）、键（K）、值（V）与门控向量。
- attention（注意力，即 P1）。用当前 token 的 Q 与可见历史 token 的 K、V 做加权求和（采用在线 Softmax，即 FlashAttention 的做法）。历史 K、V 按 **FP8**（8 位浮点，1 字节）存进 **KV cache**（键值缓存），滑窗层读 0.5 MB，全长层读 20.5 MB。
- `o` 输出投影（读 16.8 MB）。把注意力输出乘上 BF16 矩阵，加回残差流。
- `router`（路由器，读 8.4 MB）。用 FP32（单精度浮点，每参数 4 字节）矩阵为每个 token 给 256 个专家打分，挑出得分最高的 8 个。
- `pooler`（降维投影，读 67.1 MB）。用 BF16 矩阵把残差流压窄一半，送入专家。
- MoE 专家计算（即 P2，最忙卡读约 53 MB）。每个被选中的本地专家执行上投影 `w13` 与下投影 `w2` 两次矩阵乘，权重存为 **NVFP4**（4 位浮点，见第 6 章）。
- `unpooler`（升维投影，小批量切片读 8.4 MB）。用 BF16 矩阵把专家输出升回残差流宽度，加回残差流。

## 2. 算术强度、平衡点与单层理论下界

<!-- FIG ch00-b: 图 0-2 画以算术强度（FLOP/B）为横轴的 roofline 性能边界图（图中工作点对应单层各阶段在 T=1［稠密层 1、注意力 16、专家 3.6 FLOP/B］、T=256、prefill 三个算法批量下的 y = W · x 及注意力步）。读数显示 decode T=1、verify T=256（qkv_gate 224 / pooler 与 unpooler 234 / o 约 200 / router 约 84）与 prefill 稠密矩阵乘（约 530–590）的工作点。 -->

单层权重超过百兆字节，远大于片上缓存容量。所以每步推理都必须把权重和历史 KV cache 从 **HBM**（高带宽主显存）重新读进芯片。H200 读取 HBM 的标称带宽上限是 4.8 TB/s，稠密 BF16 矩阵乘加的标称算力上限是 989 TFLOP/s。假设显存读取与矩阵运算重叠执行。按题目给定权重格式算出的单层 **floor**（理论下界），就是显存读取耗时与矩阵运算耗时中的较大值（换更小位宽的格式时下界随之下降，见第 6 章）。

```text
floor = max( 总搬运字节数 Bytes ÷ 4.8 TB/s , 总浮点运算次数 FLOPs ÷ 989 TFLOP/s )
```

一个阶段的总浮点运算次数除以总显存读写字节数称为 **arithmetic intensity**（算术强度，单位 `FLOP/B`）。用算力上限除以带宽上限得到 `989 ÷ 4.8 ≈ 206 FLOP/B`，称为 **ridge point**（平衡点）。算术强度低于 206 时，读 1 字节的耗时比矩阵单元算完对应运算还长，所以计算单元等 HBM 返回数据。高于 206 时，数据等矩阵单元。

小模型先猜候选词、再由大模型一次并行检验的做法称为投机解码，这一检验步称为 **verify**。32 个并发请求各检验 8 个候选词时，全批总词数 `T` 增大到 256。在图 0-2 中，只有 `qkv_gate`、`pooler`、`unpooler` 这 3 个大矩阵乘略微跨过了 206。`o`、`router` 与注意力依然留在平衡点以下。1 次乘加含 2 FLOP，1 个 BF16 权重占 2 字节，权重被 `T` 个 token 共享后仅按权重算强度为 `2 × T ÷ 2 = T FLOP/B`（计入激活读写后 `qkv_gate` 约为 224）。但 `router` 权重是 4 字节 FP32，仅按权重算强度减半为 `T ÷ 2 = 128`，加上激活读写后降至约 84。历史 KV cache 属于每个请求私有、无法跨请求共享，所以注意力强度不随 `T` 增大。

`T = 1` 时，BF16 稠密层强度只有 `2 × 1 ÷ 2 = 1 FLOP/B`。全层所有阶段都远低于 206，所以单请求 `decode` 下 GPU 绝大部分时间在等 HBM。把图 0-1 里滑窗层的七项读取字节数相加约为 192 MB。用 192 MB 除以 4.8 TB/s，即得全书追踪的单层基准下界 **40 µs**。其中第一阶段 `qkv_gate` 单独读 37.7 MB，下界约 7.9 µs，这是后续各章 **gemv**（矩阵乘向量，即 `y = W · x`）演化的终点线。

**带走一句话：** 单请求 decode 下滑窗层读 192 MB 权重与缓存，按 4.8 TB/s 算出的单层下界是 40 µs（其中 `qkv_gate` 占 7.9 µs）。
