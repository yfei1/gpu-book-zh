Details
  • Path 1 (L2 vector atomic add + grid barrier, verify 16 / 32-request full attention, 264 CTAs = 132 × 2 = 1 wave, without cooperative launch): the 263 faster CTAs issue 0-referenced red adds, cross 256-thread Named Barrier 1, and add weights 248 / 249 toward +65,536 on tid 128 while polling with __nanosleep(64).
  • Final-CTA release and net timings: once the 264th CTA issues red, crosses Barrier 1, and completes +65,536 (0 poll), all 264 CTAs acquire, cross Barrier 2, partition rows to write o_attn, and zero their slice, saving net 1.73 / 2.98 µs measured (1-request full slows by +2.96 / +0.62 µs).
  • Path 2 (last-arriver ticket merge, schematic G=7G = 7G=7 segments; Ch. 9 decode up to 256 splits, Ch. 7 prefill light tiles 4 splits): each CTA independently crosses Intra-CTA Barrier 1, draws an out-of-order ticket, and crosses its own Barrier 2 so early CTAs exit at once (0 cross-CTA waits, deadlock-free across waves), while only the final ticket (ticket == G - 1) reads the summed row, writes o_attn, and plain-store zeroes state.
  • Path 3 (intra-GPC cluster st.async direct write, verify 16 sliding NS=7N_S = 7NS​=7, 224 CTAs = 32 clusters): all 7 segments cross local and cluster barriers and push rows across distributed SMEM (0 B merge exchange via L2), where 0-row SM 6 exits before bytes finish landing and before SM 0–5 flip mbarrier, merge in fixed lse order in SMEM, and write o_attn.
  • Cluster residency tuning and single-request rewrite: shrinking NS: 8 → 7 removes the 3rd competing resident CTA to save 1.31 µs on earlier pull merge plus 0.49 / 0.25 µs from push, and 1-request 16-CTA 3-in-1 (prologue + split + merge) saves 0.86 / 0.56 µs (in Ch. 9, decode 1 and 16 sliding keep a separate PDL merge kernel for chain-level PDL reasons, not cluster width).
