Details
  • Node topology and wiring: the 8 H200 SXM GPUs connect through NVSwitch chips (all 18 NVLink links of every GPU go into the switches; 900 GB/s bidirectional, 450 GB/s one-way); the chip count (4) comes from the node that recorded the topology; PCIe Gen5 (128 GB/s) connects only to the host CPU, and GPU-to-GPU collectives do not use it.
  • What the solid and dashed SM tiles mean: the placement of GPU 0's 132 SM tiles is schematic (CUPTI records the grid size, not the physical SM number); a solid blue tile is a CTA that gets 16 B vectors to move or sum, and a pale dashed tile is a CTA that the fixed grid launched and that only syncs and flips the phase counter. CTA counts were recorded only at 16 KiB, so other stops draw none.
  • Two timing bases: the main readout and the curves use, for one CUDA Graph replay, the slowest of the 8 per-GPU medians (a 512 MiB L2 read flush and one cross-GPU sync before each replay; 100 interleaved replays; the GPUs still start at slightly different times, called start skew here, and that stays inside the timing); the bars below also list the time of 32 identical ops chained in one graph, divided by 32.
  • Multicast staging and byte basis: the NVSwitch multicast sum cannot use the callers' ordinary tensors through the graph pointer table, so up to 8 MiB one same-GPU SM copy kernel before and one after move data in and out of the symmetric multicast workspace, and 16 MiB uses an on-device copy; no hardware counter measured the physical link bytes of multicast on the local replica, so only the algorithm bandwidth S / t is listed. The NCCL bars include one same-GPU clone copy that the test harness makes before the call.
  • Copy-engine reference: the copy engine uses 0 SMs and was timed only for a one-way copy of one buffer from GPU 0 to GPU 1 (11.1 µs at 16 KiB) with no sum; it is a single-process timing, the median of that one process, not a slowest-of-8 median.
